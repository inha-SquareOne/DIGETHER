# 재개 가능한 작업 인계

1. 현재 파일·Git 상태·변경 diff와 실제 검사 기록을 다시 확인한다. 이전 대화 요약이나 다른 에이전트 보고만으로 완료를 판단하지 않는다.
2. [인계 양식](../../../docs/ai/SESSION_HANDOFF.md)에 목표·범위, 완료된 변경, 관련 경로, 실제 검증 결과, 남은 결정, 다음 실행 가능한 행동을 담는다. 현재 브랜치·커밋 또는 비 Git 상태도 사실대로 적는다.
3. 실패·차단은 정확한 명령 또는 작업, 대상 경로, 이유, 안전하게 재개할 조건을 남긴다. 미실행 검사를 통과로 쓰지 않는다. 증거 없는 해결 추정을 구분한다. 확인할 수 없는 설정값은 추측하지 않고 다음 작업자가 확인할 실제 파일·명령·화면 등 재확인 방법을 기록한다.
4. 기록 위치는 프로젝트 관례나 사용자 지정에 따른다. 개인 대화·민감한 로그는 공유 문서에 복사하지 않는다. [문맥 관리](../../../docs/ai/CONTEXT_HYGIENE.md)에 따라 다른 사람이 원본 개인 세션 없이 이해할 수 있게 쓴다.
5. 인계 요청은 Git 커밋·외부 메시지·작업 중단의 자동 권한이 아니다. 승인된 작업을 계속할 수 있다면 진행하고, 중간 인계에는 남은 작업을 명시한다. 사용자에게 불필요한 종료 선택을 요구하지 않는다.

## 결과

실제 수정 파일, 사용한 근거, 확인한 결과, 다음 작업 순서와 필요한 결정이 있어야 한다. 기존 staged/unstaged 변경과 다른 작업자의 변경을 이번 작업의 성과로 포함하지 않는다.

## 프로젝트 작업 경계

실행 전에 [작업 경계 기준](../../../docs/ai/WORK_BOUNDARIES.md)과 프로젝트가 채운 경계표·CODEOWNERS·기존 변경/잠금을 확인한다. 리뷰 소유자와 AI 쓰기 허용 범위는 별도다. 경계 충돌 시 기존 승인을 확인하고, 미승인 경로로 범위를 넓혀 진행하지 않는다. 필요한 결정과 독립적으로 계속할 작업을 구분한다.
