# 게임 VFX 제작과 Unreal 검수

승인된 컨셉과 게임 계약을 재생 가능한 효과로 옮긴다. 기존 개선은 원본에서 시작하고 사용자가 요청한 제작·도입 범위를 유지한다.

## 시작 조건

- 프로젝트 AGENTS와 [아트 기준](../../../docs/unreal/ART_PRODUCTION.md), [에셋 안전](../../../docs/unreal/ASSET_SAFETY.md), [검증 계획](../../../docs/verification/VERIFICATION_PLAN.md)을 읽는다.
- 기획 원본에서 효과 목적, 실제 크기·원점·진행 방향, 예고/타격 시점과 안전구역을 확인한다. 자료의 표시 번호를 코드 enum이나 판정 ID로 추측하지 않는다.
- 실제 프로젝트의 재생기·풀·데이터 설정·Niagara 사용 여부부터 조사한다. 없는 게임 코드나 에셋을 이미 있는 것으로 가정하지 않는다. 표현 효과에 피해 판정을 새로 넣지 않는다.

## 컨셉과 제작

1. 이미지와 영상의 실제 프레임을 확인하고 등장 순서·확산·유지·소멸을 분리한다. 레퍼런스 품질 요청을 단순 색상 교체로 줄이지 않는다. 승인된 컨셉이 있으면 재사용한다.
2. 새로운 컨셉 이미지가 필요한 요청에는 사용 가능한 imagegen을 사용한다. 사용자에게 컨셉 검토를 요청한 작업이면 그 승인 이후 제작하며, 이미 승인된 단계는 반복하지 않는다.
3. Blender 사용 시 `blender-core`로 실제 버전·열린 파일·도구를 확인한다. 번들 스킬은 Blender 5.2 이상 기준이므로 낮은 설치 버전에 그 API를 그대로 실행하지 않는다. 연결이 없으면 가능한 백그라운드 작업 사본을 사용하고 한계를 밝힌다.
4. GPU는 지원 장치와 렌더러를 확인해 작업에 맞게 사용한다. 설정과 실제 장치 사용 증거를 구분한다. 다른 작업자의 Blender 세션·GPU 작업과 충돌하지 않게 조정한다.
5. 예고, 지면 흔적, 섬광, 파편·먼지 등 필요한 요소를 독립 조절 가능하게 만든다. 모든 효과에 같은 레이어·색상·패턴을 강제하지 않는다. 과노출·카드 사각 경계·알파 소멸을 실제 렌더로 검사한다.
6. `.blend`, 제작 스크립트, 메시·텍스처와 시간 데이터를 프로젝트가 정한 원본 경로에 보존한다. 원본을 Unreal Content 아래에 무조건 넣지 않고 [파일 관리](../../../docs/project/DEVELOPMENT_WORKFLOW.md)를 따른다.

## Unreal 도입과 재생 계약

- `unreal-mcp`는 실제 서버·도구와 엔진 버전을 확인한 뒤 사용한다. MCP가 없으면 허용된 Editor/CLI 경로를 확인하고 미실행을 구분한다. 스킬 설치는 엔진 플러그인 활성화나 MCP 연결 완료가 아니다.
- 실제 엔진에서 지원하는 Niagara·머티리얼·컴포넌트 또는 기존 재생 구조를 사용한다. 이름이나 API를 만들어 쓰지 않는다. `.uasset`·`.umap`을 텍스트로 편집하지 않는다.
- Blender→Unreal 축·단위·피벗·UV·알파·색 공간·압축·노멀과 실제 크기를 대조한다. Blender 노드의 자동 변환을 가정하지 않는다.
- 예고·타격·잔상의 시간을 기존 데이터/편집 설정에서 조절할 수 있게 연결한다. 공유 설정 변경의 영향 범위를 밝힌다.
- 네트워크 효과는 로컬 프리뷰와 서버 확정 표현을 구분한다. 이미 정해진 권위·시계 계약을 사용하고 지연된 확정, 취소, 반복·중첩, 비활성화와 풀 반환을 검사한다. 실제 게임 연동이 범위 밖이면 공개 입력 계약과 연결 대기 상태를 남긴다.

## 완료 증거

효과의 실제 계약에 해당하는 항목만 적용한다. 비전투 장식에 타격·서버 확정 계약을 새로 요구하지 않는다. 정상 재생·취소·늦은 확정·중첩·시간 설정 변경에서 참조/컴파일/런타임 오류를 확인한다. 실제 게임 카메라로 예고·타격·소멸을 캡처하고 경계·안전구역·과노출·가독성을 직접 본다. 움직임이 중요하면 단계별 캡처나 짧은 영상으로 보여 준다. Blender 렌더를 Unreal 실행 화면으로 표시하지 않는다.

효과 경로, 배치 단위·방향, 실제 조절 항목, 재생·취소·수명 계약, 공유 설정, 검사 결과와 한계를 사용 안내에 남긴다. 사용자가 중간 검토를 요청했다면 검토본까지 완료해 보여 준다. 프리워밍 등록이 범위에 포함되면 `register-vfx-prewarming`으로 기존 등록 체계와 연결하며 새 로더를 임의로 추가하지 않는다.
