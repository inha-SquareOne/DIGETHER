# 실질적인 대안 비교

1. 목표·완료 기준·변경 가능한 범위를 먼저 파악한다. 엔진 버전, .uproject, 활성 플러그인, 모듈, 타깃 플랫폼과 [프로젝트 결정](../../../docs/templates/PROJECT_PROFILE_TEMPLATE.md)을 실제 파일에서 확인한다.
2. 현재 방식을 유지하는 선택을 포함해 실행 가능한 대안만 비교한다. 작은 국소 수정에 의미 없는 대안을 늘리지 않는다.
3. 각 대안의 기대 효과, 구현 범위, 유지 비용, 성능·네트워크·에셋·호환성 위험, 검증 방법을 같은 기준으로 정리한다. 수치와 API 지원은 실제 측정 또는 해당 버전 공식 자료를 근거로 한다.
4. 선택을 바꾸는 핵심 조건과 권고안을 명시한다. 확인되지 않은 가정은 가정으로 표시한다. 새로운 비용·계정·서비스·플러그인 도입은 비교만으로 승인된 것으로 간주하지 않는다.
5. 사용자 정책 결정이 필요한 경우에만 짧게 질문한다. 기존 승인과 관례로 결정 가능한 구현은 진행한다.

## 출력 예

| 대안 | 적합한 조건 | 변경 범위·비용 | 주요 위험 | 확인 방법 |
| --- | --- | --- | --- | --- |
| 현재 방식 보완 | 확인한 조건 | 관련 파일·작업 | 실제 위험 | 검사·실행 증거 |
| 다른 접근 | 달라지는 조건 | 추가 변경 | 남는 불확실성 | 비교 실험 |

서버 구조, 저장 방식, 플러그인 선택, 성능 예산을 공통 기본값으로 강제하지 않는다. [네트워크 권한](../../../docs/unreal/NETWORK_AUTHORITY.md), [성능 분석](../../../docs/unreal/PERFORMANCE.md)을 참조한다.

## 프로젝트 작업 경계

실행 전에 [작업 경계 기준](../../../docs/ai/WORK_BOUNDARIES.md)과 프로젝트가 채운 경계표·CODEOWNERS·기존 변경/잠금을 확인한다. 리뷰 소유자와 AI 쓰기 허용 범위는 별도다. 경계 충돌 시 기존 승인을 확인하고, 미승인 경로로 범위를 넓혀 진행하지 않는다. 필요한 결정과 독립적으로 계속할 작업을 구분한다.
