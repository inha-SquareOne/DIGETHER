# 구현 전 조사와 반복 탐색

## 먼저 확인

목표와 제약, 사용할 수 있는 검색 도구를 확인한다. 현재 저장소의 실제 심볼·호출부·테스트·설정부터 읽고, 엔진의 기존 기능과 활성 플러그인으로 충족할 수 있는지 확인한다. 검색이 불가능했던 영역을 '없음'으로 결론 내리지 않는다.

## Unreal 기본 기능 우선

[실행 정책의 Unreal 기본 기능 우선](../../../docs/ai/EXECUTION_POLICY.md#unreal-기본-기능-우선)을 적용한다. 프로젝트 버전의 공식 지원 근거, 실제 활성화 상태, 요구 충족 범위를 나누어 조사하고 지원되는 부분은 사용 가이드로 연결한다.

## 검색 → 평가 → 보완

1. 필요한 동작과 알려진 이름으로 후보 파일을 찾는다. 프로젝트의 실제 용어와 구조가 드러나면 검색어·경로를 바꾼다.
2. 후보의 관련 이유, 현재 구현 여부, 호출부/상태/데이터 연결, 아직 빠진 근거를 기록한다. 파일 수나 임의 점수만으로 충분하다고 판단하지 않는다.
3. 중요한 공백을 겨냥해 다음 검색을 좁힌다. 무관함이 확인된 경로는 제외하되 새로운 증거가 생기면 다시 포함한다. 핵심 테스트를 일괄 제외하지 않는다.
4. 필요한 근거가 충족되면 멈춘다. 진전이 없거나 도구 한계에 도달하면 읽은 범위·남은 공백·다음 확인 방법을 보고한다. 고정 반복 횟수에 도달했다고 중요한 미확인을 확정 사실로 바꾸지 않는다.
5. 에셋 내부와 Blueprint 참조는 텍스트 검색으로 다 확인할 수 없다. 실제 Editor 참조 정보나 검증된 export가 필요하면 그 한계를 남긴다.

## 선택

기존 코드/엔진 기능 사용, 작은 확장, 외부 의존성, 직접 구현을 기능 적합성·엔진/플랫폼 호환·유지 상태·라이선스·의존 비용·권한·빌드/패키징 영향으로 비교한다. 신규 의존성은 공식 자료와 실제 버전에서 확인한다.

[대안 비교](../present-alternatives/SKILL.md)는 최종 선택을 설명할 때 사용하고, [문맥 관리](../../../docs/ai/CONTEXT_HYGIENE.md)는 자료량과 재개 시 최신성을 관리한다. 조사만으로 설치·계정 연결·MCP 변경·유료 서비스·새 에이전트 실행을 시작하지 않는다. 연구 에이전트가 반드시 필요하다고 강제하지 않는다.

## 결과

읽은 경로·검색 범위·후보와 근거·권고 선택·미확인 조건·필요한 승인 또는 검사를 제공한다. 없어진 검색 채널이나 지원하지 않는 도구를 사용했다고 주장하지 않는다.

## 작업 경계와 근거

[작업 경계](../../../docs/ai/WORK_BOUNDARIES.md), 프로젝트 경계표·CODEOWNERS·기존 변경/잠금을 먼저 확인한다. 경계 충돌 시 미승인 경로로 범위를 넓히지 않는다. 읽기 조사와 파일 수정·외부 실행 권한을 구분한다.
