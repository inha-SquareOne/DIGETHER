# Meshy 모델 제작과 Unreal 도입 준비

## 시작 조건

사용자의 모델 제작·개선 의도와 입력 자료, 목표 용도·실루엣·크기·재질·플랫폼을 확인한다. 기존 모델 개선이면 먼저 원본의 형상·UV·노멀·리깅·애니메이션을 점검하고 보존할 특성을 정한다. 명시되지 않은 화풍이나 게임 설정을 가져오지 않는다.

사용 가능한 Meshy 도구, 현재 지원 기능과 입력 제약을 [도구 확인 절차](../../../docs/ai/MESHY_TOOLS.md)로 검증한다. 연결·인증·유료 크레딧 한도가 불명확하면 그 단계만 보류하고 입력 분석·제작 계획을 계속한다. 계정·키·전역 설정을 임의로 바꾸지 않는다.

## 제작 절차

1. 입력 자료의 사용 권한과 외부 서비스 전송 범위를 확인한다. 작업별 비용 한도·후보 수·재시도 범위를 기존 승인에서 확인하고 없으면 필요한 결정을 받는다.
2. 신규 생성과 기존 모델 편집 중 실제 요구에 맞는 경로를 선택한다. 보존이 필요한 모델을 무조건 새로 생성하지 않는다. 지원되지 않는 편집은 한계와 대안을 제시한다.
3. 요청 파라미터와 반환된 작업 ID를 기록한다. 비동기 작업은 상태를 조회한다. 응답 지연·불확실성만으로 새 유료 작업을 반복 생성하지 않는다.
4. 원본 출력과 작업 사본을 구분한다. 형상, UV, 노멀·탄젠트, 재질, 텍스처 채널, 스케일·축, 리깅·애니메이션을 실제 결과에서 검사한다. 생성했다는 사실만으로 품질 통과를 선언하지 않는다.
5. AO·normal·roughness·metallic 같은 맵은 실제 의미와 데이터로 검토한다. 단순 색 변환이나 파일명 변경을 진짜 베이크·PBR 결과로 보고하지 않는다. 텍스처의 색 공간과 Unreal 머티리얼 입력 연결은 실제 프로젝트에서 확인한다.
6. 최적화는 프로젝트 예산을 기준으로 한다. LOD·Nanite·콜리전·텍스처 크기·드로콜 정책을 임의로 고정하지 않는다. 간소화 후 UV·실루엣·변형과 재질을 다시 확인한다.
7. 에셋 도입이 승인되면 지원되는 Unreal Editor 경로로 import·재질 연결·저장한다. 바이너리 패키지를 텍스트처럼 수정하지 않는다. [에셋 안전](../../../docs/unreal/ASSET_SAFETY.md)과 [아트 제작](../../../docs/unreal/ART_PRODUCTION.md)을 따른다.

## 완료 보고

AO를 개선할 때에는 베이크 UV·이미지·활성 타깃·색 공간을 지정하고 고밀도→저밀도 투영의 케이지/거리를 확인한다. 독립 키트는 조각 자체의 local AO와 주변 조각의 가림을 구분하고, 고정 조립물은 접촉 AO와 조립 변경에 따른 재베이크 여부를 확인한다. 개선 전후는 같은 카메라·노출·조명에서 비교하고 Unreal의 실제 머티리얼 입력을 검사한다. 다른 엔진의 채널 패킹을 그대로 적용하지 않는다.

사용 입력과 결과 경로, 작업 ID, 확인 가능한 비용·사용량, 보존·변경 특성, 실제 시각 검사와 도입 검사 결과를 남긴다. 이미지·뷰포트·애니메이션 검사 없이 시각 품질을 완료로 쓰지 않는다. 모델 파일 완성과 엔진 내 도입·런타임 검증을 각각 표시한다. 실패한 시도와 미검증 항목도 적되 비밀정보는 기록하지 않는다.

## 프로젝트 작업 경계

실행 전에 [작업 경계 기준](../../../docs/ai/WORK_BOUNDARIES.md)과 프로젝트가 채운 경계표·CODEOWNERS·기존 변경/잠금을 확인한다. 리뷰 소유자와 AI 쓰기 허용 범위는 별도다. 경계 충돌 시 기존 승인을 확인하고, 미승인 경로로 범위를 넓혀 진행하지 않는다. 필요한 결정과 독립적으로 계속할 작업을 구분한다.
