# 코드와 문서 소유권 확인

## 절차

1. 요청에서 이미 승인된 파일·기능·행위를 먼저 확인한다. 현재 체크아웃의 AGENTS.md, 프로젝트 지침, CODEOWNERS와 실제 경로를 읽는다. 파일 작성자나 최근 커밋 작성자를 현재 담당자로 단정하지 않는다.
2. Git을 쓰는 경우 변경 대상의 기존 수정과 staged/unstaged 상태를 구분한다. 버전 관리가 없으면 변경 전 내용을 기록하고 편집 직전 다시 확인한다.
3. 규칙이 대상 파일에 실제로 적용되는지 확인한다. 소유권 표시는 리뷰 책임일 수 있으므로 자동으로 모든 수정에 새 승인이 필요하다고 해석하지 않는다. 이미 승인된 요청과 적용 지침에 따라 진행한다.
4. 담당 영역 밖 수정이 필요한 경우 영향 파일, 이유, 대안을 구체화한다. 기존 권한으로 해결할 수 없는 결정만 사용자에게 묻고 독립적인 승인 범위 작업은 계속한다.
5. 결과에 확인한 규칙과 경로, 미확인 담당 경계, 필요한 리뷰를 남긴다. 소유자에게 메시지를 보내거나 리뷰를 요청하는 행위에는 별도 발신 권한이 필요하다.

Unreal에서는 코드 파일뿐 아니라 맵·패키지·외부 액터·데이터·플러그인과 소스 컨트롤 잠금도 확인한다. 같은 바이너리 패키지의 동시 편집을 피하고 다른 작업자의 변경을 되돌리지 않는다.

근거: [실행 정책](../../../docs/ai/EXECUTION_POLICY.md), [에셋 안전](../../../docs/unreal/ASSET_SAFETY.md), [작업 분담](../../../docs/ai/WORK_ORCHESTRATION.md).

## 완료 조건

대상 범위와 실제 적용 규칙이 식별되고, 진행 가능한 수정과 사용자 결정이 필요한 경계가 구분되어 있어야 한다. 읽기 전용 조사 자체를 불필요한 승인 절차로 막지 않는다.

## 프로젝트 작업 경계

실행 전에 [작업 경계 기준](../../../docs/ai/WORK_BOUNDARIES.md)과 프로젝트가 채운 경계표·CODEOWNERS·기존 변경/잠금을 확인한다. 리뷰 소유자와 AI 쓰기 허용 범위는 별도다. 경계 충돌 시 기존 승인을 확인하고, 미승인 경로로 범위를 넓혀 진행하지 않는다. 필요한 결정과 독립적으로 계속할 작업을 구분한다.
