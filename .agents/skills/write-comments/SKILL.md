# 이유와 제약을 설명하는 주석

1. 주변 코드와 호출부를 읽고 실제 동작을 확인한다. 요청된 주석 범위와 저장소의 언어·문체·API 문서 관례를 따른다. C# XML 문서나 특정 주석 언어를 공통 규칙으로 강제하지 않는다.
2. 코드가 하는 일을 반복하기보다 선택 이유, 깨지기 쉬운 전제, 수명·스레드·네트워크 권한·직렬화 제약을 설명한다. 불확실한 추측을 사실처럼 남기지 않는다.
3. Unreal 코드에서는 실제 UCLASS/USTRUCT/UPROPERTY/UFUNCTION 선언과 엔진 버전에 맞는 의미를 확인한다. 주석 작업으로 리플렉션 매크로·전처리기·문자열·라이선스·생성 도구 지시문을 변경하지 않는다.
4. 주석만 변경하는 작업에서는 실행 토큰과 동작이 유지되었는지 diff를 검토한다. Blueprint 설명은 실제 그래프와 에셋 편집 권한을 확인한 뒤 지원되는 Editor 도구로 변경한다.
5. 코드 결함을 발견하면 별도로 보고한다. 수정까지 승인된 범위라면 분리된 변경과 검증으로 다룬다.

## 완료 조건

주석이 실제 코드와 일치하고, 중복 설명·오래된 사실·불필요한 장문이 줄어야 한다. 확인하지 않은 성능 수치나 엔진 보장은 넣지 않는다. [개발 패턴](../../../docs/unreal/ENGINEERING_PATTERNS.md)을 참조한다.

## 프로젝트 작업 경계

실행 전에 [작업 경계 기준](../../../docs/ai/WORK_BOUNDARIES.md)과 프로젝트가 채운 경계표·CODEOWNERS·기존 변경/잠금을 확인한다. 리뷰 소유자와 AI 쓰기 허용 범위는 별도다. 경계 충돌 시 기존 승인을 확인하고, 미승인 경로로 범위를 넓혀 진행하지 않는다. 필요한 결정과 독립적으로 계속할 작업을 구분한다.
