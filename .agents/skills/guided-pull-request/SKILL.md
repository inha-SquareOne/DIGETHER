# Pull Request 준비

## 사실 확인

- 사용자가 원하는 것이 PR 초안, 실제 생성, 기존 PR 갱신 중 무엇인지 확인한다. 원격 저장소·base/head·현재 브랜치와 실제 커밋을 조회한다. develop/main 같은 이름을 추측하지 않는다.
- uncommitted 변경, 로컬 커밋, 원격에 올라간 커밋을 구분한다. 공유·푸시·PR 생성 권한을 기존 요청에서 확인한다. PR 요청에 포함되지 않은 이력 재작성이나 병합은 하지 않는다.
- 실제 PR 템플릿·기여 지침·변경 diff를 읽고 관련 없는 파일이 포함되었는지 확인한다. [커밋 절차](../guided-commit/SKILL.md)가 필요한 경우에만 연결한다.

## 문안

구체적인 문제와 최종 동작부터 설명한다. 변경 이유, 주요 영향, 검증 환경과 결과, 미실행 항목을 필요한 만큼 쓴다. 범위가 바뀌면 최종 구현에 맞춰 제목·본문을 다시 쓴다. 실험·중간 대화·폐기한 접근은 판단에 필요한 경우에만 남긴다.

Unreal 에셋·데이터·네트워크 변경이 있으면 패키지 경로·호환성·검증 조합·복구 조건을 해당 증거와 함께 명시한다. 실행하지 않은 빌드·패키징·멀티플레이를 통과로 표시하지 않는다.

## 생성과 확인

승인된 범위에서 필요한 푸시·PR 생성 또는 갱신을 실행한다. 여러 줄 CLI 본문은 body 파일로 전달한다. 리뷰어·assignee·label은 실제 존재와 사용자 의도를 확인한 것만 지정한다. 자동으로 타인에게 리뷰를 요청하거나 멘션하지 않는다.

반환된 PR URL과 실제 base/head·내용을 확인한다. 앱에 PR 연결 도구가 제공되면 그 도구의 규칙에 따라 연결한다. 결과가 불명확하면 기존 PR부터 조회해 중복 생성을 피한다. 병합은 별도 요청 없이 실행하지 않는다.

[검증 기준](../../../docs/ai/VERIFICATION.md), [에셋 안전](../../../docs/unreal/ASSET_SAFETY.md)을 따른다.

## 프로젝트 작업 경계

실행 전에 [작업 경계 기준](../../../docs/ai/WORK_BOUNDARIES.md)과 프로젝트가 채운 경계표·CODEOWNERS·기존 변경/잠금을 확인한다. 리뷰 소유자와 AI 쓰기 허용 범위는 별도다. 경계 충돌 시 기존 승인을 확인하고, 미승인 경로로 범위를 넓혀 진행하지 않는다. 필요한 결정과 독립적으로 계속할 작업을 구분한다.
