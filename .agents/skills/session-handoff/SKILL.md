# 새 세션으로 작업 이어가기

## 적용 판단

- 요청의 목표·산출물·대상 프로젝트가 바뀌어 기존 작업과 분리하는 편이 명확할 때 새 세션과 `write-handoff` 사용을 권한다. 같은 목표의 버그 수정, 세부 조건 보완, 상태 질문만으로 전환을 반복 권하지 않는다. 사용자가 이전 목표를 취소했는지, 추가했는지 구분해 기록한다.
- 현재 활성 세션의 컨텍스트 사용량이 **70% 이상(70% 포함)**이면 새 세션을 권하고 인수인계를 작성한다. 런타임/클라이언트가 제공한 사용 비율 또는 사용자가 전달한 현재 수치를 근거로 삼는다. 남은 비율이면 `100 - 남은 비율`로 변환한다.
- 계정 사용 한도, 결제 토큰, 전체 세션 누적 토큰, goal 예산은 컨텍스트 점유율이 아니다. 현재 컨텍스트 토큰 수와 실제 창 크기가 모두 확인된 경우에만 비율을 계산한다. 수치가 없으면 "사용량 확인 불가"로 남기고 대화 길이로 70%를 추정하지 않는다. 자동 압축 뒤 과거 수치를 현재 수치로 재사용하지 않는다.
- 이 스킬은 이벤트마다 판단하는 절차이며 상주 감시 훅이 아니다. 자동 수치 제공이 없는 환경에서 정확한 70% 자동 감지를 보장하지 않는다.

## 인수인계와 질문

1. 진행 중인 변경·도구 호출을 안전한 중간 지점까지 정리한다. 미완료 작업을 완료로 표시하거나 사용자 에디터를 종료하지 않는다.
2. [write-handoff](../write-handoff/SKILL.md)를 읽고 실행한다. [프로젝트 인수인계 기준](../../../docs/ai/SESSION_HANDOFF.md)에 따라 작업 기록, `.claude/docs/{날짜}/handover/{제목}.md`, `.claude/docs/pointer.md`를 작성·갱신한다. 동일 전환 시도는 기존 문서를 갱신한다.
3. 인계에는 원래 요청과 변경된 요청, 살아 있는 목표·취소된 범위, 실제 파일/브랜치/커밋·미커밋 변경, 검증·미검증, 남은 결정, 진행 중 도구·에셋 편집, 다음 첫 행동을 적는다. 전환 사유와 컨텍스트 수치의 출처·확인 시점도 포함한다. 개인 설정·비밀값·전체 대화를 복제하지 않는다.
4. 구체적인 인수인계 파일 링크를 보여 주고 **"인수인계서를 작성했습니다. 새 세션에서 이 작업을 이어갈까요?"**라고 묻는다. 사용 가능한 질문 도구가 있으면 사용한다. 선택지는 "새 세션에서 계속"과 "현재 세션에서 계속"이다. 이 스킬 설치 요청 자체는 지금 새 세션을 만들라는 승인이 아니다.
5. 동의가 오기 전에는 세션을 생성하지 않는다. 무응답을 동의로 간주하지 않는다. 기다리는 동안 같은 파일에 대한 장기 변경을 새로 시작하지 않는다. 사용자가 현재 세션을 선택하면 가능한 범위에서 계속하고 같은 조건으로 매 턴 재질문하지 않는다. 새로운 목표 변경·사용자 요청·실제 한계가 생기면 다시 판단한다.

## 동의 후 새 세션 생성

현재 클라이언트의 지원 기능을 발견하고 그 스키마/도움말을 읽는다. 환경별로 아래 중 해당 경로 하나만 사용한다. 자동 커밋·푸시·브랜치 생성·권한 확대는 하지 않는다.

- **Codex 데스크톱:** 프로젝트 목록에서 실제 프로젝트 ID를 확인하고 `create_thread`로 같은 프로젝트의 local 새 채팅을 만든다. 사용자 지정 없이 worktree·브랜치·모델을 새로 선택하지 않는다. 짧고 독립적인 재개 프롬프트를 첫 메시지로 제공한다. 반환 ID로 한 번 상태를 확인해 생성과 실행 시작을 구분하고, 지원되는 새 채팅 링크를 사용자에게 제공한다. 필요하면 승인된 새 채팅을 여는 탐색 도구를 사용한다. 생성 결과가 불확실하면 목록·상태로 확인한 뒤 재시도해 중복 생성을 막는다.
- **Claude Code:** 현재 `claude --help`에서 새 세션 실행 지원을 확인한다. `claude --bg`처럼 현재 설치 버전이 지원하는 새 로컬 세션에 재개 프롬프트를 전달한다. 셸 문자열로 프롬프트를 조립하지 말고 프로세스 인자 배열을 사용하며, cwd는 같은 저장소로 유지한다. 부모 Claude 환경에서 중첩 실행이 거부되면 보호 환경변수를 제거하거나 검사를 우회하지 않는다. 반환 세션 ID와 상태를 확인하고 지원되는 attach/resume 안내를 제공한다. 기존 이력 전체를 상속하는 continue/resume/fork를 컨텍스트 비우기의 대체로 사용하지 않는다.
- **도구 없는 Codex CLI·Claude 환경:** 새 세션을 실제로 여는 지원 API/명령이 없거나 호출이 거부되면 생성했다고 말하지 않는다. 인수인계 경로와 재개 프롬프트를 제공하고 사용자가 새 세션을 열도록 안내한다. 임의 UI 자동화나 백그라운드 루프로 우회하지 않는다.

`.claude/docs/`는 Git 제외 로컬 자료다. 새 세션이 같은 파일 시스템을 읽을 수 있는지 확인한다. 접근할 수 없는 원격 환경으로 자동 전환하지 않는다.

새 세션이 작업을 인수하면 부모는 같은 파일 수정·검증을 중복 수행하지 않는다. 인계 문서에 생성된 실제 세션 ID·시작 여부를 갱신한다. 생성 실패 시 문서를 보존하고 실패 원인과 현재 세션에서 계속할 수 있는 작업을 알린다.

## 새 세션에 전달할 프롬프트

다음 내용을 실제 값으로 채우되 작업 이력 전체를 넣지 않는다.

- 프로젝트 절대 경로와 사용자 지정 브랜치
- 먼저 읽을 AGENTS.md 및 인수인계 문서의 절대 경로
- 사용자가 새 세션 재개에 동의했다는 사실
- 원래 목표, 최신 수정 요구, 완료 기준과 남은 범위
- git status·현재 파일·잠금·진행 중 프로세스를 다시 확인하고, 기존 변경을 보존할 것
- 인수인계의 첫 행동부터 실제 구현·검증을 계속하되 미검증을 성공으로 취급하지 말 것
- 커밋·푸시·메시지 발송 등의 실제 승인 범위

완료 보고에는 인수인계 위치, 새 세션 생성/시작 여부, 실제 세션 링크 또는 ID, 남은 제한을 구분한다.
