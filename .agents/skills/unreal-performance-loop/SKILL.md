# Unreal 성능 개선 반복

1. 실제 느린 동작과 대표 맵·입력·인원·네트워크 역할·플랫폼·빌드를 정한다. 유지해야 할 정확성, 측정 지표와 기준선, 후보 수·시간·비용·데이터 영향 한도를 확인한다. 기존 승인에서 정해진 예산은 다시 묻지 않는다.
2. [성능 기준](../../../docs/unreal/PERFORMANCE.md)에 따라 실제 지원되는 프로파일러/Unreal Insights 등의 측정 도구와 조건을 확인한다. 기준선이 없으면 먼저 재현·측정한다. 도구가 없으면 계획과 미측정 상태를 보고한다.
3. 증거가 가리키는 병목에 대해 한 후보당 하나의 가설을 세운다. 후보별 변경 파일·명령·입력·측정·정확성·부작용을 기록하고 동일 조건에서 비교한다.
4. 동작·권한·수명·에셋/세이브 호환성 검사를 실패한 후보는 빠르더라도 채택하지 않는다. 평균만으로 판단하지 않고 프로젝트에 필요한 프레임 시간 분포·메모리·네트워크 등 관련 지표도 본다.
5. 현재 채택 후보와 기준선을 다시 비교해 차이가 반복되는지 확인한다. 대표 입력 밖의 회귀와 다른 타깃 영향도 필요한 범위에서 검사한다. 전체 가능한 구현 중 최적이라고 주장하지 않는다.
6. 개선이 측정 잡음 수준이거나 예산을 넘거나 여러 변수의 영향을 설명할 수 없으면 반복을 멈추고 근거·미결을 남긴다. 이미 승인된 목표를 새 비용이나 과도한 재시도로 확장하지 않는다.
7. 채택 후보의 정확성·반복 측정·복구 조건·실제 명령을 프로젝트 기록에 남긴다. 성능 개선 요청을 자동 커밋·푸시 권한으로 해석하지 않는다.

| 후보 | 가설·변경 경로 | 조건·명령·증거 | 성능 결과 | 정확성/회귀 | 채택·제외 이유 |
| --- | --- | --- | --- | --- | --- |
| 기준선 | 기존 구현 | 실제 기록 | 측정값 | 결과 | 비교 기준 |
| 후보 | 한 가지 가설 | 동일 조건 | 측정값 | 결과 | 근거 |

[작업 경계](../../../docs/ai/WORK_BOUNDARIES.md)와 프로젝트 경계표·CODEOWNERS·기존 변경/잠금을 먼저 확인한다. 구현은 승인된 작성자가, 실행은 허용된 검사 담당이 수행한다. 읽기 전용 성능 분석 역할이 이 스킬을 참조해도 쓰기·실행 권한이 생기지 않는다. 경계 충돌 시 범위를 임의로 넓히지 않는다.
