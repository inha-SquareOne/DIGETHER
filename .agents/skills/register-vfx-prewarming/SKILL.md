# VFX 준비 대상 등록

목록 등록, 실제 로딩, 시뮬레이션, 렌더·PSO 준비와 성능 개선을 각각 구분한다.

## 실제 등록 체계 찾기

프로젝트 AGENTS, 효과 사용 안내, [성능 기준](../../../docs/unreal/PERFORMANCE.md), [에셋 안전](../../../docs/unreal/ASSET_SAFETY.md)을 읽는다. `prewarm`, `warmup`, `프리워밍`, 해당 에셋 참조로 기존 카탈로그·로더·풀을 찾는다. Niagara의 워밍업 옵션 하나를 범용 로딩 준비 시스템으로 해석하지 않는다.

실행 카탈로그가 있으면 소비 코드와 필드 형식을 확인해 등록한다. 문서만 있으면 실제 대상을 문서에 적고 자동 실행 미구현을 명시한다. 자동 프리워밍 구현을 요청받았다면 문서만으로 끝내지 않고 그 구현 범위와 완료 조건을 별도로 충족한다. 프로젝트에 효과 에셋 자체가 없으면 경로를 만들어 등록하지 않는다.

## 경로와 의존성

1. 사용자 지정 효과와 필요한 변형을 실제 파일·사용 안내에서 확인한다. 다른 보스나 패키지 전체를 묶어 넣지 않는다.
2. 지원되는 Unreal Editor/MCP 조회 또는 실제 Asset Registry 수단으로 패키지·오브젝트 경로를 대조한다. 경로 형식은 소비 코드가 요구하는 형식을 사용하고 경로/식별자 기준으로 중복을 제거한다.
3. 실제 참조 메시·머티리얼·텍스처·자식 효과를 수집한다. 정적 조회만 했으면 동적 로딩·소프트 참조·런타임 변형 누락 가능성을 표시한다. `.uasset`을 문자열 검색해 참조 검사 완료로 보고하지 않는다.
4. 효과별 의존성 수와 전체 고유 의존성을 구분한다. 파일 수·입자 수만으로 GPU 메모리·풀 예산을 계산하지 않는다.

## 등록 내용

- 적용 맵·사용 조건과 필수 게임 예고/장식 구분
- 실제 에셋 경로·확인 수단·의존 에셋
- 준비 단계: 로딩, 인스턴스 생성, 시뮬레이션, 실제 렌더·PSO 중 필요한 범위
- 타깃 플랫폼·그래픽스 API·품질 조건 및 미검증 변형
- 초기/최대 동시 수·상주 예산과 실제 측정 근거; 없으면 미정
- 정상 종료·취소·풀 반환·중첩 사용 시 수명 계약
- 확인일·카탈로그 소비 경로·실제 검사·남은 일

## 검증

등록 경로의 존재·참조·중복을 확인하고 실행 카탈로그를 수정했다면 로더가 새 항목을 소비하는지 검사한다. 문서만 바꾸면 링크·diff 검사로 범위를 한정한다. 에셋·코드는 [검증 계획](../../../docs/verification/VERIFICATION_PLAN.md)의 해당 수준을 적용한다.

워밍업 반환이나 등록만으로 첫 사용 끊김이 해결됐다고 하지 않는다. 해당 플랫폼·빌드에서 준비 전후 첫 사용 프레임·메모리·실패 경로를 관찰해야 성능 효과를 판단한다. 준비 실패를 숨기려고 필수 예고를 생략하거나 서버 판정을 바꾸지 않는다. 결과에는 등록·실행·측정 상태를 따로 기록한다.
