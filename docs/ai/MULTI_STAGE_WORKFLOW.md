# 여러 단계에 걸친 작업

각 단계는 독립적으로 관찰할 수 있는 결과와 검증 기준을 갖는다. 파일 수나 클래스 작성 비율만으로 단계 완료를 표시하지 않는다.

| 단계 | 산출물·제외 범위 | 선행 결정·입력 | 검사한 상태·증거 | 현재 상태 | 다음 첫 행동 |
|---|---|---|---|---|---|
| 작업별 단계 | 구체적 결과 | 확정·미결 구분 | 버전·변경분·로그 | 검증 상태 어휘 | 실행 가능한 행동 |

- 작은 실행 가능한 단위로 나누고, 완료 시 해당 단계의 빌드·기능·회귀 기준을 확인한다. 문서 단계는 L1 문서 검사로 판단한다.
- 필수 검증이 없거나 빌드가 깨진 상태를 안정점으로 부르지 않는다. 중단이 불가피하면 실패 상태와 재현·복구 경로를 사실대로 인계한다.
- 미결 계약에 의존하지 않는 작업은 계속한다. 실제 다인 환경 대기는 검사 항목·구성·예상 결과·수집할 로그를 준비해 넘긴다.
- 단계 종료를 이유로 커밋·푸시·배포를 자동 실행하지 않는다. 현재 변경 상태와 승인 범위를 기록한다.
- 장기 작업을 이어갈 때 원래 요청, 제외 범위, 결정 기록, 현재 파일을 다시 읽고 완료·남은 일을 대조한다.
- 프로젝트 일정·마감·필수 기능은 프로젝트가 정한다. 원본 프로젝트의 날짜나 미완료 작업을 복사하지 않는다.

[작업 브리프](TASK_BRIEF.md)와 [인수인계](SESSION_HANDOFF.md)를 재사용하고 같은 현황을 여러 문서에 복제하지 않는다.
