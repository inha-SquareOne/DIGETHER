# 역할 분담과 인계

에이전트 정의가 설치되어 있다는 사실은 병렬 실행 요청이 아니다. 사용자 요청이나 현재 적용 지침이 위임을 허용할 때 필요한 역할만 사용한다. 한 맥락에서 끝나는 작은 작업은 분업 비용과 비교한다.

## 여러 요청을 한 번에 받을 때

사용자가 한 메시지에서 서로 다른 기능·작업을 여러 개 지시하면 기능별로 하위 세션을 하나씩 열어 진행한다. 이 규칙은 사용자가 정한 프로젝트 기준이므로 매번 다시 묻지 않는다.

- 단위는 기능이다. 같은 기능에 속하는 지시는 한 세션에 묶는다.
- 결과가 다른 항목의 입력이거나 같은 파일·패키지·공용 설정을 고치는 항목은 나누지 않고 한 세션에서 순서대로 한다.
- 질문에 답하기, 이미 진행 중인 작업의 작은 수정처럼 현재 세션에서 바로 끝나는 항목은 세션을 열지 않는다.
- 각 세션에 목표, 쓰기 범위, 제외 범위, 완료 기준, 필요한 검증을 [작업 계약](#작업-계약)대로 전달한다. 하위 세션도 이 저장소의 지침과 커밋·푸시 범위를 똑같이 따른다.
- 세션마다 별도 작업 트리를 쓰면 결과가 각 브랜치에 남는다. 합칠지는 사용자에게 확인한다.
- 부모 세션은 어떤 항목을 어느 세션에 맡겼는지 알리고, 각 세션의 보고를 파일·실행 증거로 확인한 뒤 결과를 정리한다.
- 런타임이 하위 세션을 지원하지 않으면 그 사실을 알리고 현재 세션에서 항목별로 순서대로 진행한다.

## 작업 계약

부모는 작업마다 목표, 읽기 범위, 배타적인 쓰기 범위, 제외 범위, 기준 버전·변경분, 엔진·플러그인·플랫폼, 산출물, 완료 기준, 실행 가능한 검증, 차단 조건을 전달한다. 긴 요약 대신 필요한 규칙 원문도 연결한다.

- 하나의 파일·패키지는 한 작업자에게만 쓰기를 배정한다. 공용 설정·인터페이스·맵·에셋·생성 스크립트를 동시에 편집하지 않는다.
- OFPA를 쓴다고 공용 월드 설정이나 참조 충돌까지 없어지는 것은 아니다. 실제 파일 단위와 소스 관리 잠금을 확인한다.
- 출력이 다음 작업의 입력인 단계는 순차 실행한다. 읽기 전용 검토는 겹치는 파일을 볼 수 있다.
- 변경 가능한 경로를 받지 못한 역할은 먼저 읽기 전용으로 조사한다. 역할명만으로 전체 저장소 편집권을 얻지 않는다.

## 인계와 통합

작업자는 변경 위치, 결과, 증거 경로·검사한 버전, 미검증, 범위 밖 필요한 변경, 다음 수신 역할을 보고한다. 인계는 다른 사용자나 외부 서비스에 메시지를 보낼 권한을 주지 않는다.

부모는 요구 ID별 누락·중복을 대조하고 파일·실행 증거를 확인한 뒤 통합한다. 통합한 최종 상태로 회귀 검사를 수행한다. 리뷰어에게는 요구사항·실제 변경·기준·증거를 주고 작성자의 자기평가를 정답으로 전달하지 않는다.

## 역할과 권한

역할별 범위는 [에이전트 목록](../common/AGENTS_OVERVIEW.md)을 따른다. Claude의 도구 허용 목록과 Codex의 샌드박스는 서로 다른 통제다. 쉘·MCP·부모 실행 옵션으로 인한 실제 권한 차이는 [도구 적용 안내](../common/INTEGRATION.md)에서 확인한다.

역할이 막히면 원인·경로·필요한 입력만 보고한다. 검증 실패를 없애려고 테스트를 지우거나 권한을 우회하지 않는다. 복구와 프로세스 정리는 [실행 정책](EXECUTION_POLICY.md), 세션 인계는 [인수인계](SESSION_HANDOFF.md)를 따른다.

구체적인 담당자·공유 경로 최종 책임자·AI 쓰기 범위·잠금·사후 리뷰는 [작업 경계](WORK_BOUNDARIES.md)와 프로젝트에서 채운 [경계 양식](../templates/PROJECT_BOUNDARIES_TEMPLATE.md)을 따른다. 위임마다 그 범위와 기존 변경을 확인하고 경계 충돌 시 추가 수정을 진행하지 않는다.
