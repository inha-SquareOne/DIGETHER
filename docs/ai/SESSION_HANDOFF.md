# 세션 인수인계

인수인계는 다음 세션이 이어받기 위한 작업 메모이며 기준 문서가 아니다.
DIGETHER의 작업 기록은 `.claude/docs/{날짜}/{제목}.md`, 다른 사람에게 전달할 인수인계는 `.claude/docs/{날짜}/handover/{제목}.md`에 둔다. Claude와 Codex 모두 같은 경로를 사용한다. 날짜는 한국 시간의 작업 시작일 `YYYY-MM-DD`로 고정하고, 제목은 내용을 식별할 수 있는 파일명으로 쓴다. 같은 작업은 기존 문서를 갱신하며 같은 이름의 다른 작업은 제목을 구분한다.

전체 문서 목록은 로컬 `.claude/docs/pointer.md`에 둔다. `.claude/docs/`는 Git에서 제외되므로 다른 PC에는 없을 수 있다. 최초 작업 시 목록을 만들고, 실제 전달은 승인된 공유 경로로 별도 수행한다. 각 문서의 날짜·종류·상태·한 줄 설명·상대 링크를 기록하고 생성·이동·이름 변경·완료 시 함께 갱신한다. 완료 문서도 목록에서 삭제하지 않고 완료 상태로 남긴다. 작업 시작·재개 시 관련 항목을 찾아 읽고 실제 Git 상태와 대조한다.

[STATUS](../project/STATUS.md)는 프로젝트 현황 요약이며 상세 작업 기록의 목록을 복제하지 않는다. 기존 `docs/project/reviews/`의 검증 기록은 과거 근거로 유지하고 임의 이동하지 않는다. 새 작업 기록과 전달 문서는 사용자 지정 경로를 따른다. 비밀값·개인 대화 전문·민감한 로그는 기록하지 않는다.

팀에 공유할 결정은 해당 기준 문서에, 기능 상태 변화는 기능 현황 문서에 반영한다. 인수인계에만 적힌 결정은 결정이 아니다.
팀에 공유할 일회성 기록(검토·검증 증거)은 날짜별 기록 폴더에 두고 과거 상태를 현재 상태로 덮어쓰지 않는다. 정정·민감정보 처리는 [문서 유지](../DOCUMENTATION_POLICY.md)를 따른다.
인수인계가 없다고 이전 작업이 없다고 단정하지 말고 git 상태와 공유 문서를 확인한다.
사용자가 할 일·우선순위·남은 작업을 물을 때도 pointer와 관련 인수인계 본문을 확인한다. 현재 상태와 대조해 답하는 절차는 [응답 방식](RESPONSE_STYLE_GUIDE.md)을 따른다.

## 작성 시점

- 구현·조사·설계·오류 해결·설정·문서 작성 등 의미 있는 작업에는 작업 기록을 남긴다. 완료 시 결과와 검증을 정리하고, 장기 작업의 중간 단계·중단 시에는 재개 지점을 갱신한다. 단순 인사·기존 내용 설명만 한 턴에는 빈 기록을 만들지 않는다.
- 다른 담당자의 조치·검토·결정이 필요하거나, 담당 전환·다인 검증 대기·인터페이스 협의처럼 전달할 내용이 있으면 별도의 handover 문서를 작성한다. 전달할 내용이 없으면 형식적인 전달 문서를 만들지 않는다.
- handover에는 대상 역할 또는 확인된 담당자, 전달 목적, 필요한 행동·완료 조건, 주의사항과 원본 작업 기록 링크를 적는다. 담당자와 기한을 임의로 정하지 않는다. 같은 상세 결과를 복제하지 않는다.
- 작업 기록·handover·pointer 작성은 외부 발송이나 커밋의 자동 승인이 아니다.

## 템플릿

- 목표와 근거:
- 완료한 것 / 파일·로그 증거:
- 미완료한 것 / 막힌 이유:
- 현재 브랜치 / 미커밋 변경(저장소가 아니면 기준 사본·파일 해시):
- 엔진·도구·플랫폼·빌드 타깃과 검사한 변경 상태:
- 변경한 모듈 / 맵 / 데이터 에셋:
- 검증 수준과 결과(L1 / L2 / L3 / M등급), 추가·실패한 테스트:
- 미결 결정과 필요한 입력:
- 다음 세션 첫 행동:
- 보존할 사용자 변경 / 동시 편집 주의:
- 복구 기준·방법 / 직접 시작한 프로세스·임시 산출물과 정리 상태:
- 이어받을 승인 범위 / 별도 결정이 필요한 단계:

## 적는 방식

"미커밋", 커밋 해시, 실행 중인 프로세스 같은 동적 상태는 재확인 방법과 함께 적는다. 다음 세션은 소스 관리 상태(Git이면 status·log)와 파일·실행 환경으로 다시 확인한다. 실행 중인 프로세스는 PID만 믿지 말고 경로·시작 시각·용도도 확인한다.
추정을 사실처럼 기록하지 않는다. 확인하지 못한 것은 확인한 범위와 함께 미확인으로 적는다.
추적되지 않는 산출물(패키지, 로그)은 다른 PC에 없을 수 있다는 점과 재생성 방법을 적는다.
