# 그레이박스 프로토타입

`prototype` 브랜치에서 시스템 기획의 개발 기능을 시험한다. 정식 아트 제작과 보이스 연동은 제외하며, 사용자 추가 이미지의 광산·폐교 분위기는 프로토타입 표현에 반영한다. 이 문서의 시험값은 정식 게임 밸런스나 미결 기획의 확정값이 아니다. **기획 전체가 구현·검증 완료된 상태는 아니다.**

Steam App ID480으로 다른 네트워크에서 테스트하려면 [Steam 외부망 실행 안내](PROTOTYPE_STEAM.md)를 따른다. 아래 실행기는 `-nosteam`으로 로컬 IP 시험을 유지한다.

## 갱도 미로·폐교·금액 입력 흐름

2026-10-29 시험 흐름은 **거점 출발 → 승강기 옆 갱도 미로 → 푸른 포탈 → 폐교 교실 회수품 → 포탈로 광산 복귀 → 승강기 귀환·정산 → 금액 입력 납부 → 다음 탐사**다. 학교는 같은 탐사 안의 별도 공간이며 포탈 사용 자체는 정산이나 일차 변경을 하지 않는다. [흐름 계약](MAZE_SCHOOL_FLOW.md)을 따른다.

납부대에서 E를 누르면 한글 입력창이 열린다. 양의 정수를 입력한 뒤 Enter/확인으로 제출하고 ESC/취소로 닫는다. 보유금 초과는 거부하며 목표 잔여보다 큰 유효 요청은 잔여분만 차감한다. 입력 중 게임 조작은 차단되고 종료하면 복원된다. 기존 E 유지 자동 납부는 이 경로에서 사용하지 않는다.

`prototype-maze-school-04`에서 1인 렌더 및 로컬 4인 완주 각각13단계를 통과했다. 4인은 학교 물품120원을 각30원으로 정산하고 전원 금액 납부·목표 달성·새 RunId 출발까지 확인했다. 전원 정상 종료, 오류 로그·잔류 프로세스0이다. 최종 `prototype-maze-school-05`는 같은 게임/네트워크 코드에 입력란의 포커스 글자색만 수정한 빌드이며 최종 화면·굴착 회귀 결과를 별도로 기록한다. 4인 실행 결과를05에서 수행한 것으로 바꾸어 표시하지 않는다.

미로 배치와 학교 가구는 컨셉 확인용 기본 도형이다. 기존 굴착 한정 볼륨, 600초 시험 시간, 회수품·경제 수치를 유지하며 최종 아트나 기획 전체 완료를 뜻하지 않는다.

최종05에서도 1인 렌더 완주13단계와 실제 금액창 표시를 확인했다. 별도 굴착 회귀6단계에서 바닥 약208cm 제거·직접 진입·계단 복귀·벽124cm 제거·목재1개 보강을 통과했다. 모두 정상 종료·오류 로그0이며, 실행별 증거는 로컬 작업 기록에 보존한다.

## 실제 지형 굴착으로 전환하는 범위

2026-10-28 사용자 지시는 Digging a Hole처럼 조준한 흙이 실제로 깎여 구멍이 넓어지고 아래로 파 내려가는 방식이다. 기존 독립 큐브 축소는 이 요구를 충족하지 못한다. 갱도의 허용 3D 흙 볼륨에서 메시와 충돌을 함께 바꾸고, 던전의 지정된 파괴 가능 벽은 별도 규칙으로 유지한다. 벽·바닥·천장 방향별 허용 영역과 동시 굴착 결과는 T02~T03으로 확인한다.

구현 계약·검증 범위는 [굴착 구현 설계](../design/EXCAVATION_IMPLEMENTATION.md)를 따른다. 초도 runtime 시험은 8m × 8m, 보호층을 제외한 최대 굴착 깊이 약 2.15m의 한정 볼륨과 벽 방향 회전 시험이다. 이 시험 크기는 최종 맵 규모가 아니며 넓은 광산·다중 청크·던전으로의 확장은 미완료 범위다. 신규 프로토타입/새 게임에는 플레이 시험용 기본 삽 1개·2kg를 제공하도록 구성한다. 이는 정식 시작 지급 데이터 D22를 확정한 것이 아니다.

표현 목표는 어두운 Low Poly 광산, 따뜻한 작업등, 목재 보강, 철제 승강기, 1인칭 도구, 폐교 분위기와 읽기 쉬운 한국어 HUD다. 이미지에 보이는 수분 등 아이콘을 새 생존 자원으로 도입하지 않는다. 코드 작성·Blueprint 연결·패키지 플레이·다인 검증을 각각 확인해야 하며, 아래 과거 검증 결과를 새로운 지형 수용 결과로 재사용하지 않는다.

## 실제 굴착 패키지 검증

2026-10-28 `prototype-excavation-03`에서 Editor/Win64 패키징, 순수 지형 회귀 검사, Blueprint 연결을 확인했다. 1인 렌더 검사 6단계는 바닥 약 208cm 제거·캐릭터 하강·계단 복귀·벽 약124cm 제거·보강을 통과했다. 같은 PC의 별도 4개 프로세스에서 굴착 복제·보강·동시 요청10회·동일 ID 재접속 6단계를 통과했다. 동시 요청은 실제 변경1회와 이미 제거된 공간의 무변경9회를 구분하며 매 회차 전원 지형 hash/revision이 일치했다. 개별 네 참가자 유효 굴착도 별도 실행에서 확인했다. 이 검사는 `-nosteam` 로컬 M2이며 다른 PC Steam 접속은 미검증이다.

새 Steam 호스트는 DG-452D6C78 방의 SteamSockets listen/SDR OK까지 확인했고, 새 ZIP은 [Steam 안내](PROTOTYPE_STEAM.md)에 기재했다. 굴착 위치는 승강기 너머 노란 난간 안 갈색 흙이며 좌클릭 유지, L 헤드램프, F 보강, F1 도움말을 사용한다. 아래 기존 큐브 검증은 과거 기록으로 유지한다.
## 기준과 구성

- 엔진: UE 5.8.4(2026-11-03 변경, 아래 10-28 기록은 5.8.2 실행).
- 기준: [시스템 기획](../SYSTEM_DESIGN.md), [기본 기능 기획](../planning/BASE_FEATURE_DESIGN.md), [미결 결정](../planning/DECISIONS.md).
- 코드: `DIGETHER/Source/DIGETHER/Prototype/`. 서버 GameMode가 규칙과 거래를 처리하고 GameState는 공개 상태, PlayerState는 소유자 개인 상태를 전달한다.
- 시험 접속 ID: `?PrototypePlayerId=Player1`. 동일 ID 재접속을 시험하기 위한 문자열이며 실제 사용자 인증이 아니다.
- 저장: `DIGETHER_Prototype_` 접두사의 별도 시험 슬롯. `-PrototypeSaveSlot=<접미사>`로 실행마다 분리할 수 있다.
- 맵 Blueprint의 탐사 제한 시간은 시험용 600초다. 반복 경합·재접속을 실제 이동으로 검사할 시간을 확보한 값이며 정식 제한 시간이 아니다. 화면에는 카운트다운을 표시하지 않는다.

`Content/Prototype/Maps/L_Prototype.umap`과 `Content/Prototype/Blueprints/`의 Blueprint 10개가 네이티브 클래스를 조합한다. GameMode·Character·Controller·HUD와 월드·승강 카·장치·굴착 셀·물품·위험 요소의 클래스 연결과 시험값은 Blueprint에 있으며, 권한·정산·복제 규칙은 C++에 둔다. 코드를 빌드한 뒤 Unreal MCP로 생성·컴파일·저장했다.

미정 정책은 시험값으로만 연결했다. 시험 ID는 계정 인증이 아니며, 회수·긴급 탈출의 상세 수치나 고정 맵은 정식 기획 확정을 뜻하지 않는다. 새 게임은 기존 저장 파일을 보존하고 새 `Game_<GUID>` 접미사로 분리한다. 이후 F5/F9는 새 슬롯을 사용하며 화면에 슬롯명을 알린다.

## 직접 확인할 흐름

1. 거점에서 출발 레버를 유지하고, 중간에 놓았을 때 취소되는지 확인한다.
2. 새 굴착 빌드에서는 허용 흙 볼륨을 조준해 옆·아래로 파고 실제 표면·충돌·이동이 함께 바뀌는지 확인한다. 목재 보강과 여진 이후 손상·붕괴·재굴착·보수는 각 연결 상태와 시험 결과를 구분한다.
3. 여러 참가자가 같은 회수품을 획득해 한 사람만 소유하는지 확인한다. 일반 슬롯과 히든 슬롯, 양손 운반·중량 제한을 비교한다.
4. 동료 피해·매몰·구조·사망·시체 회수와 관전을 확인한다.
5. 엘리베이터 또는 긴급 탈출 후 정산·거점 귀환·납부·다음 탐사를 확인한다.
6. 탐사 중 신규 참가 거절과 기존 시험 ID 재접속을 구별한다. 개인 잔고와 소지품은 자기 화면에서만 확인한다.

## 자동 검증과 판정

저장소 루트에서 다음 명령으로 별도 게임 창을 연다. 참가자마다 다른 시험 ID를 쓰고 재접속할 때는 이전 ID를 사용한다. 실행기는 기존 게임 프로세스를 종료하지 않는다. 검증한 패키지를 지정하는 방식을 우선한다.

```powershell
# 호스트
$game = 'D:/DIGETHER/DIGETHER/Saved/Packages/prototype-04/Windows/DIGETHER/Binaries/Win64/DIGETHER.exe'
./scripts/Launch-Prototype.ps1 -EngineRoot 'C:/Program Files/Epic Games/UE_5.8' -GameExe $game -Mode Host

# 같은 PC의 두 번째 참가자
./scripts/Launch-Prototype.ps1 -EngineRoot 'C:/Program Files/Epic Games/UE_5.8' -GameExe $game -Mode Client -Address '127.0.0.1:7777' -PlayerId Client1
```

패키지와 로그는 Git에서 제외된 로컬 산출물로 다른 PC에는 없을 수 있다. 스크립트는 시험 맵 `/Game/Prototype/Maps/L_Prototype`의 존재를 확인하며, 맵이 없는 이전 패키지로 실행하면 실패한다. `-GameExe`를 생략한 Editor `-game` 경로는 이 환경의 Python Editor 플러그인 초기화 오류가 관찰되어 청정 실행으로 검증하지 않았다.

산술 검사는 `DIGETHER.Prototype.Settlement`다. 다중 프로세스 실행기는 `scripts/validation/Invoke-PrototypeMultiplayerValidation.ps1`이며 1·2·4인 실행을 각각 구분한다. 명령 발신과 실제 상태 변화는 별도로 판정하고 실패 로그를 보존한다.

2026-10-28, UE 5.8.2 Win64 Development의 **기존 큐브 방식 `prototype-04`** 패키지로 다음을 확인했다. 자동 다인 런은 같은 PC의 별도 프로세스·NullRHI 실행이며, 한국어 화면은 별도 PIE에서 확인했다. 아래의 ‘굴착’ 통과는 액터 축소·상태 변경 시험이며, 새로운 실제 지형 제거·충돌 구멍·하강 이동·볼륨 재접속 복제를 검증한 결과가 아니다.

최종 4인 실행은 약 6분44초였고 Host·Client1·Client2·Client3·재접속 프로세스가 모두 exit0으로 종료됐다. 명령 성공 응답만으로 통과시키지 않고 복제 상태·고유 물품 ID·실제 이동·승강·정산 결과를 검사했다. 이전 실패와 원인 수정은 로컬 `.claude/docs/2026-10-28/개발반-그레이박스-프로토타입.md`, 상세 JSON·로그는 그 날짜의 `prototype/runs/`에 보존한다.

같은 PC의 다중 프로세스 검사는 서로 다른 PC·플랫폼 서비스·WAN 환경이나 게임 전체 M2/M3 수용을 대신하지 않는다. 스냅샷 비교로 패킷 수준 비밀성까지 증명하지 않으며, 시험 이동 입력은 물리 키 입력 전체 검증을 대신하지 않는다.

경합 기록은 두 로컬 Controller의 RPC 호출과 고유 물품의 단일 획득을 확인한다. 패자의 요청이 서버에서 처리·거절됐다는 별도 응답이나 패킷 캡처까지 수집한 검증은 아니다.
