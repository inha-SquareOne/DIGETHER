# DIGETHER 개발 결정과 기획 확인 요청

기준일: **2026-11-06** · 전달 대상: **기획반** · 상태: **검토 요청용 공유본**

개발하면서 정한 사항, 확정 전 시험용으로 넣은 값, 앞으로 결정할 사항을 한 문서에 정리했다. **경제·납부 경계, 전멸 시 장비 처리, 최초 몬스터 상세부터 확인을 요청한다.** 이미 정한 규칙은 유지하고, 시험값은 유지·변경·시험 후 결정 중 하나로 답해 주면 된다. 각 항목의 배경과 현재 처리를 본문에 적었으므로 다른 자료를 열지 않고 검토할 수 있다.

## 읽는 기준

| 구분 | 뜻 | 기획반이 할 일 |
|---|---|---|
| 사용자 결정 | 개발 과정에서 사용자가 명시적으로 선택한 내용 | 기획에 반영하고, 변경이 필요하면 이유와 새 결정을 기록 |
| 기획 자료의 확정 규칙 | 현재 개발 기준으로 받은 기획에서 확정으로 표시한 내용 | 팀 승인 상태를 확인. 자료 안의 확정 표시와 팀 승인 완료를 구분 |
| 기획 시험안 | 기획 또는 사용자가 비교·조정을 위해 제시한 값과 동작 | 유지·변경·시험 후 결정 중 하나로 답변 |
| 개발 기본값 | 기능을 연결하고 시험하기 위해 개발이 채운 값 | 정식 수치로 채택할지 결정하고 단위·범위·적용 시점 지정 |
| 미결 | 규칙이 비어 있거나 여러 설명이 달라 결론이 필요한 내용 | 정상 동작과 예외를 함께 결정 |
| 개발 후속 | 규칙은 있으나 구현·연결·검증이 남은 내용 | 새 정책 질문과 구분하고 결과를 확인해 수용 여부 판단 |

**미정 수치를 임시로 채워 개발을 진행하는 것은 사용자에게 허용받았으며, 최종 기획 승인은 별도다.** 이 문서의 값은 시험 기본값과 제작 시 입력값을 포함한다. 실제 에셋의 현재 저장값과 미저장 편집값은 이번에 추출하지 않았으므로 모든 숫자가 현재 게임에 그대로 적용됐다고 볼 수 없다. 새 게임 실행·플레이테스트를 수행한 보고서도 아니며, 수치의 재미·밸런스·최종 승인과 기능의 구현·검증은 구분한다.

## 1. 이미 정한 사항

### 사용자 결정과 이후 변경

| 주제 | 현재 결정 | 적용 경계 |
|---|---|---|
| 굴착 | 조준한 허용 흙이 실제로 깎이고 구멍이 넓어지며 아래로도 팔 수 있음 | 최종 지형 규모와 던전 지정 벽의 파괴 허용은 별도 |
| 엘리베이터 문 | 레버 게이지 완료 후 자동 닫힘. 닫히는 동안 탑승 가능. 탑승 목록은 문이 완전히 닫힌 순간 고정 | 문턱에 선 사람을 밀어내는 이전 방안은 폐기. 게이지 완료 뒤 계속 레버를 잡을 필요 없음 |
| 거점 미탑승자 | 문 닫힘 완료 때 거점에 남아 있는 참가자를 사슬로 소집 | 초기 시험 구현은 순간이동 1회. 사슬·암전의 연출 길이는 시험값 |
| 같은 계정 재접속 | 이전 접속을 끊은 뒤 새 접속 수락 | 이미 연결돼 있다는 이유로 새 접속을 거절하던 이전 방식을 대체 |
| 시작 잔고 | 새 게임은 개인 잔고 0 | 지원금 500은 개발 빌드의 시험 전용이며 출시 시작 잔고가 아님 |
| 수동 저장 | 플레이어용 수동 저장 없음 | 개발용 저장·불러오기 기능은 출시 빌드에서 제외 |
| 참가 실패 안내 | 계정 확인 실패·같은 계정 접속 중·탐사 중·정원 초과·버전 불일치·방 종료의 6종 구분 | 실패 사유를 참가자에게 구분해 안내 |
| 음성 방식 | 엔진 기본 음성 통신 사용. 기본 마이크는 항상 켜짐. 개인 설정에서 누르고 말하기 선택 가능 | 누르고 말하기의 기본키는 미배정. 실제 Steam 환경 검증은 개발 후속 |
| 관전 음성 | 관전자끼리는 거리와 무관하게 대화. 관전자는 관전 대상의 위치·구역 기준으로 생존자 음성을 들음 | 생존자는 관전자 음성을 듣지 못함. 관전 대상을 바꾸면 청취 기준도 함께 변경 |
| 개발 환경·출시 | Unreal Engine 5.8.4, Steam 판매 방향 | 시험용 Steam App ID 480을 출시용으로 사용한다는 결정은 아님 |

엘리베이터 문턱·계정 교체·출시 지원금의 현재 기준은 2026-11-05 결정이고, 음성의 위치·구역 및 조작 상세는 11-06 결정까지 반영했다. 이전 방식을 다시 선택하도록 묻지 않고 남은 예외만 3절에서 확인한다.

### 기획에서 정한 현재 개발 기준

아래는 현재 기획 기준이다. 규칙이 있다는 것과 구현·플레이테스트·팀 승인이 끝났다는 것은 별개다.

| 주제 | 유지할 규칙 | 경계·예외 |
|---|---|---|
| 초대 | Steam 초대와 방 코드 모두 사용 | 게임 내 친구 목록은 UI 시안 뒤 검토 |
| 납부 입력 | 여러 명이 동시에 우클릭을 누르고 금화를 붓는 방식 | 이전의 직접 금액 입력·정산기 1인 점유 방식은 사용하지 않음 |
| 신규 참가 | 정상 거점 준비 중에만 허용 | 출발 게이지 완료부터 로딩·탐사·정산·실패 사건·크레딧까지 잠금. 기존 참가자 재접속과 구분 |
| 호스트 이탈 | 방 종료, 다른 참가자에게 호스트를 넘기지 않음 | 탐사 도중 종료한 진행은 저장하지 않고 마지막 정상 완료 저장을 사용 |
| 목적지 | 해금 비용은 요청자 부담, 팀 전체 해금. 누구나 선택 가능 | 출발 레버를 잡기 시작하면 목적지 고정. 게이지 도중 취소 시 고정 해제 |
| 시작 장비 | 개인 삽 1개·헤드랜턴 1개. 새 게임 공용 삽·곡괭이·헤드랜턴 각 4개 | 가격·중량·가치는 별도 미결 |
| 상승·제한 시간 | 일반 상승 최대 2회, 최초 하강은 횟수에서 제외. 최초 하강을 마쳐 갱도에 도착한 순간 제한 시간 시작 | 상승 1회 비교 프로필은 폐기 |
| 매몰·구조 | 시간 경과만으로 매몰 단계가 오르지 않음. 더 높은 추가 붕괴에 덮이면 새 단계로 갱신하고 구조 진행 0 | 한 매몰자에게 한 번에 1명만 구조 |
| 거점 공격 | 공격 동작 가능, 피해 0 | 넉백 등 부수 효과는 별도 확인 |
| 정산 분배 | 일반 화물 회수 총액을 거점 출발 인원으로 나눔. 생존자는 탈출 시점과 무관하게 지급, 사망자 몫 소멸 | 현재 합산형의 최종 유지는 플레이테스트 후 재검토. 탈출 시점에 따른 분배는 비교 요청 상태 |
| 시체 복구 | 전멸이어도 지상에 도착한 유효 시체의 복구금 지급 | 손실·복구 비율은 잠정 |
| 자동 저장 | 정상 탐사 완료·목표 달성·호스트 정상 거점 종료·5일차 실패 귀환 시 저장 | 플레이 중 저장 실패는 알림 후 재시도하며 출발을 막지 않음 |
| 공통 로딩 실패 | 준비·납부·마감을 유지하고 같은 일차의 거점으로 복귀 | 개인 로딩 실패·접속 종료의 정산 자격은 추가 결정 필요 |
| 게임 오버 | 우물 범람→거점 침수→흡입→함께 보는 결과 크레딧 | 크레딧 뒤 현재 슬롯을 새 게임으로 초기화하고 같은 방의 새 거점으로 이어짐 |
| 외형·하우징 | 개인 기본 외형과 진행별 구매 치장 구분. 고정 물체는 엘리베이터·정산머신·갱도 해금 머신 | 외형 변경 장치 없이 거점 메뉴에서 변경. 유효하지 않은 저장 배치는 전체 기본 배치로 복원 |
| 정보 공개 | 출발 경고에 개인 잔고·납부 부족분을 표시하지 않음. 생존자 화면에 발화자 이름·위치 표시 없음 | 던전에는 갱도 흔들림·소리·여진 경보를 전달하지 않음 |

납부의 동시 붓기, 여러 저장 슬롯, 출발을 막지 않는 저장 실패 처리, 전멸 시 유효 시체 복구금 지급은 이전 설명을 대체한다. 현재 기준에 맞지 않는 옛 안내는 개발에서 정리한다.

## 2. 확정 전 시험용으로 넣은 값과 동작

### 기획·사용자가 제시한 시험 기준

| 항목 | 현재 시험 기준 | 결정이 필요한 부분 |
|---|---|---|
| 일차별 납부 효율 | 1~3일차 30%·50%·70%. **4일차 100%는 확정** | 1~3일차 정식 효율과 난이도. 초기 시험값 70%·80%·90%는 사용하지 않음 |
| 목표 금액 | 첫 목표 100, 달성마다 +100 | 최초 금액·증가식·플레이 인원별 조정 여부. 첫 목표는 별도 수치 입력, +100은 개발 기본값 |
| 사망·시체 | 잔고 100% 손실, 유효 시체 회수 시 사망 직전 잔고 50% 복구, 소수점 버림 | 비율 유지 여부. 손실률을 바꿀 때 복구 기준을 사망 직전 잔고로 유지할지 손실액으로 바꿀지 |
| 최초 몬스터 | 땅거미 HP 100, 미스터리 박스 처치 가능·HP 200. 기본 공격 12.5 가정 | 종별 행동·피해·처치 조건. 박스의 처치 가능 여부도 최종 승인 필요 |
| 무료 목재 | 탐사마다 팀 공용 4개 배치 | 정식 수량·회수 가치·일반 화물 분배 포함 여부. 시험 기준이 있다는 것이 현재 배치 완료를 뜻하지 않음 |
| 납부 신호기 | 인정액 비율 50% 이상 주황, 80% 이상 초록, 그 미만 빨강 | 구간 유지 여부와 색·소리의 의미 |
| 음성 거리 | 3m까지 원음, 최대 25m. 매몰 시 먹먹함·최대 거리 절반은 기획 제안 | 거리·감쇠·매몰 효과를 실제 음성 시험으로 조정. 매몰 효과 구현 완료를 뜻하지 않음 |
| 캐릭터 초기 규격 | 스케일 1.2/1.2/0.85, 통과 82×165cm, 앉기 115cm, 중력 1.5배 | 충돌 범위·카메라와 실제 통과 규격의 대응 |
| 이동·점프 | 걷기/달리기/웅크리기 400/600/200cm/초, 점프 450cm/초 | 실제 점프 높이·공중 제어·점프 1회 스태미나 |

### 개발 진행을 위해 채운 기본값

아래 값은 개발 기본값 또는 시험 시설을 만들 때 넣은 값이다. 이미 있는 에셋에서 별도 값을 지정했으면 실제 적용값이 다를 수 있다.

| 항목 | 현재 기본값·시험 동작 | 기획 확인점 |
|---|---|---|
| 붓기 금액 | 한 주기당 10. 잔고 부족 시 남은 잔고 사용을 시도 | 주기당 금액과 주기 간격을 함께 확정 |
| 엘리베이터 무게 표시 | 무게 한도의 30%·70%를 표시 단계 경계로 사용 | 단계 경계·표시 의미 |
| 레버·정차·문 | 위층 정차 3초, 상승 레버 3초, 출발 기본 유지시간 3초, 거점·갱도 문 닫힘 각 3초 | 각각의 시간. 4일차 출발 유지시간 2배 규칙과 기본 3초의 임시 상태를 구분 |
| 사슬 소집 | 연출 길이 0초. 문 닫힘 완료 순간 순간이동 1회 | 사슬·암전·권양기 예고의 길이와 표현 |
| 여진 | 3단계, 간격 최대 30초→최소 5초 | 단계 수·시간 변화 곡선·체감 위험 |
| 저장·결과 보관 | 슬롯 3개, 슬롯당 이전 결과 10개, 저장 실패 재시도 10초 | 슬롯 개수·보관 개수·알림 방식. 여러 슬롯을 둔다는 요구와 3개라는 시험값을 구분 |
| 계정 교체 | 이전 연결 정리 최대 대기 5초 | 대기·실패 안내 경험. 이전 연결 종료 후 새 접속 수락 정책은 이미 결정 |
| 실패 사건 | 정산 화면 5초, 범람·침수·흡입 전체 12초, 앞 50% 범람 후 흡입, 흡입 1500cm/초 | 장면별 길이·속도·시점. 전체 12초가 끝나면 남은 사람을 강제로 흡입하는 복구 처리 존재 |
| 크레딧 | 시작 대기 2초, 화면 높이의 0.08/초로 스크롤, 기울기 25도, 블록 간격은 화면 높이의 0.15 | 글꼴·줄바꿈·가독성·끝나는 시각을 함께 검수 |
| 크레딧 빨리감기·길이 | 빨리감기 4배, 전체 길이 계산용 줄높이는 화면 높이의 0.06 | 마지막 항목이 지나가기 전에 종료되지 않는지 확인 |
| 우물 범위 | 흡입 반경 기본 30m, 대기 간격 1.2m, 대기 깊이 기본 −15m | 우물 위치·흡입 범위·대기 화면. 맵에서 지정한 실제 값은 미확인 |
| 거점 시험 상점 | 목재 묶음 10, 예비 헤드랜턴 20, 시험 곡괭이 30 | 정식 품목·가격·중량·성능·배송/수령 방식 |
| 시험 목적지 | 광산 기본 해금, 유적 100·수정 200 | 시험 목적지의 정식 채택·해금비. 현재 시험 구역은 정식 갱도 콘텐츠가 아님 |
| 제단 | 5헌납→팀 누적·10초 발광 | 헌납 목적·비용·효과·개인/팀 공유 범위 |
| 침대 | 침대별 1인 점유·휴식 위치 이동/복귀. 회복 효과 없음 | 휴식 효과 채택 여부. HP·피로 회복을 구현했다는 뜻이 아님 |

우물의 수면·흡입 모양, 발광·회전, 크레딧 위젯 간격은 시험 시각 표현이다. 판정 범위·게임 규칙과 구분해 최종 아트 시안으로 검수한다. 음성 상태 갱신 0.25초, 납부 요청 제한 0.2초, 저장 용량·기록 수 상한은 개발 기술값이며 납부 주기나 게임 경제 수치로 해석하지 않는다.

### 납부에서 특히 확인할 현재 시험 처리

현재 시험안은 **목표를 채우는 데 필요한 금액만 실제로 소비하고, 나머지를 바닥 금화로 돌려주는 방식**이다. 이를 최종 승인한 상태는 아니다.

- 매 주기 금액과 잔고 중 작은 금액을 기준으로 효율을 곱하고 소수점 아래를 버린다. 인정액이 0이면 잔고를 차감하지 않고 붓기를 멈춘다.
- 목표를 초과하면 목표를 채우는 최소 정수 금액만 소비하고 나머지는 정산기 앞 바닥 금화로 돌려준다. 바닥 금화 생성에 실패하면 필요한 금액만 지갑에서 차감한다.
- 예: **효율 30%, 잔고 10, 남은 목표 1**이면 지갑 10 차감→목표 1 인정→바닥에 6 반환, 실제 소비 4다. 효율 30%에서 잔고 1~3만 남으면 인정액 0이므로 차감 없이 중단한다.
- 목표를 달성하면 모든 사람의 붓기를 종료한다. 현재 돈자루를 손에 들어야 붓는 조건은 구현 후속이다.

이 방식에서는 같은 금액이라도 여러 작은 주기로 나누면 매번 버림이 발생할 수 있다. 인정액의 소수 부분을 다음 주기로 이월할지, 작은 잔고를 따로 처리할지도 함께 결정해야 한다.

### 프로토타입 제작에 사용한 시험값

다음은 프로토타입을 처음 만들 때 입력한 수치다. 기존 에셋을 자동으로 덮어쓰지 않으므로 현재 게임의 적용값으로 확정하면 안 된다.

| 항목 | 제작 시 시험값 | 확인할 점 |
|---|---|---|
| 첫 목표·제한 시간 | 목표 100, 제한 시간 600초 | 현재 사용 프로필과 최종 승인값 대조 |
| 상호작용·적재 | 상호작용 350cm, 엘리베이터 한도 40kg | 정식 플레이어·장비·카메라 기준으로 검수 |
| 상승·운행 | 상승당 시간 감소 10초, 운행 4초 | 구간별 시간인지 전체 시간인지 정의 필요 |
| 납부·긴급 탈출 | 붓기 간격 0.25초, 긴급 탈출 5kg | 요청 제한 0.2초와 붓기 주기를 혼동하지 않음 |
| 회수품 | 가치 40·중량 5kg | 정식 아이템 목록·경제표에 맞춰 별도 승인 |

첫 목표·시간·중량·사망 비율은 탐사에 사용하는 수치 프로필에 입력해야 한다. 최종 수치표 승인 시 실제 사용 프로필도 함께 대조한다. 붕괴 예고·천장 각도·몬스터 출현 조건 등 아직 수치 연결이 없는 항목은 값을 정하는 것과 게임에 연결하는 작업을 구분한다.

## 3. 기획반 결정이 필요한 사항

검토 순서는 제안이며 담당자·기한을 배정한 것이 아니다. **현재 처리 유지**라고 답하더라도 경계·예외까지 포함하는지 밝혀 주면 된다. 아래 번호는 이 문서 안에서 답변 대상을 구분하기 위한 번호다.

### 먼저 확인할 게임 규칙

| 번호·주제 | 요청하는 결정 | 결정에 따라 달라지는 부분 |
|---|---|---|
| 01 경제·무료 자원 | 첫 목표·증가식, 1~3일차 효율, 아이템 가치·중량·가격·상점 목록을 정해 달라. 무료 목재 회수금이 일반 화물 분배에 포함되고 전멸 시 함께 소멸하는지도 필요 | 경제 난이도·구매력·무료 자원의 반복 회수 |
| 02 붓기·잔돈 | 주기당 금액·간격, 최소 정수 단위, 소수 인정분 이월 여부, 작은 잔고 처리, 목표 초과분 반환 산식을 정해 달라. 2절 시험 처리와 숫자 예시를 유지해도 되는지 확인 | 실소비·잔돈·목표 달성 순간의 동시 납부 |
| 03 분배·사망·장비 | 현재 합산형 분배를 유지할지 비교 시험 후 결정. 사망 손실·복구 비율과 계산 기준을 정해 달라. **전멸 시 장비가 어디까지 사라지고 어디까지 남는지** 시험 기준도 필요 | 생존/사망 위험·장비 보존·시체 회수 보상 |
| 04 최초 몬스터 | 땅거미·미스터리 박스의 시험 선정을 정식 선정으로 유지할지 결정. 종별 감지·이동·공격·상태이상·해제·보상·처치 여부·장비별 피해·체력 표시·등장 수 상한을 명세 | 최초 몬스터 제작 범위·전투·출현·음성 감지 |
| 05 시설·바닥 물품 저장 | 거점 바닥 물품의 저장 범위를 정해 달라. **시설 상태가 바뀔 때마다 자동 저장하는 현재 처리를 공식 저장 시점에 추가할지** 확인 | 구매·해금·배치·헌납 후 종료/재시작 결과 |
| 06 엘리베이터 예외 | 문 닫힘 완료 후 출발을 취소할 사유, 빈 편도 상승 횟수·시간 차감에 포함하는지, 레버 점유·무게 초과가 겹칠 때 안내 우선순위를 정해 달라 | 상승 횟수·남은 시간·취소와 실패 안내 |
| 07 구역 전환·벽 파괴 | 갱도↔던전 전환에서 무로딩이 필수인지, 짧은 전환 연출·로딩을 허용하는지 결정. 던전 지정 벽 파괴는 레벨 디자인 결정 전 보류. 채택하지 않으면 몬스터 길 막힘 대응도 필요 | 구역 연결·생성·레벨 제작량·길찾기 |

| 번호·주제 | 요청하는 결정 | 현재 정해진 부분 |
|---|---|---|
| 08 실패 사건·크레딧 | 장면·소리·길이·가독성, 별도 할당량 미달 화면 필요 여부. 총액 첫 블록과 획득/히든/사망손실 3블록 구성, 저장→조작 복구 순서를 확인. 떠난 사람 포함 기준·참가 순서 기준도 필요 | 범람→침수→흡입→함께 크레딧→같은 슬롯 새 게임 |

## 4. 개발 협의와 정리가 먼저 필요한 사항

아래는 기획반이 새 게임 규칙을 모두 정해야 하는 목록이 아니다. 개발에서 선택지·비용·검증 결과를 준비하고 필요한 부분만 공동 결정한다.

| 항목 | 필요한 조치 |
|---|---|
| 옛 안내 정리 | 동일 계정 추가 접속 거절, 납부 직접 입력·1인 점유, 문턱 밀어내기, 수동 저장·저장 실패 출발 차단 등 이전 안내를 현재 결정에 맞춰 정리 |
| 납부 마감 경계 | **4일차 출발 게이지 완료 순간** 마감으로 통일. 문 닫힘 완료나 실제 이동 시작과 혼동하지 않게 안내 |
| 수치표 연결 | 모든 값에 이름·단위·기본/최소/최대·적용 범위·진행 중 변경 여부를 기록. 단위는 kg·m·초·도·정수 금액 등을 명시하고 실제 적용값과 대조 |
| 고정값·생성값 | 상승 2회는 고정 규칙으로 표시. 맵 생성 때 쓰는 둥지 확률 등을 변경하면 다음 생성부터 적용되는지 명확히 표시 |
| 중복 요청 | 요청마다 고유 번호를 붙이는 방식 자체가 필요한지, 최종 결과가 한 번만 반영되면 충분한지 개발 계약 확인 |
| 음성 연동 | 실제 Steam 계정·다른 PC에서 차단·거리·방향감·관전 음성·마이크 모드 검증. 몬스터 감지에 사용할 발화 정보 제공 여부 확인 |
| 출시·지원 | 정식 Steam App ID, 출시 세션 구성·Steam Cloud, 지원 OS·최소 사양·프레임/대역폭 목표, 저장 형식 호환 범위를 공동 결정. 현재 내부 백업이 있는 자동 저장을 사용한다는 사실과 출시 저장 호환 정책을 구분 |
| 승인·수용 | 결정의 개정·승인자·승인일과 기능별 수용 기준 기록. 담당과 기한은 실제 배정 후 기록 |

규칙은 있으나 구현이 남은 부분도 있다. 현재 돈자루를 손에 들어야 붓는 조건을 생략하고 있으며, 거점 이탈 시 장비를 바닥에 남기는 처리는 인벤토리 연결 후속이다. 사슬 소집 위치를 찾지 못하면 출발을 거절하는 시험 처리도 있다. 이들은 새로 승인된 게임 예외가 아니라 개발이 규칙과의 차이를 해소하고 검증할 항목이다.

## 5. 기획반 답변 양식

각 항목의 주제 또는 3절의 번호를 적고 아래 형식으로 답하면 된다. 숫자만 답할 때도 단위·범위·적용 시점을 함께 남긴다. “현재 시험값 유지”에는 이 문서의 정수 계산·부족분·초과분·동시 처리까지 포함하는지 밝혀 달라.

| 답변 항목 | 작성 내용 |
|---|---|
| 대상 | 절·번호·주제 |
| 결정 | 현재 기준 유지 / 변경 / 시험 후 결정 / 보류 |
| 확정 규칙·수치 | 값·단위·최소/최대·적용 대상 |
| 예외 | 잔고 부족·목표 초과·동시 요청·사망·끊김·종료 시 처리 |
| 적용 시점 | 즉시 / 다음 탐사 / 다음 기간 / 새 게임 |
| 시험 기준 | 플레이테스트에서 확인할 행동·관찰 결과·판정 기준 |
| 승인 | 개정·승인 상태·승인자·승인일 |

답변을 받은 뒤 개발은 해당 결정에 맞춰 구현·검증 결과를 정리하고, 기획반은 그 결과를 기준으로 수용 여부를 확인한다. 시험값을 정식으로 유지하는 경우에도 값과 적용 범위를 승인 기록에 남긴다.
