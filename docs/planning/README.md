# DIGETHER 기획 — Notion 가져오기 패키지

기준일: 2026-10-23(문서 목록과 Notion 서술은 2026-11-10 정정). 상태: **로컬 초안 / 기획 원본의 Notion 이관 전**. Notion에는 개발 작업 보드가 있으나([담당 연결](../project/CODE_OWNERSHIP.md)) 작업 목록이며 기획 원본이 아니다. 아래 '권장 DB'의 요구사항·결정 DB를 온라인으로 만든 상태가 아니며, 기획 원본 페이지의 주소와 작성·검토 담당자는 이 저장소에 등록돼 있지 않다.

## 원본과 관리 경계

- 사용자 확정: 기획은 Notion, 프로젝트 파일은 GitHub, 엔진은 Unreal Engine **5.8.4**(2026-11-03 5.8.2에서 변경).
- 현재 이 폴더는 검토 가능한 기획 초안이다. **Notion을 기획 원본으로 사용하는 것은 사용자 확정이다.** 실제 이관을 확인하고 주소를 연결한 뒤 이 폴더를 기준일이 있는 스냅샷으로 관리하는 절차는 제안이다. 두 원본을 동시에 수정하지 않는다.
- GitHub에는 소스·설정·에셋과 기술 문서, 구현 작업과 검증 근거를 관리한다. 저장소 origin은 https://github.com/inha-SquareOne/DIGETHER 로 확인했다. LFS 등 운영 규칙과 원격 권한은 별도 확인한다. 외부 서비스 개설·연결은 수행하지 않았다.
- 요구 ID는 Notion 요구사항, GitHub Issue/PR, 검증 기록의 공통 연결 키다. 수치의 기획 목표는 Notion에, 실제 적용값은 구현 데이터 원본에 두고 링크로 비교한다.

Notion에 DIGETHER 루트 페이지를 만든 뒤 Markdown 파일을 가져오거나 본문을 붙여 넣는다. 실제 가져오기 기능과 권한은 사용 시 확인한다. 기획 파일 링크는 이관된 Notion 페이지 링크로 교체한다. GitHub 소관 ADR·기술 문서는 push 후 실제 커밋이 고정된 GitHub URL로 교체하고, 그 전에는 외부 링크 등록 보류로 표시한다. 이어서 요구 ID·표·페이지 근거·미정 표시가 보존되는지 점검한다. 아래 DB는 필요 시 팀이 생성할 **구조 제안**이며 이미 생성된 DB가 아니다.

## 권장 DB 속성

| DB | 속성 | 설명 |
| --- | --- | --- |
| 요구사항 | 제목, 요구 ID, 영역, 근거, 근거 상태, 기획 승인 상태, 구현 수용 결과, 수용 조건 | 근거 상태(사용자 확정/기획 초안/검토 필요/제안), 착수 전 기획 승인(미검토/검토 중/승인/보류), 구현 후 수용(미검증/수용/변경 필요)을 분리 |
| 요구사항 | 개정 번호, 승인일, 승인자, 마일스톤, 담당, 결정, GitHub Issue, PR, 검증 링크 | 담당과 URL은 실제 배정·생성 뒤 입력; 없으면 공란 |
| 결정 | 결정 ID, 제목, 상태, 연결 요구, 배경, 대안, 결정·이유, 승인 근거, 검토 계기 | 미결을 승인 완료로 옮기려면 실제 결정 근거 필요 |
| 마일스톤 | 단계, 목표, 포함 요구, 완료 근거, 담당, 시작일, 종료일 | 날짜·담당 미정; 완료 근거 없는 완료 표시 금지 |
| 플레이테스트 | 테스트 ID, 빌드/커밋, 연결 요구, 참가 인원, 절차, 기대, 관찰 결과, 증거, 이슈 | 요구사항 수용 조건을 실제 결과와 분리 |

개정 번호는 팀이 직접 부여하며 PR에는 요구 ID와 함께 기록한다. 마일스톤 완료는 GitHub 증거 링크와 기획 수용 확인이 있어야 표시한다. 기술·운영 결정 DB 행은 질문·요구·ADR 링크만 관리하고 실제 결정과 상태는 GitHub 원본을 따른다.

DB 관계는 가져온 Markdown만으로 자동 구성되었다고 가정하지 않는다. 요구사항→결정/마일스톤/플레이테스트 관계를 실제 생성한 뒤 연결한다. GitHub 작업에는 `DG-xxx`, 기획 변경에는 해당 결정 ID를 넣는다.

## 기획 변경 흐름 제안

Notion에 변경 이유·영향 요구를 기록 → 미결 결정을 팀이 승인 → 관련 GitHub 작업에 기획 링크 및 요구 ID 연결 → 구현·검증 증거 연결 → Notion의 기획 수용 결과 확인. 개발 진행 상태는 GitHub Issue/PR을 참조하고, Notion에서 별도로 최신 상태를 수작업 복제하지 않는다. 엔진 버전 등 기술 결정이 기획에 영향을 주면 양쪽 문서에 같은 결정 ID를 연결한다.

수용 조건은 **검증을 위한 초안**이며 실제로 테스트를 통과했다는 의미가 아니다.

가져오기 기능 근거: [Notion 공식 가져오기 안내](https://www.notion.com/help/import-data-into-notion), 2026-10-23 확인. Markdown 가져오기 뒤 링크와 표를 검수한다.

## Notion에서 기획 읽기

이관 뒤 페이지 내용을 가져오거나 구현 전 요구사항을 확인할 때 [notion-read-planning](../../.agents/skills/notion-read-planning/SKILL.md)을 사용한다. Notion 연결과 페이지 접근 권한을 확인하고 원문 링크·개정·승인 상태를 함께 읽는다. 위 문서는 이관 전 초안이며 Notion 기획 원본과 대조한 결과가 아니다.
