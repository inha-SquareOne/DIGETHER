# DIGETHER 거점 기능 설계

기준일: 2026-10-28 · **Notion 이관 전 초안**. 개발팀 작업 목록을 반영한 기획 범위이며 팀 승인·구현 완료를 뜻하지 않는다. 전체 상태 소유와 경합·저장 계약은 [전체 시스템 설계](../SYSTEM_DESIGN.md)를 따른다.

## 거점에서 할 일

모든 플레이어는 장비를 준비하고 상점에서 개인 재화로 구매하며, 정산머신에 납부하고 해금된 갱도를 선택할 수 있다. 해금 비용은 요청자의 잔고에서 차감하고 결과는 팀이 공유한다. 동시에 같은 갱도를 해금해도 호스트가 먼저 확정한 한 건만 차감한다. 목적지 동시 변경과 출발이 겹칠 때 고정 시점과 점유 방식은 D28이다.

출발 레버는 누구나 당길 수 있고 별도의 준비 확인은 없다. 완료하면 모두 엘리베이터에 이동한다. 4일차에는 일반 유지 시간의 두 배를 요구하고 경고를 표시한다. 게이지를 채우기 전에는 마감하지 않는다. 완료 순간 납부를 마감하며 미달이어도 출발한다. 목표 달성이 먼저 확정되면 기존 레버·경고와 마감은 취소하고 새 목표의 1일차 출발을 다시 요청한다. 마감이 먼저면 늦은 납부는 차감 없이 거절한다.

출발 확정 시 진행 중 거래를 정리하고 창구·패널·배치 점유를 해제하며 미확정 배치를 원위치로 유지한다. 납부는 한 번에 한 명만 정산머신을 사용하며 정수 금액이다. 초과 납부·환불은 허용하지 않는다. 완료·취소·거리 이탈·연결 해제에 점유를 정리한다. 개인 납부 상세는 다른 플레이어에게 공개하지 않으며 표시·복제·오류·로그를 함께 검사한다. 인정액의 절사·이월과 최소 차감 단위는 D27, 최초 목표와 일차별 비율은 D22 미결이다.

목표 달성은 즉시 새 기간·목표·1일차로 전환한다. 4일차 미달을 확정하고 출발한 탐사가 끝나면 5일차 거점에서 종료 모션 → 실패 화면 → 결과 크레딧 순서로 진행한다. 크레딧을 먼저 마친 사람의 신호로 새 게임을 한 번 만들고 뒤늦게 마친 사람은 같은 거점에 들어온다. 아직 크레딧을 보는 연결된 사람이 있으면 출발을 막는다.

## 저장과 배치

자동 저장은 탐사 종료 후 일차 변경·정산·복구·지급 완료 기록·부활·귀환 판정을 반영한 뒤 수행한다. 조기 목표 달성도 납부와 새 기간 전환을 완료한 상태를 저장한다. 출발 로딩 실패 시 해당 일차 시작 자동 저장으로 되돌리며 이후 구매·납부·해금·목적지·배치와 마감도 함께 복원한다. 수동 저장은 호스트만 가능하며 허용 상태는 D29에서 결정한다.

S35 하우징은 P2 후속이다. 모든 플레이어는 상점·침대 등 이동 가능 오브젝트를 자유 배치·회전할 수 있다. 호스트는 벽·사람·오브젝트와의 겹침, 출입구·납부기 앞·동선을 검증한다. 엘리베이터·정산머신은 고정, 해금 머신과 외형 변경 장치의 고정은 D40 시험 기준이다. 배치는 진행 저장 단위에 포함하고 새 게임에서는 기본값으로 초기화한다. 유효하지 않은 저장 배치는 전체 기본 배치로 복구하고 안내한다.

## 수용 관찰 초안

1~4인에서 원격 참가자의 출발, 동시 해금·납부, 목표 달성과 출발 경합을 확인한다. 4일차 미달 출발과 5일차 실패, 빠른 크레딧 종료 및 중복 완료 신호를 검사한다. 구매·납부·해금·배치 후 로딩 실패와 정산 완료 후 재시작에서 모든 값의 일관성과 중복 지급 방지를 관찰한다. 개인 납부 내용의 전송과 표시도 검사한다. 이는 실행 결과가 아니며 실제 구현 후 L1~L3/M2가 필요하다.
