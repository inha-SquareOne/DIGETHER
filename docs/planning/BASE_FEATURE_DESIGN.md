# DIGETHER 거점 기능 설계

기준일: 2026-11-06 · **Notion 이관 전 초안**. 시스템 작업리스트 1.1.0과 기획 공유 사양 2026-11-05 및 사용자 전달 [2026-11-06 기획 답변](PLANNING_RESPONSE_2026-11-06.md)을 반영한 기획 범위다. 11-06의 팀장 결정은 **팀 승인 전**이며 문서 반영을 구현·검증 완료로 보지 않는다. 작업리스트보다 우선하는 [사용자 결정 2026-11-05](DECISIONS.md#사용자-결정-2026-11-05)를 따른다. 전체 상태 소유와 경합·저장 계약은 [전체 시스템 설계](../SYSTEM_DESIGN.md), 용어는 [게임 기획](../GAME_DESIGN.md#용어)을 따른다. 2026-11-05 당시 출발·납부·게임 오버·저장 구현분은 자동 테스트를 통과했고 M2·연출은 미검증이다. 11-06 답변으로 달라진 규칙은 이 과거 구현 증거에 포함하지 않는다. 격리 사본 Editor 빌드와 `DIGETHER.Game` 자동 테스트 165개 실패 0까지 확인했고, 실제 다인(M2)과 BP·맵 연출은 확인하지 않았다. 하우징(S35)은 P2 후속이라 구현하지 않았다.

## 거점에서 할 일

교류·외형 변경·장비 준비·구매·납부에 강제 순서는 없다. 거점에서 공격 동작은 가능하지만 피해량은 0이다. 외형 변경 장치는 두지 않는다. MVP 치장은 상점에서만 얻으며 메인 메뉴에서는 개인 기본 외형만, 거점 메뉴에서는 그 방에서 산 치장을 착용하고 탐사 중에는 바꾸지 않는다. 착용 부위·동시 착용 수·색은 캐릭터·아트 문서, 가격은 경제 담당 확인을 기다린다(11-06 답변 13). 상점에서는 개인 재화로 사고 구매한 장비·목재는 상점 굴뚝으로 받는다. 해금 비용은 요청자의 잔고에서 차감하고 결과는 팀이 공유한다. 동시에 같은 갱도를 해금해도 호스트가 먼저 확정한 한 건만 차감한다. 해금된 목적지는 패널을 조작하는 누구나 고르고, 누군가 출발 레버 조작을 시작하면 고정하며 도중 취소하면 푼다. 패널 점유 없이 마지막에 고른 목적지를 적용한다(11-06 답변 11).

출발 레버는 누구나 당길 수 있고 준비 확인은 없다. 유지 시간 T는 1~3일차 약 3초(시험 값), 4일차 2T다. 1~3일차는 주황색 형광등·비프음과 팀원 문구 “승강기가 곧 출발합니다”, 할당량 미달 4일차는 빨간 경고등·사이렌과 레버 조작자 문구 “현재 할당량 마감일입니다!”를 띄운다. 게이지 완료 순간 구매·납부·신규 참가 접수를 닫고 열린 창을 닫으며 수동 취소를 받지 않는다. 이어서 문이 자동으로 닫히고(임시 3초) 닫히는 동안 걸어서 탈 수 있다. 문 닫힘 완료 순간 거점에서 엘리베이터 밖에 있는 참가자 전원을 사슬 소집으로 옮긴다(MVP는 암전 후 순간이동). 이 인원이 출발 인원이다. 목표 달성이 게이지 완료보다 먼저 확정되면 기존 레버·경고·마감을 취소하고 새 목표의 1일차 출발을 다시 요청한다. 같은 처리 시점이면 납부를 먼저 판정한다. 마감 뒤 납부는 차감 없이 거절한다.

구현 메모: 문 닫힘 시간 `LOBBY_DOOR_CLOSE_TIME`은 3초 임시값이다. 사슬 소집은 서버 순간이동까지이며 클라이언트 암전은 BP 이벤트 `OnChainSummoned` 연결이 필요하다. 1~3일차·4일차 경고는 `WarningKind`로 복제하며 형광등·소리 연출 BP가 필요하다.

## 정산머신 납부

여러 명이 동시에 각자의 돈자루를 들고 정산기 입구를 조준해 우클릭을 유지하면 금화를 붓는다(납부는 손에 든 돈자루의 사용 동작). 호스트가 처리한 순서로 주기마다 정수 금액을 차감·인정하며, 우클릭을 떼거나 거리를 벗어나거나 끊기거나 잔고가 바닥나거나 접수가 닫히면 본인 납부만 멈추고 확정분은 유지한다. 목표액과 달성 여부는 공개하고 공동 인정액은 외부 3색 신호기(시험 경계 50%·80%)로만 보여 준다. 정확한 누적 금액·개인 납부 상세·잔고는 다른 플레이어에게 공개하지 않으며 표시·복제·로그를 함께 검사한다. 달성 순간 신호기가 꺼지고 금괴가 우물로 떨어진 뒤 새 사이클 색으로 다시 켜진다(공통 카메라 컷신 없음). 목표를 넘는 금화는 정산기 앞 바닥에 떨어지고 누구나 E로 주워 자기 잔고에 넣는다. 새 목표에 합산하지 않으며 이미 인정된 납부의 환불은 없다.

구현 메모: 붓기는 서버 Tick에서 레버보다 먼저 처리한다. 한 주기 금액 `PAY_UNIT_AMOUNT`는 10(임시)이고 첫 차감은 누른 뒤 간격이 지난 시각이다. 누적 금액은 복제하지 않고 HUD도 신호기 단계만 보여 준다. 초과 금화는 PQ-34 안 A(목표를 채우는 데 필요한 최소 금화만 쓰고 나머지는 바닥 더미)로 시험하며 기획 확인 전 최종 규칙이 아니다. 바닥 금화는 거점 저장 확장 v2에 저장한다. 입력 에셋(IA/IMC) 지정과 신호기 HUD 연결이 필요하다.

인정 비율은 4일차 100% 확정, 1~3일차 30/50/70%는 사용자 결정 임시값이며 목표 반영액은 소수점 버림이다. 첫 목표 100·달성마다 +100은 임시값이고 정식 값은 D22다. 인정액의 절사·이월과 최소 단위·마지막 금화 분할은 D27, 인정 비율 100% 미만에서 바닥 금화 계산은 PQ-34, 마감 시점 표현(게이지 완료 대 출발)은 PQ-22다. 금액 직접 입력 방식은 쓰지 않는다. 새 게임은 개인 잔고 0원으로 시작하며, 시험 지원금 500은 개발 빌드 전용이다.

## 게임 오버와 크레딧

4일차 미달 마감 뒤 탐사가 끝나면 5일차가 되고 검은 개인 정산 화면을 거쳐 거점으로 돌아온다. 귀환 자동 저장(게임 오버 확정 포함) → 조작 복구 뒤 실패 사건(우물 범람 → 거점 침수 → 깊은 우물로 흡입)이 각자 조작을 유지한 채 진행된다(11-06 답변 08: 저장 우선, 팀 승인 전). 먼저 흡입된 사람은 기다리고 떠난 사람은 기다리지 않는다. 현재 참가자 흡입이 끝나면 전원이 함께 결과 크레딧을 본다. 빨리감기는 호스트만 조작하고 모두에게 같은 속도로 적용하며 건너뛰기·일시정지·다시 보기는 없다. 크레딧 중 방 나가기·앱 종료는 허용하고 떠난 사람 때문에 대기하거나 출발을 잠그지 않는다. 실패 사건·크레딧 중에는 구매·납부·출발·신규 참가가 불가하다. 크레딧이 끝나면 호스트가 현재 슬롯만 새 게임으로 한 번 초기화하고 같은 방의 새 거점으로 이어진다. 다른 저장 슬롯은 유지한다. 크레딧 중 끊긴 사람이 새 게임 거점에 돌아오면 정원·버전·상태 확인 후 신규 참가로 받고 시작 장비를 새 게임 기준으로 한 번만 준다. 이전 게임 기록은 결과 보관에만 남긴다(11-06 답변 17). 별도 할당량 미달 안내 화면은 11-06 답변 08에서도 보류이며 연출 세부는 D15다. 크레딧은 전체 총액 → 획득 금액(히든 포함) → 히든 슬롯 획득액 → 사망 손실액 순으로 표시한다. 각 블록은 참가 순서대로 “이름: 금액”을 나열하고 순위 없이 0원인 사람·중간 이탈자도 포함한다.

구현 메모: 흡입 시각은 서버가 우물과의 거리로 정하고, 마감까지 남은 사람은 강제로 흡입한다. 크레딧 재생은 서버 시각에 맞춰 모두 같다. 새 게임은 새 GameId를 발급하며 이전 결과는 10개까지 보관한다(임시). 크레딧 블록은 지갑의 누적 통계(획득·히든·사망 손실 순액)로 만들고 히든 수익은 크레딧에서만 공개한다. 연출 길이 `GO_*`는 모두 임시값이다. 우물 Actor 배치·크레딧 WBP·침수·흡입 연출 BP가 필요하고 크레딧 전원 음성 전환은 구현하지 않았다.

## 저장과 배치

수동 저장은 없고 자동 저장만 한다(D29 닫힘, 개발용 치트 명령은 Shipping 제외). 자동 저장 시점은 ① 탐사 정상 완료 후(일차·정산·복구·지급 완료·부활·귀환 판정 반영 뒤) ② 할당량 달성(잔고 차감·새 목표·1일차 전환·바닥 초과 금화를 한 번에) ③ 호스트가 정상 거점에서 종료할 때 ④ 5일차 실패 귀환 때다(11-06 답변 05). 시설 상태가 바뀔 때마다 저장하지 않으며 구매·해금·배치 뒤 강제 종료되면 마지막 저장 상태로 돌아가는 것을 허용한다. 탐사 중·정산 중간 상태는 저장하지 않는다. 저장 실패는 알리고 재시도하며 출발을 막지 않는다. 공통 출발 로딩 실패는 구매·납부·해금·배치와 이미 기록한 4일차 마감을 유지한 채 같은 일차 거점으로 돌아가며 일차를 소비하지 않는다. 일차 시작 자동 저장으로 되돌리던 이전 규칙은 폐기됐다. 세부는 [전체 시스템 설계](../SYSTEM_DESIGN.md#저장-기준점과-복구)를 따른다.

구현 메모: 저장 실패 재시도 간격은 10초(임시)다. 공통 로딩 실패 복귀는 메모리 기준점으로 만들었지만 실제 로딩 계층이 없어 호출 경로는 아직 없다. 저장 슬롯은 3개(임시)이며 방을 만들 때 새 게임/이어하기를 고른다(WBP 위젯 추가 필요). 11-06 답변 05에 따라 시설 거래별 저장 API `SaveHubFacilityProgress`와 호출은 이번 코드 변경에서 제거했다. 통합 빌드·실행 검증은 과거 11-05 검사와 구분한다. 일반 바닥 물품의 전체 저장·안전 위치 복구는 별도 구현·검증이 필요하다.

거점 바닥 물품은 종류·수량·위치·방향을 저장한다. 지형에 끼거나 맵 밖으로 나간 바닥 물품은 다시 불러올 때 엘리베이터 안에 복구한다(11-06 답변 05). 이는 아래 하우징 배치 전체의 유효성 복구와 구분한다.

S35 하우징은 P2 후속이다. 모든 플레이어는 상점·침대 등 이동 가능 오브젝트를 격자 없이 자유 배치·회전할 수 있다. 고정 오브젝트는 엘리베이터·정산머신·갱도 해금 머신 3종으로 확정했고(D40 닫힘), 배치 모드에서 처음부터 선택되지 않는다. 외형 변경 장치는 삭제됐다. 배치 모드는 놓을 수 없는 위치를 빨간색, 놓을 수 있는 위치를 파란색으로 표시하고 이유 문구는 띄우지 않는다. 호스트는 겹침과 엘리베이터 입구·정산머신 사용 공간·동선을 검증한다. 배치는 진행 저장 단위에 포함하고 새 게임에서는 기본값으로 초기화한다. 유효하지 않은 저장 배치는 전체를 검사한 뒤 기본 배치 전체로 되돌린다.

## 거점 콘텐츠 범위

11-06 답변 15 기준(팀 승인 전): 유적·수정 시험 목적지는 정식 갱도로 교체한다. 정식 목록·이름·비용을 이 문서에서 정하지 않는다. 제단 헌납은 쓰지 않고 침대는 회복 효과 없이 쉬기·교류용으로 둔다. 탐사에서 잃은 체력은 갱도에서 거점으로 귀환할 때 초기화한다.

## 수용 관찰 초안

1~4인에서 원격 참가자의 출발·사슬 소집, 동시 해금·동시 붓기 납부, 목표 달성과 출발 경합(같은 처리 시점 납부 우선)을 확인한다. 신호기 경계와 초과 금화 낙하·줍기를 본다. 4일차 미달 출발과 5일차 실패 사건, 호스트 빨리감기, 크레딧 중 이탈과 중복 완료 신호를 검사한다. 구매·납부·해금·배치 후 공통 로딩 실패와 정산 완료 후 재시작에서 모든 값의 일관성과 중복 지급 방지를 관찰한다. 개인 납부 내용의 전송과 표시도 검사한다. 추가로 시설 거래만으로 저장되지 않는지, 네 공식 저장 시점에서 거점 바닥 물품 종류·수량·위치·방향이 복원되는지, 유효하지 않은 바닥 물품만 엘리베이터 안으로 돌아오는지 확인한다. 목적지 최종 선택·레버 고정과 중단 해제, 크레딧 이탈자의 새 게임 신규 참가·시작 장비 1회 지급도 확인한다. 이는 실행 결과가 아니며 실제 구현 후 L1~L3/M2가 필요하다.
