# 레벨·에셋 안전

.umap·.uasset은 바이너리다. 텍스트 편집·자동 병합·임의 재생성을 하지 않는다.
같은 패키지 파일·Blueprint·데이터 에셋은 한 번에 한 작업자가 편집한다. 담당자가 정해지지 않았으면 실제 병행 작업 상태와 소스 관리 잠금을 확인한다. 레벨을 분담할 때는 OFPA 등 실제 저장 단위를 확인하고 공용 월드 설정·참조 변경은 조율한다.

## 편집

- 이동·이름 변경은 에디터에서 하고 참조와 리다이렉터를 확인한다.
- 리다이렉터 정리는 영향 에셋을 확인한 범위에서만 한다.
- 저장 전 변경 목록을 확인하고, 의도하지 않게 에디터가 재저장한 파일을 작업에 섞지 않는다.
- 스크립트로 에셋을 만들 때는 대상이 이미 있으면 덮어쓰지 않고 중단하게 한다.
- 기존 맵을 바꾸는 대신 프로젝트가 허용한 테스트 위치에 복제해 실험하면 앞 단계의 회귀 기준이 남는다. 복제본의 이름·참조·cook 포함 여부를 확인한다.
- 엔진 버전 전환·플러그인 변경·대량 재저장은 호환성과 복구 가능성을 먼저 확인한다. 원본에 바로 버전 변환을 적용하거나 이전 엔진으로 다시 열 수 있다고 가정하지 않는다.
- World Partition·OFPA는 .umap 외의 외부 액터 패키지도 변경할 수 있다. 에디터 변경 목록과 참조를 확인하여 필요한 파일을 함께 관리하고, 인코딩된 파일명만 보고 불필요한 파일로 판단하지 않는다.

## 소스 관리

- Config/Default*.ini, Source, Content, .uproject와 프로젝트 소유 Plugins의 .uplugin·Source·Content·설정은 필요한 소스 관리 대상이다. 라이선스·비밀값·배포 방식도 함께 확인한다.
- Intermediate·DerivedDataCache와 재생성 가능한 Binaries는 보통 생성물이다. 다만 소스 없는 플러그인의 배포 바이너리는 재생성할 수 없을 수 있다. Saved에는 로그·자동 저장·사용자 데이터가 있을 수 있으므로 폴더명만으로 일괄 삭제하지 않는다. 생성물을 수동 패치해 원인을 숨기지 않고, 프로젝트가 하위 폴더에 있으면 ignore 적용 깊이를 확인한다.
- Git에서 바이너리 에셋과 큰 원본을 관리할 때는 프로젝트의 LFS 규칙을 확인한다. .gitattributes에 규칙이 있다고 설치·업로드·잠금이 검증된 것은 아니다. 대형 에셋 추가 전 실제 필터와 원격 지원을 확인한다. 다른 소스 관리 도구는 해당 저장·잠금 정책을 따른다.
- LFS 포인터만 있는 상태를 실제 에셋 확보로 보고하지 않는다.
- 외부 에셋은 원본 변경을 최소화하고 라이선스와 자체 통합 코드를 구분한다.

## 맵과 패키징

- 개발용 맵을 출시 cook에서 제외했다면, 출시 구성 빌드 성공이 플레이 가능한 패키지를 뜻하지 않는다. 플레이테스트용 구성을 따로 두고 어느 맵을 포함하는지 적는다.
- 맵 목록·전환 경로·기본 맵을 바꾸면 대상 패키지에서 진입·전환을 확인한다. 네트워크 프로젝트에서는 다인 전환도 확인한다.
- World Partition 같은 맵별 설정은 맵을 만들 때마다 확인한다. soft reference·동적 로드 에셋도 대상 패키지에 포함되어 로드되는지 확인한다.

## 기술 근거

2026-10-10에 Epic의 [One File Per Actor](https://dev.epicgames.com/documentation/en-us/unreal-engine/one-file-per-actor-in-unreal-engine)와 [Plugins](https://dev.epicgames.com/documentation/en-us/unreal-engine/plugins-in-unreal-engine)를 확인했다(열람 화면 UE 5.8). 외부 액터 파일·소스 없는 플러그인의 바이너리 설명을 참고했으며, 프로젝트의 저장·잠금·cook 결과는 별도 검증한다.
