# 모델·재질 제작과 검수

제작 방식과 스타일·예산은 프로젝트 프로필과 사용자 요청을 따른다. 원본 개선 요청을 새 생성으로 바꾸거나 특정 생성 서비스를 임의로 대체하지 않는다.

## 원본과 가공

- 참조, 용도, 단위·치수·피벗·축, 모듈 조립 여부, 리깅 여부, 목표 플랫폼·카메라를 확인한다.
- 원본과 편집본을 분리하고 보관·소스 관리 방식은 [에셋·데이터 정책](../ai/ASSET_AND_DATA.md)을 따른다.
- 형태·UV·노멀·재질 슬롯·버텍스 컬러를 확인한다. 기존 데이터를 무조건 초기화하지 않고 리깅 모델의 본·웨이트·변형을 보존한다.
- AO·노멀·PBR 맵은 생성 방식과 한계를 기록한다. 색의 명암이나 임의 노이즈를 실제 형상 베이크로 보고하지 않는다. 베이크 타깃·UV·여백·투영 범위와 결과를 검수한다.
- AO·Roughness·Metallic 등의 채널 패킹은 대상 Unreal 머티리얼이 실제로 읽는 채널과 색 공간을 확인한다. 원본 도구나 다른 엔진의 연결 규칙을 그대로 적용하지 않는다.
- LOD·충돌·Nanite·텍스처 해상도와 압축은 프로젝트의 실제 지원·성능 목표로 선택한다. 고정 개수나 일괄 필수 기능으로 두지 않는다.

## Unreal 통합과 증거

변경은 [에셋 안전](ASSET_SAFETY.md)의 에디터·검증된 도구 경로를 사용한다. 임포트 스케일, 참조, 머티리얼·텍스처, 충돌, 필요한 LOD와 cook 포함 여부를 확인한다.

같은 노출·광원·프레이밍에서 원본과 결과를 비교하고, 게임 거리·근거리·뒤쪽·필요한 LOD를 관찰한다. 반복 키트는 인접 배치의 이음도 확인한다. 빈 이미지나 정지 프리뷰를 실제 플레이·성능 검증으로 보고하지 않는다.

결과에는 원본·편집본·임포트 에셋 경로, 권리·도구 버전, 치수·비용 지표, 비교 이미지, 실제 검사·남은 항목을 남긴다. 요청한 제작 범위 완료와 게임 배포 검증을 구분한다.
