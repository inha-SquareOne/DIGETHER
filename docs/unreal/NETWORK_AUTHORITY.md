# 네트워크 권위

게임 결과가 사람마다 달라지면 안 되는 상태는 서버가 소유한다.
클라이언트는 입력을 요청하고 확정 상태를 받아 표현한다. 모듈을 나눴다고 서버 실행이 보장되지는 않는다.

| 서버 판정 | 클라이언트 표현 |
|---|---|
| 획득·배치·점유·거리 같은 상호작용의 성사 여부 | 입력·카메라·로컬 UI |
| 공유 상태(진행도, 열림/닫힘, 점수)의 값 | 확정 값에 따른 시각·오디오 적용 |
| 자원(체력·배터리·탄약)의 증감 | 게이지·조명 표현 |
| AI 판단, 피해, 상태 전환 | 화면 효과·후처리 |
| 무작위 생성 결과, 종료·승패 | 결과 화면 |

서버 권위를 채택한 멀티플레이의 기준이다. 싱글플레이나 다른 동기화 구조는 프로젝트 층에 적용 범위·대체 계약을 적는다.
프로젝트 층은 이 표를 자기 게임의 상태 목록으로 구체화하고 상태별 소유자, 수신 대상, 요청 경로, 초기화·전환·종료 시점을 정한다. 클라이언트 예측을 쓰면 임시 표현과 서버 확정·보정 상태를 구분한다.

## 규칙

- RPC의 실행 경로·소유 연결과 게임 규칙상의 권한은 따로 검증한다. 클라이언트 요청은 소유한 복제 액터·컴포넌트의 유효한 경로를 거치며, 서버는 대상·거리·현재 상태·값 범위·빈도·재사용·중복 요청을 확인한다. 클라이언트가 보낸 값은 요청이지 사실이 아니다.
- Blueprint와 C++ 모두 프로젝트가 정한 서버 요청 경로를 사용한다. 복제 상태를 클라이언트에서 직접 바꿔 서버 판정을 대체하지 않는다.
- 지속 상태를 일회성 멀티캐스트만으로 전달하지 않는다. 복제 상태를 원본으로 두고 표현은 그 값에서 적용하면 후입·재접속이 같은 경로로 맞는다. 멀티캐스트는 놓쳐도 되는 일회성 사건에만 쓴다.
- 표현 적용은 재호출해도 부작용이 중복되지 않는 공통 경로로 모은다. C++ 서버의 값 대입이 OnRep를 자동 호출한다고 가정하지 않는다. 리슨 서버의 값 변경, 클라이언트 OnRep, 표현 객체가 준비된 초기화·재생성 시점에 현재 상태를 적용한다. Blueprint Set의 RepNotify 동작은 C++과 다르므로 이중 적용을 확인한다.
- 초기 상태를 OnRep에만 맡기지 않는다. 값이 기본값과 같거나 UI·참조 객체가 늦게 준비되는 경우도 검사한다. BeginPlay 한 번만으로 모든 의존 객체의 준비를 보장하지 않고, 필요한 객체가 준비되면 현재 상태를 다시 적용한다.
- 호스트(리슨 서버)도 클라이언트와 같은 적용 함수를 거친다. 호스트에서만 되는 것을 통과로 보지 않고 원격 클라이언트 결과를 따로 확인한다.
- 큰 상태는 비용에 따라 차이 적용을 검토하되, 초기 수신·재동기화에서 완전한 현재 상태를 복원할 수 있어야 한다.
- 서로 다른 프로퍼티의 OnRep나 액터 간 RPC 도착 순서에 의존하지 않는다. 함께 해석할 상태의 묶음·버전·준비 조건을 정하고 누락·순서 변화·지연에서 검증한다.
- Reliable RPC도 전역 순서나 무제한 처리량을 보장하지 않는다. 반복 입력의 빈도·크기를 제한하고, 지속 상태를 매 프레임 Reliable RPC로 중계하지 않는다.
- 소유자·팀 전용 정보는 전달 대상부터 제한한다. 모든 클라이언트에 복제한 뒤 UI에서 숨기는 것을 정보 보호로 보지 않는다. 전용 서버의 판정은 UI·오디오 객체 존재에 의존하지 않게 한다.
- 음성처럼 게임 상태와 연결된 외부 서비스는 종료·재시작 때 잔류를 검사한다.

## 정책은 프로젝트가 정한다

호스트 이탈 시 종료인지 승계인지, 비호스트 이탈과 인원 축소, 재접속 허용 여부는 프로젝트 결정이다. 정해지지 않았으면 임의로 구현하지 않는다.
검증은 [멀티플레이 테스트](../ai/MULTIPLAYER_TEST.md)를 따른다.

## 기술 근거

2026-10-10에 Epic의 [프로퍼티 복제와 RepNotify](https://dev.epicgames.com/documentation/en-us/unreal-engine/replicate-actor-properties-in-unreal-engine), [RPC](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-procedure-calls-in-unreal-engine), [복제 실행 순서](https://dev.epicgames.com/documentation/en-us/unreal-engine/replicated-object-execution-order-in-unreal-engine)를 확인했다(열람 화면 UE 5.8). 적용 중인 복제 방식·버전과 프로젝트 초기화 순서의 실제 동작은 별도 다인 검증이 필요하다.
