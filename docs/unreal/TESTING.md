# Unreal 테스트

무엇을 먼저 테스트로 쓰는지는 [TDD](../ai/TDD.md)가 기준이다. 이 문서는 Unreal에서 쓰고 돌리는 방법이다.
이 프로젝트의 UE 5.8.2 Windows 테스트 실행은 미검증이다. 아래는 공식 문서를 참고한 템플릿이며, 프로젝트의 실제 엔진·플러그인·플랫폼·타깃에서 지원 여부와 종료 동작을 확인한 뒤 사용한다.

## 종류

| 종류 | 쓰는 곳 | 수단 |
|---|---|---|
| 단위 | 월드가 필요 없는 규칙·계산·상태 전이·생성기·저장 형식 | Automation Test (`IMPLEMENT_SIMPLE_AUTOMATION_TEST`, Spec) |
| 월드 통합 | 액터·컴포넌트·서브시스템이 엮인 동작 | 테스트 월드를 만드는 Automation Test, Functional Test 맵 |
| 다중 프로세스 스모크 | 복제·RPC·세션 흐름 | 호스트와 클라이언트를 별도 프로세스로 띄우는 스크립트 + 로그 판정 |
| 에셋·데이터 검사 | 배선, 참조, 표 무결성 | 에디터 파이썬 검사 스크립트, 데이터 검증 |

TDD의 Red-Green 순환은 단위 테스트에서 가장 빠르다. 규칙을 월드와 떼어 두면 대부분이 단위로 내려온다.

## 테스트 모듈

- 전용 테스트 모듈은 분리 방법 중 하나다. 기존 테스트 배치와 제품의 테스트 의존을 확인한 뒤 전용 모듈 또는 적절한 컴파일 가드를 선택한다. 출시 구성에서 빠져야 할 테스트는 모듈 타입·타깃·가드로 제외하고 Shipping 빌드에서 확인한다.
- 제품 모듈이 테스트 모듈에 의존하지 않게 한다.
- 테스트 이름은 프로젝트 접두사로 시작하는 계층 이름으로 짓는다(`<접두사>.<영역>.<동작>`). 접두사로 전체를, 영역으로 일부를 골라 돌릴 수 있다.
- 테스트 플래그는 테스트별 실행 문맥(에디터·게임 등)과 필터에 맞춘다. 모든 테스트에 같은 문맥을 강제하지 않는다. 필요한 모듈·플러그인이 실제 로드되고 대상 테스트가 발견되는지 먼저 확인한다.

## 명령줄 실행

공식 실행 안내의 `Automation RunTest …;Quit`와 보고서 인자를 바탕으로 한 Windows 명령 형식이다. 아래 블록 자체는 실행 스크립트가 아니며, 자리표시자를 실제 경로·필터로 바꾸고 사용하는 셸의 실행 문법으로 호출한다.

```text
"<엔진 실행 파일 전체 경로>" "<프로젝트.uproject 전체 경로>" -unattended -ExecCmds="Automation RunTest <접두사>;Quit" -ReportExportPath="<이번 실행의 보고서 폴더>" -abslog="<이번 실행의 로그 파일>"
```

다른 종료 방식을 쓰는 프로젝트는 실제 엔진에서 지원과 완료 후 종료를 확인한 명령을 프로젝트 층에 남긴다. 여기서는 검증하지 않은 종료 옵션을 추가로 혼합하지 않는다.

- 엔진 실행 파일 경로와 .uproject는 실제 위치를 확인해 넣는다. 추측한 경로로 스크립트를 만들지 않는다.
- 판정은 이번 실행의 JSON 보고서(프로젝트 엔진에서 파일명·스키마 확인), 로그와 프로세스 종료 코드로 한다. 성공·실패·경고·미실행 수와 테스트 이름이 기대와 맞는지 확인한다.
- 선택·실행된 테스트가 0개이거나 보고서가 누락·불완전하면 통과로 처리하지 않는다. UE 5.8.2의 0개 선택 종료 코드와 `Automation AllowZeroTestResults` 동작은 여기서 미검증이며, 필요하면 해당 엔진 소스·실행 로그로 확인한다.
- 시작·완료 시각, 최대 대기 시간, 크래시·타임아웃 판정을 정한다. 종료 뒤 보고서가 완성됐는지 확인하고, 오래된 보고서를 재사용하지 않는다. 작은 알려진 통과·실패 사례로 실행기 자체의 판정도 확인한다.
- 엔진 초기화 중 나오는 기존 경고·오류 로그와 프로젝트 테스트 결과를 구분해 적는다. 로그 전체가 무오류라고 뭉뚱그리지 않는다.
- `-nullrhi`·`-nosound`는 그래픽·오디오가 불필요하고 해당 테스트가 지원할 때만 추가한다. 렌더링·오디오·실제 입력 검증은 그 기능을 켠 실행으로 확인한다.

## 다중 프로세스 스모크

- 같은 빌드로 [M등급 구성](../ai/MULTIPLAYER_TEST.md)에 맞춰 리슨 또는 전용 서버와 클라이언트를 띄운다. 포트·계정·실행 인자를 구분하고 프로세스별 로그·PID·시작 시각을 남긴다.
- 스모크가 이동·상태를 준비용으로 주입한다면 그 사실을 결과에 적는다. 사람의 플레이 검증을 대신하지 않는다.
- 입력을 액션 주입으로 검증한 것과 실제 키보드·마우스 입력은 구분한다.
- 경합은 [멀티플레이 테스트](../ai/MULTIPLAYER_TEST.md)의 반복 기준에 따라 검사하고 횟수·실패율을 적는다.
- 성공·실패·타임아웃 후 이번 실행이 시작한 프로세스만 식별해 정리한다. 기존 에디터·다른 테스트 세션을 프로세스 이름만으로 종료하지 않는다.

## 테스트하기 좋은 구조

- 규칙은 UObject·월드 없이 호출할 수 있는 함수나 구조체로 둔다. 액터는 결과를 적용만 한다.
- 시간·난수는 인자로 받는다. 생성기는 시드와 버전을 결과와 함께 남겨 재현할 수 있게 한다.
- 저장 형식은 바이트·문자열 수준에서 읽고 쓰는 함수로 분리해 파일 없이 검사한다.
- 서버 판정은 "요청과 현재 상태를 받아 허용 여부와 새 상태를 돌려주는" 형태로 빼면 RPC 없이 검사된다.

## 버그를 고칠 때

1. 실패 조건과 원인을 확인한다. 자동화에 적합하면 재현 테스트를 쓰고 수정 전 실패를 확인한다. 시각·에셋·문서 변경 등 예외는 [TDD 범위](../ai/TDD.md)를 따른다.
2. 확인한 원인 지점을 수정한다.
3. 재현 조건과 관련 회귀 검사를 실행한다. 영향 범위·새 실패·남은 위험이 있을 때 전체 검사로 확대하고 불필요하게 반복하지 않는다.
4. 다인에서만 재현되면 스모크 시나리오에 추가하고, 원인이 순수 규칙이면 단위 테스트로 내려 고정한다.

## 기술 근거와 미검증 범위

2026-10-10에 Epic의 [Run Automation Tests](https://dev.epicgames.com/documentation/en-us/unreal-engine/run-automation-tests-in-unreal-engine)를 확인했다(열람 화면 UE 5.8). 명령 필터·종료 예시와 JSON 보고서 안내를 참고했다. 특정 패치 버전의 실행 파일·매크로·플래그·보고서 스키마와 이 템플릿의 셸별 실행 결과는 검증하지 않았다. 이 폴더에는 .uproject·테스트 모듈·실행 스크립트가 포함되어 있지 않다.
