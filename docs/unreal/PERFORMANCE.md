# 성능 조사와 변경

최적화는 관찰한 병목과 프로젝트 예산으로 판단한다. 엔진 기능이나 코딩 패턴만 보고 프레임·서버 틱·대역폭 목표 달성을 주장하지 않는다.

1. 실제 엔진·플러그인·빌드 타깃·구성·장치·맵·인원·렌더링 설정과 측정 구간을 고정한다. 에디터와 패키지, 같은 PC 다중 프로세스와 분리 장치 결과를 구분한다.
2. 프로젝트에서 지원하는 Unreal Insights·프로파일러·통계의 실제 사용법을 확인한다. 명령·트레이스 옵션은 설치된 버전의 공식 자료나 도움말로 확인하며 존재를 추측하지 않는다.
3. 워밍업, 반복 수, 측정 단위, 대표값과 최악 구간을 정한다. 게임 스레드·렌더 스레드·GPU·메모리·IO·네트워크 중 관찰한 원인과 아직 추정인 원인을 분리한다.
4. 호출 빈도·객체 수·메시지 크기·대상 수를 근거로 비용을 설명한다. 풀링·캐싱·비동기화·복제 주기 조정은 측정 이득과 수명·정합성 복잡도를 비교한다.
5. 허용된 범위에서 한 원인을 바꾸고 같은 조건으로 전후를 측정한다. 기능·권위·저장 호환 회귀도 확인한다.

성능 분석 역할은 근거와 수정 후보를 넘기고, 구현 역할이 승인된 코드 범위를 고친다. 측정 실행과 결과 판정은 [검증](../ai/VERIFICATION.md), 네트워크 비교 조건은 [멀티플레이 테스트](../ai/MULTIPLAYER_TEST.md)를 따른다. 캡처가 없으면 개선량을 추정 또는 미검증으로 남긴다.
