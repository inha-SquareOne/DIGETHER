# DIGETHER 기술 구조 초안

이 문서는 기술 구조의 요약이다. 아래 계약의 일부는 `Source/DIGETHER/Game/`에 구현돼 있고 일부는 제안 단계다. 무엇이 구현·검증됐는지는 [구현 현황](design/IMPLEMENTATION_STATUS.md)에서 확인하며, 이 문서의 서술만으로 구현·검증 완료로 읽지 않는다. `Prototype/`의 [그레이박스 구현](prototype/PROTOTYPE.md)은 초기 시험용이며 정식 구현과 구분한다.

기준일: 2026-10-28(설계 계약) · 현황 서술은 2026-11-10 코드 대조로 정정. [전체 시스템 설계](SYSTEM_DESIGN.md)는 제공된 최신 작업 목록에 맞춘 게임 상태·S01~S35 소유자·Unreal 배치 후보·데이터 인계·검증의 통합 기준이다. [개발반 구현 설계](design/DEVELOPMENT_SYSTEM_DESIGN.md)는 요청 검증·거래·복제·저장 경계를 정리한다. 엔진 지원 근거와 적용 후보는 [Unreal 기능 안내](design/UNREAL_FEATURE_COVERAGE.md)를 따른다.

2026-11-06 보정: 사용자 전달 [기획 답변](planning/PLANNING_RESPONSE_2026-11-06.md)의 요구 변경을 [시스템 계약](SYSTEM_DESIGN.md#2026-11-06-기획-답변-반영-범위)에 반영했다. 대부분 기획 팀장 결정·팀 승인 전이며, 아래 변경은 구현·검증 완료를 뜻하지 않는다.

호스트가 게임·기간·런의 상태를 판정한다. 입력/표현, 세션, 런 흐름, 지형, 생존, 아이템, 엘리베이터, 경제, AI, 음성, 저장을 책임별로 분리하고 대상의 소유자만 해당 상태를 확정한다. 요청은 소유 연결의 Server RPC로 받아 호스트가 현재 상태를 검사하고 같은 실행 안에서 반영하며, 아이템 인스턴스·게임·런·사망 ID와 지형 revision만 유지한다. 출시 방향은 Steam 판매다([2026-10-29 보정](SYSTEM_DESIGN.md#2026-10-29-보정-steam-판매-기준과-요청-처리-단순화)). 개인 지갑·납부·히든 상세는 다른 클라이언트에 전달하지 않고 공용 표시를 통한 정확한 개인 값의 역산을 검토하되 감속·장비·무게 단계로 짐작하는 것은 기획 의도다. 호스트 자신의 메모리에 대한 비밀 보장은 별도 정책이다.

월드 전환 시 장부와 인스턴스가 자동 생존한다고 가정하지 않는다. 신규 참가는 정상 거점 준비 상태에서만 받고 출발 게이지 완료~결과 크레딧 동안 막는다. 수락은 호스트의 요청 수락 처리 순간이며, 게이지 완료 전 수락·이후 참가 완료는 빈자리에서 관전 합류한다(MVP 관전 접속 불가 시 임시 거절). 거점에서 나간 사람은 캐릭터를 제거하고 장비를 바닥에 남긴다. 문 닫힘 이후 로딩 중 끊겨도 출발 인원·캐릭터·자리를 유지하고 기존 캐릭터에 재접속하며, 생존·실종은 종료 시 위치로 판정한다. 크레딧 중 끊겼다가 새 게임 거점에 오면 신규 참가로 검사하고 새 게임 초기 지급을 한 번만 한다(답변 16·17·20, 팀 승인 전). 같은 ID가 다시 들어오면 이전 접속을 끊고 새 접속을 받는다(사용자 결정 2026-11-05).

저장은 수동 저장 없이 탐사 정상 종료·목표 달성·호스트 정상 거점 종료·5일차 실패 귀환의 네 시점에만 한다. 시설 변경마다 저장하지 않으며 거점 바닥 물품의 종류·수량·위치·방향도 기록한다. 유효하지 않은 복원 위치는 엘리베이터 안으로 옮긴다(답변 05). 탐사 중·정산 중간 상태는 저장하지 않고, 탐사 중 호스트 종료는 마지막 유효 저장으로 돌아가며 별도 악용 대책을 두지 않는다(18). 공통 출발 로딩 실패는 확정된 준비·4일차 마감을 유지한 채 같은 일차 거점으로 돌아가며 일차 시작 저장으로 되돌리지 않는다. 저장은 엔진 SaveGame 기반으로 호스트 PC에 구현돼 있으며(`Game/Save/`), Steam Cloud 등 플랫폼 저장 연동은 미결이다.

갱도는 허용된 3D 흙 볼륨을 실제로 깎는 밀도 지형 방식이다(2026-10-28 결정, [굴착 구현 설계](design/EXCAVATION_IMPLEMENTATION.md)). 구현은 프로토타입 계열과 담당 구현 계열([통합 설계](design/DAIN_EXCAVATION_INTEGRATION.md)) 둘이 있고 어느 쪽을 제품 기준으로 삼을지는 결정 대기다. 답변 07·12 기준으로 갱도↔던전은 로딩 없는 이동을 목표로 하고, 던전 지정 벽 파괴는 플레이어·몬스터 모두 레벨 디자이너 결정 전 보류한다. 굴착 주체와 관계없이 천장을 붕괴·보강 대상으로 삼으며, 지지 땅이 사라진 설치 장비는 파괴하지 않고 떨어뜨려 다시 줍게 한다(10·12, 팀 승인 전). 넓은 갱도로 확장하는 방식은 충돌·다인 동기화·AI 경로·성능을 확인한 뒤 정한다. 아이템의 낙하와 플레이어를 막는 물리 충돌 여부는 별도 계약으로 검증한다. 전투 전용 무기는 현 범위 밖이나 장비 공격·팀킬은 포함한다. 구체 클래스·플러그인·서버 이동 방식은 구현과 검증 전 제안이다.

개발 우선순위와 미정은 [기획](GAME_DESIGN.md)과 [결정 목록](planning/DECISIONS.md), 적용 검사는 [검증 계획](verification/VERIFICATION_PLAN.md)을 따른다. 이 설계 문서 작성은 게임 기능의 빌드·플레이·멀티플레이 검증을 의미하지 않는다.
