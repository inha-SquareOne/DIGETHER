# DIGETHER 기술 구조 초안

`prototype` 브랜치에 이 설계의 일부를 시험하는 [그레이박스 구현](prototype/PROTOTYPE.md)이 추가됐다. 아래의 완제품 계약과 프로토타입의 실제 구현·검증 범위는 구분한다.

기준일: 2026-10-28 · **설계 제안, 미구현**. [전체 시스템 설계](SYSTEM_DESIGN.md)는 제공된 최신 작업 목록에 맞춘 게임 상태·S01~S35 소유자·Unreal 배치 후보·데이터 인계·검증의 통합 기준이다. [개발반 구현 설계](design/DEVELOPMENT_SYSTEM_DESIGN.md)는 요청 검증·거래·복제·저장 경계를 정리한다. 엔진 지원 근거와 적용 후보는 [Unreal 기능 안내](design/UNREAL_FEATURE_COVERAGE.md)를 따른다.

호스트가 게임·기간·런의 상태를 판정한다. 입력/표현, 세션, 런 흐름, 지형, 생존, 아이템, 엘리베이터, 경제, AI, 음성, 저장을 책임별로 분리하고 대상의 소유자만 해당 상태를 확정한다. 요청은 소유 연결의 Server RPC로 받아 호스트가 현재 상태를 검사하고 같은 실행 안에서 반영하며, 아이템 인스턴스·게임·런·사망 ID와 지형 revision만 유지한다. 출시 방향은 Steam 판매다([2026-10-29 보정](SYSTEM_DESIGN.md#2026-10-29-보정-steam-판매-기준과-요청-처리-단순화)). 개인 지갑·납부·히든 상세는 다른 클라이언트에 전달하지 않고 공용 표시를 통한 정확한 개인 값의 역산을 검토하되 감속·장비·무게 단계로 짐작하는 것은 기획 의도다. 호스트 자신의 메모리에 대한 비밀 보장은 별도 정책이다.

월드 전환 시 장부와 인스턴스가 자동 생존한다고 가정하지 않는다. 탐사 중 신규 참가를 거절하고 기존 ID 재접속은 기존 캐릭터·자산·최신 상태에 연결한다. 일차 시작 자동 저장을 출발 실패 복원 기준으로 사용하며 정산 중간 상태를 저장하지 않는다. 저장 기술·플랫폼 제공자와 수동 저장 허용 상태는 미결이다.

갱도는 허용된 3D 흙 볼륨을 실제로 깎는 밀도 지형 방식이다(2026-10-28 결정, [굴착 구현 설계](design/EXCAVATION_IMPLEMENTATION.md)). 던전 지정 벽 파괴는 별도 규칙이다. 넓은 갱도로 확장하는 방식은 충돌·다인 동기화·AI 경로·성능을 확인한 뒤 정한다. 아이템은 물리 충돌이 없는 현재 규칙을 따른다. 전투 전용 무기는 현 범위 밖이나 장비 공격·팀킬은 포함한다. 구체 클래스·플러그인·서버 이동 방식은 구현과 검증 전 제안이다.

개발 우선순위와 미정은 [기획](GAME_DESIGN.md)과 [결정 목록](planning/DECISIONS.md), 적용 검사는 [검증 계획](verification/VERIFICATION_PLAN.md)을 따른다. 이 설계 문서 작성은 게임 기능의 빌드·플레이·멀티플레이 검증을 의미하지 않는다.
