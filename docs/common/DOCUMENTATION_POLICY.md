# 문서 유지

지침과 현황이 여러 문서에 복제되면 한쪽만 낡고, 에이전트는 낡은 쪽을 사실로 읽는다. 내용마다 두는 곳을 하나로 정한다.

## 어디에 두는가

| 내용 | 두는 곳 | 고치는 시점 |
|---|---|---|
| 매 세션의 시작·필수 정책 요약 | 루트 AGENTS.md | 정책 진입점이 바뀔 때 |
| AI 실행·승인·엔진 기능 우선·원인 해결의 상세 정책 | docs/ai/EXECUTION_POLICY.md | 사용자 결정이 바뀔 때 |
| 역할별 사용 순서·작업 전달 안내 | docs/guides/ | 해당 파트의 작업 흐름이 바뀔 때 |
| 구현·검증 현황과 남은 기능 | 기능 현황 문서 하나 | 기능 상태가 바뀐 작업 안에서 |
| 기능의 계약·사용법·한계 | 기능별 기술 문서 | 그 기능을 바꾼 작업 안에서 |
| 작업 결과·검증 증거·판단 근거 | `.claude/docs/{날짜}/{제목}.md` | 과거 결과는 보존하고 정정은 연결된 추가 기록으로 남긴다 |
| 타인에게 전달할 행동·재개 조건 | `.claude/docs/{날짜}/handover/{제목}.md` | 전달·담당 전환·상태 변경 시 |
| 작업·전달 문서 목록과 한 줄 설명 | `.claude/docs/pointer.md` | 문서 생성·이동·상태 변경 시 |
| 미결 결정 | 결정 대기 목록 | 결정·해소 시 |
| 기술·작업 상세 기준 | docs/ai/·docs/unreal/ | 채택한 프로젝트 기준에 맞춰 관련 참조를 함께 수정 |

## 지침 문서 작성 기준

- 진입 지침(AGENTS.md)은 가볍게 둔다. 도구별 로드 조건과 연결 방법은 [도구 관리](INTEGRATION.md)를 따른다. 구현 이력을 쌓지 않고, 저장소를 읽으면 알 수 있는 내용도 적지 않는다. 읽어서는 알기 어려운 함정에 분량을 쓴다.
- 같은 사실은 한 곳에만 쓰고 나머지는 링크한다.
- 규칙에는 이유를 붙인다. 최악의 사고를 막는 것이 아니면 금지 대신 판단 기준을 적는다.
- 서로 충돌하는 지시를 남기지 않는다. 새 규칙을 넣을 때 기존 규칙과 부딪히는지 검색한다.
- 필요할 때만 쓰는 절차(검증 등급, 다인 테스트, 인수인계 템플릿, 커밋)는 별도 문서나 스킬에 두고 진입 지침에서는 링크만 한다.
- 완료·승인·보고의 상세 기준은 실행 정책에 두고 진입 지침에서 연결한다.
- "깊이 생각해" 같은 문구를 넣지 않는다. 사고량은 도구 설정으로 조절한다.
- 예시는 꼭 필요할 때만 넣는다. 예시는 그 모양대로 따라 하게 만든다.

## 유지 절차

- 새 문서를 만들면 문서 지도에 올린다. 어디에서도 링크되지 않는 문서를 남기지 않는다.
- 문서를 고친 뒤 로컬 링크·앵커·대소문자와 문서 지도를 검사한다. 코드 블록 속 도입용 자리표시자와 실제 링크를 구분한다. 외부 출처는 제목·URL·대상 버전·확인일과 검증 한계를 적는다.
- 작업 전후의 변경을 비교하고 기존 편집·파일 형식·인코딩·줄바꿈을 보존한다. 문서 폴더만 있으면 기준 사본이나 해시를 사용한다.
- 프로젝트 예외에는 대상 규칙, 이유, 결정 근거·주체, 적용 범위, 재검토 조건을 적는다. 제안이나 미결 항목을 채택된 정책처럼 쓰지 않는다.
- 날짜별 기록의 "미커밋"·"다음 작업" 같은 문구는 그날의 상태다. 현재 상태로 읽지 않으며, 낡았다고 고치지도 않는다.
- 설계 문서의 완료 표시는 설계 작성 상태다. 구현·검증 완료와 구분해 읽는다.
- 진입 지침이 길어지면 현황·이력이 다시 섞였는지 먼저 본다.
- 비밀값·개인정보가 기록에 들어갔다면 기록 불변 원칙을 이유로 남겨두지 않는다. 노출 확산을 멈추고 승인된 범위에서 가린 뒤 값 자체를 제외한 처리 이력을 남긴다([에셋·데이터 정책](../ai/ASSET_AND_DATA.md)).
- 기준 변경은 관련 현황과 검증 기록에 범위·한계를 남긴다. 같은 내용을 여러 요약 문서에 반복하지 않는다.

## 근거 통합과 정합성 점검

- 새 근거를 반영할 때 기존 주제 문서부터 찾아 갱신한다. 같은 결론의 요약 문서를 추가하기보다 원본·적용 조건·관련 문서를 연결한다. 입력 자료의 주장과 프로젝트에서 채택한 결정을 구분한다.
- 새 근거가 기존 문장과 충돌하면 두 근거의 시점·적용 범위·승인 상태를 비교한다. 해결되지 않은 차이는 미결로 남기며 조용히 한쪽을 사실로 확정하지 않는다. 기획 원본 변경 권한은 [문서 운영](../project/DOCUMENTATION.md)을 따른다.
- 관련 문서를 변경하거나 문서 점검을 요청받으면 깨진 링크뿐 아니라 오래된 주장, 서로 모순되는 규칙, 지도나 다른 문서에서 도달할 수 없는 새 문서를 확인한다. 범위 밖 문제는 근거와 함께 보고하고 무관한 일괄 개편은 하지 않는다.
- 반복해서 쓸 결론은 해당 기준 문서에, 조사 과정과 그날의 검증 결과는 작업 기록에 남긴다. 문서 지도는 주제 탐색에, 작업 기록 목록은 작업 이력 탐색에 사용한다. 별도 위키·색인·로그를 중복 생성하지 않는다.

## 공용 스킬·역할과 공유 기록

공용 절차의 자세한 실행 단계는 [원본 스킬](../README.md#스킬), 역할 계약은 [역할 목록](AGENTS_OVERVIEW.md)에 둔다. 도구별 발견 파일은 원본의 복사본이며 자동 생성되지 않는다. [동기화 절차](INTEGRATION.md)에 따라 원본을 고칠 때 복사본도 같은 작업에서 맞춘다. 공통 규칙이 바뀌면 관련 원본과 복사본을 함께 확인한다.

공유 문서는 개인 대화·로컬 비공개 로그를 읽어야만 이해할 수 있게 쓰지 않는다. [문맥 관리](../ai/CONTEXT_HYGIENE.md)에 따라 필요한 사실·근거·미결 사항만 정리하고 민감정보를 제외한다. 외부 자료의 고지는 [라이선스 안내](SOURCES.md)와 provenance/에서 유지하고 프로젝트의 현재 작업 상태와 섞지 않는다.

## 사람·AI·기술 문서 배치

사람이 먼저 읽는 핵심 문서(기획서·시스템 기획서·아키텍처·로드맵·컨벤션·온보딩)는 docs/ 바로 아래에, 상세 문서는 종류별 하위 폴더(planning·design·decisions·prototype·verification·tools·project)에 둔다. 역할별 사람용 가이드는 docs/guides/에, 문서 체계·도구 관리·역할·출처 설명은 docs/common/에, 프로젝트 양식은 docs/templates/에 둔다. 폴더별 용도는 [문서 지도](DOCUMENT_MAP.md#문서-배치)를 따른다. AI 실행 규칙은 docs/ai/, Unreal 기술 기준은 docs/unreal/에 둔다. 루트 README.md는 사람이 읽는 진입 문서, AGENTS.md는 AI 도구가 읽는 진입 지침이다. 역할 지침 원본은 docs/ai/roles/에 두고 도구별 발견 파일은 그 복사본으로 맞춘다. 스킬·진입 파일·설정·법적 고지는 [문서 지도](DOCUMENT_MAP.md)의 배치 예외를 따른다.

프로젝트 문서는 지도에 적힌 독자·목적·필수 항목·갱신 계기·책임·연결·완료 기준으로 관리한다. 작은 프로젝트는 같은 내용을 여러 파일로 복제하지 않고 한 안내의 절로 합친다. 양식 원본과 프로젝트의 채택된 값은 구분한다.
