# 환경 준비와 첫 실행

상태: 절차 준비, 엔진 실행 미검증. 환경 값의 원본은 [프로필](PROJECT_PROFILE.md)이다.

## 지금 할 수 있는 준비

1. 팀이 부여한 GitHub 저장소 읽기/쓰기 권한을 확인하고 저장소를 복제한다. 이미 복제되어 있으면 새 복제 없이 작업 트리 상태를 확인한다.
2. README → 프로젝트 문서 지도 → Notion 기획 원본/이관 전 초안 → 작업 경계를 읽는다.
3. 팀 기준 Unreal Engine 5.8.2의 설치 방식과 컴파일 도구를 확정한다. 다른 버전에서 프로젝트를 열어 자동 변환하지 않는다.
4. LFS 채택 시 최초 에셋 커밋 전에 추적 패턴·용량 정책을 합의하고 설치·복원을 확인한다.

아래는 소스 확보 절차이며 이번 작업에서 실행한 clone은 아니다.

```powershell
git clone https://github.com/inha-SquareOne/DIGETHER.git
cd DIGETHER
git status --short
git remote -v
```

## 프로젝트 생성 후 채울 첫 실행 절차

| 단계 | 필요한 확정값 | 성공 관찰 | 실패 시 확인 |
|---|---|---|---|
| 의존 복원 | 엔진 배포·SDK·플러그인 버전 | 팀 기준과 실제 버전 일치 | 임의 업데이트 대신 버전 차이 기록 |
| 에셋 복원 | LFS 추적·권한 | 포인터가 아닌 실제 에셋 확보 | LFS 상태·객체 다운로드 오류 |
| 프로젝트 열기 | 실제 `.uproject` 경로 | Editor가 오류 없이 로드 | 엔진 로그·모듈·플러그인 |
| 빌드 | 실제 타깃·구성 | 선택 타깃 빌드 성공 | 첫 오류와 새 경고 구분 |
| 기본 실행 | 첫 맵·플레이 진입 방식 | 시작·종료·재시작 확인 | 기본 맵·초기화·참조 |
| 다인 검사 | 토폴로지·접속 방법 | [검증 계획](VERIFICATION_PLAN.md)의 해당 단계 관찰 | 서버/클라이언트 로그 각각 확보 |

현재 `.uproject`와 빌드 타깃이 없으므로 엔진 실행 명령을 만들어 적지 않는다. 첫 참여자가 실제로 성공한 명령·환경·로그·확인일을 이 문서와 검증 기록에 남긴 뒤 재현 완료로 표시한다.
