# DIGETHER 기술 구조 초안

상태: **설계 제안, 미구현**. UE 5.8.2 선택만 확정되었으며 실제 모듈·클래스·API·폴더는 아직 없다. 게임 기획을 구현 가능한 경계로 나누기 위한 문서이며 기술 책임자 검토 후 채택한다.

## 핵심 기술 결정 순서

1. 지원 플랫폼·리슨/전용 서버·세션/근거리 음성 제공자를 결정한다.
2. 굴착 기술을 비교한다: 셀/청크 기반 변형, 사전 제작 파괴 구간, 외부 플러그인. 4인 동기화·충돌·몬스터 경로·성능·라이선스를 같은 시나리오로 검증한다. 특정 방식을 채택하지 않았다.
3. 최소 런에서 굴착 → 운반 → 탈출 → 개인 정산을 연결한다.
4. 붕괴·구출·비공개 납부·일차 전환·이탈 및 저장 정책을 확정한다.

## 시스템과 상태 소유 제안

| 논리 영역 | 담당 상태·수명 | 권위/공개 범위 제안 | 협력 영역 |
|---|---|---|---|
| 세션·런 흐름 | 로비, 런, 정산, 상점·납부, 다음 일차, 게임 오버 | 서버 판정, 허용된 공용 상태만 복제 | 모든 런 시스템 |
| 굴착·붕괴 | 지형 수정·보강·여진·잔해, 런 단위 | 서버가 수정 결과와 버전 관리 | 이동·충돌·AI·구출 |
| 캐릭터·구출 | 중량, 생존/깔림/사망 상태 | 서버가 상태 전이, 표현은 클라이언트 | 굴착·인벤토리·경제 |
| 회수품·운반 | 물건 ID·위치·소유/운반 상태·가치·중량 | 서버가 획득/적재/정산 확정 | 물리·엘리베이터·경제 |
| 개인 경제·할당량 | 개인 지갑·납부 거래·일차·공동 달성 판정 | 서버 권위, 개인 거래 상세는 소유자만 | 상점·사망·시체 회수 |
| 절차 맵·던전 | 생성 조건·연결·파괴 가능 구간 | 서버가 유효 구조 결정 | 굴착·포탈·AI |
| 몬스터·트랩 | 감지·행동·피해·경로 | 서버 판정, 클라이언트 연출 | 지형 변경·캐릭터 |
| UI·음성·아트 | 표현·근거리 대화 | UI는 허용 정보만 소비. 음성 서비스 미정 | 플레이어 위치·사망 정책·관전 도입 여부 |

런 종료와 4일 주기 사이에 무엇을 보존하는지, 영구 저장 유무는 기획 결정 전까지 확정하지 않는다. 지갑이 서버 권위라는 제안은 저장 위치·백엔드 선택을 의미하지 않는다.

## 공유 계약 제안

아래 이름은 논리 계약 ID이며 존재하는 함수명이 아니다. 모든 요청은 호출 플레이어·세션·런 ID·허용 상태·대상 유효성·거리·중복을 검증하고, 실패 시 상태를 부분 변경하지 않는 것을 목표로 한다.

| 계약 | 요청·검증 | 성공/실패와 중복 처리 | 필요한 검사 |
|---|---|---|---|
| CT-DIG | 구간·도구·위치, 도달 가능·굴착 허용 여부 | 유효 구간 수정·충돌 반영. 만료 구간/중복 요청 거부 | 동시 굴착, 이동·AI 경로 회귀 |
| CT-RESCUE | 대상·구출 진행, 생존·깔림·거리 | 유효 상태에서만 해제. 죽음·이탈·취소 시 정리 | 구출과 사망 경합, 구조자 이탈 |
| CT-ITEM | 물건 ID·획득/놓기/적재 | 한 물건의 단일 소유·소비. 이미 정산된 물건 재사용 거부 | 동시 획득, 중량 경계, 재전송 |
| CT-SETTLE | 런 ID·회수품·정산 대상 | 같은 런/물건 정산은 한 번만. 귀속 규칙은 기획 결정 필요 | 중복 탈출/정산·이탈·사망 순서 |
| CT-PAY | 금액·거래 ID·일차 | 1인씩 납부하는 기획에 맞춰 동시 창구 접근 처리와 잔액/납부 허용 상태를 확인한 후 차감과 반영을 함께 처리. 같은 ID는 재차감하지 않음 | 동시 구매·납부, 일차 경계, 음수/초과 |
| CT-DAY | 런 종료·일차·할당량 판정 | 진행 단계는 한 번만 전환. 도중 요청 처리 규칙 필요 | 4일차 달성/미달·중복 종료 |

거래 ID의 보존 수명, 서버 재시작 후 재전송 처리, 장애 시 복구는 저장 정책과 함께 결정한다. 메모리 내 중복 방지를 영구 장애 복구로 주장하지 않는다.

## 비공개 정보

기획은 개인 납부 금액과 기여도 비공개를 요구한다. UI에서 숨기는 것만으로 충족하지 않으며 다른 클라이언트에 상세 금액을 전달하지 않는 설계를 제안한다. 공용 잔액·할당량 누적 표시의 변화로 개인 납부가 역산되는지도 검토한다. 공개 합계의 표시 주기·정밀도와 지갑/히든 슬롯의 공개 범위는 기획 미결이다. 시체 복구액으로 사망자의 지갑을, 개인/엘리베이터 중량으로 히든 슬롯 내용을 역산할 수 있는지도 검사한다. 복구 귀속·조건·공개 범위와 중량 합산·표시는 D-007/D-008에서 결정한다. 리슨 서버 채택 시 호스트 프로세스에는 권위 데이터가 있으므로 악의적 호스트에 대한 비밀 보장 범위를 별도로 결정한다.

## 코드·데이터·표현 분리 제안

권위 로직·거래 불변식·복제 계약은 C++ 중심, 콘텐츠 구성·연출·UI는 Blueprint 중심으로 검토한다. 수치는 승인된 데이터 자산으로 분리하고 Notion의 값·단위·개정과 연결한다. 실제 클래스 구성과 데이터 자산 타입은 프로토타입 이후 정한다. 갱신 시 [기술 기준](../unreal/ENGINEERING_PATTERNS.md)을 UE 5.8.2 환경에서 확인한다.

## 실패 경로와 결정 대기

- 1인 플레이의 구출·사망 규칙은 D-006 결정 후 반영한다.
- 후입·재접속 허용 여부에 따라 지형 수정·아이템·일차의 스냅샷 전달 또는 입장 거부가 필요하다.
- 호스트/클라이언트 이탈은 D-004, 포탈 이동 실패·전원 사망·갇힘은 D-006, 중량 초과 시 결과·정산은 D-007을 따른다. 런 시간 제한과 관전은 도입 여부 자체가 D-006의 미결 질문이며 기존 기능으로 전제하지 않는다.
- 경제·시체 회수의 미결 규칙은 D-008에서 관리한다.
- 갇힘 복구는 D-006과 연결하고 파괴 후 충돌·시각 메시 불일치를 검사한다.

결정은 [기획 결정 대기](notion/DECISIONS.md), 경로 책임은 [작업 경계](PROJECT_BOUNDARIES.md), 실제 검증은 [검증 계획](VERIFICATION_PLAN.md)으로 연결한다.
