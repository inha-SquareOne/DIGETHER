# 검증 계획

현재 게임 실행 검증은 전부 미실행이다. 문서 작성 완료와 게임 완성을 구분한다. 환경·실제 명령·예상 테스트 수는 프로젝트 생성 후 채운다.

## 적용 수준

| 변경 | 필요한 검증 |
|---|---|
| 문서 | L1: 출처·확정/제안 구분·로컬 링크·규칙 정합성 |
| 코드·에셋 | L1: 해당 빌드, BP 컴파일·로드·참조 |
| 기능·데이터 | L1+L2: 정상·실패 경로 자동 검사 또는 테스트 레벨 |
| 상태 전환·네트워크 | L1~L3와 M2: 4인 별도 프로세스의 통합·경합 |
| 실제 서비스·음성·온라인 품질 | M3: 서로 다른 PC 4인, 실제 계정/서비스 환경 |

공통 [검증 기준](../ai/VERIFICATION.md)과 [멀티플레이 기준](../ai/MULTIPLAYER_TEST.md)을 적용한다. M2는 리슨이면 호스트+클라이언트 3, 전용이면 서버+클라이언트 4다. 토폴로지는 미정이다. 1인 지원도 별도 검사하며 4인 통과로 대체하지 않는다.

여기서 M0~M3는 **멀티플레이 검증 등급**이다. 로드맵의 M1 프로토타입·M2 알파·M3 베타는 **제작 단계**로, 이름이 같아도 서로 다른 구분이다.

요구 ID와 상세 수용 조건은 [게임 기획](notion/GAME_DESIGN.md)에서 연결한다. 수치 미결은 통과로 판정하지 않으며, 미결 값과 독립적인 불변식은 먼저 검증할 수 있다. 경합은 공통 기준의 최소 10회와 실제 시드·지연·손실 조건을 기록한다.

## 결과 양식

검사 ID / 요구 ID / 기획 개정 / 엔진·플러그인 / 대상 커밋과 미커밋 diff 또는 해시 / 명령·단계 / PC·프로세스·인원 / 예상·실제 / 통과·실패·skip·미실행 수 / 종료 코드 / 로그 경로 / 알려진 한계.

실제 명령: 미등록. 자동 테스트 이름·예상 개수: 미정. 결과는 `docs/project/reviews/`의 날짜별 기록 또는 Issue/CI 아티팩트로 보존한다. 종료 코드 0만으로 통과시키지 않고 테스트 0개·필수 단계 누락·타임아웃을 구분한다.

M3 이후에도 출시 대상·라이선스·패키징·알려진 결함·배포 및 복구 책임을 확정한 [릴리스 양식](../templates/RELEASE_OPERATIONS_TEMPLATE.md)을 채워야 한다. 이번 작업은 배포를 수행하지 않는다.
