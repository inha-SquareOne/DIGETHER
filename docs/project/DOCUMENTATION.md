# Notion과 GitHub 문서 운영

사용자 확정: 기획은 Notion, 프로젝트 파일 관리는 GitHub. 아래 동기화 절차는 초기 운영안이며 실제 담당·리뷰 계정 지정은 남아 있다.

| 정보 | 단일 운영 원본 | 다른 곳에 남길 내용 |
|---|---|---|
| 게임 규칙·콘텐츠·수치·기획 일정 | Notion | 요구 ID, 원본 URL, 승인 개정·확인일, 구현에 필요한 승인 스냅샷 |
| 코드·Unreal 에셋·설정·기술 설계·검사 증거 | GitHub | Notion에는 Issue/PR/검증 기록 링크 |
| 개발 작업 진행 | GitHub Issue/PR 사용 제안 | Notion에는 기획 승인 상태와 관련 링크; 개발 완료 상태를 별도로 수작업 복제하지 않음 |
| 기획 변경 결정 | Notion 결정 DB | 관련 기술 ADR·Issue 연결 |
| 기술·운영 선택 결정 | GitHub ADR, 채택 전 질문은 구조/운영 문서 | Notion에는 질문·연결 요구·ADR 링크만 두며 상태·결정 본문을 별도로 운영하지 않음 |
| 작업 결과·인수인계 | 로컬 `.claude/docs/{날짜}/`와 `.claude/docs/pointer.md` | 공유 작업 상태와 검증 근거는 해당 GitHub Issue/PR 또는 검증 기록을 참조한다. 로컬 기록은 Git에서 제외된다 |
| 제작 마일스톤 수용 | Notion | 완료 표시는 GitHub 구현·검증 증거 링크를 확인한 기획 수용 결과이며 개발 작업 상태를 대체하지 않음 |

## 초기 이관

1. `notion/` 문서를 Notion으로 가져온다. 현재 파일은 이관 전 초안이다.
2. 제목·표·페이지 간 링크를 검수하고 팀 기획 담당이 내용과 미결 표시를 확인한다.
3. 실제 페이지 URL·확인일·검토자를 [가져오기 안내](../planning/README.md)에 등록한다. 가져오기만으로 기획 승인된 것으로 표시하지 않는다.
4. 이관 완료 후 로컬 기획 파일을 이관 시점의 스냅샷으로 선언한다. 최신 요구사항은 Notion을 읽는다.
5. 오프라인 구현이 필요하면 해당 요구만 승인된 개정으로 내보내고, 원본 URL·확인일·승인 근거를 함께 둔다. 자동 동기화는 구축되어 있지 않다.

## 변경 추적

기획 변경 → 요구 ID/개정 갱신 → 영향받는 기술 계약·Issue 링크 → 구현 PR → 검사 증거 → 기획 수용 관찰 확인 순서로 연결한다. PR에는 `요구 ID + 팀이 부여한 개정 번호`를 기록한다. Notion 요구사항에 개정 번호·승인자·승인일을 두고 변경 시 올린다. Notion 내부 이력 기능의 고정 링크를 가정하지 않는다. 기획 승인과 구현 후 수용은 별도 상태로 기록한다. 최신 Notion과 스냅샷이 다르면 해당 규칙의 구현 결정을 보류하고 차이를 기록한다. 코드가 달라졌다는 이유로 기획을 자동 수정하지 않는다.

Notion 접근이 없으면 새 내용을 추측하지 않는다. 마지막 확인 시점의 스냅샷을 명시하고 그 범위에서 독립 작업을 수행한다. 비밀값·팀 외부 공유 권한은 문서에 넣지 않는다.

## 중복 없이 관리할 기준

| 주제 | 상세 기준을 고칠 위치 | 다른 문서의 역할 |
|---|---|---|
| AI 실행·승인·Unreal 지원 조사·원인 해결 | [실행 정책](../ai/EXECUTION_POLICY.md) | AGENTS와 스킬은 요약·진입 링크 |
| 환경·엔진 버전·연결 위치 | [프로필](PROJECT_PROFILE.md) | 가이드는 값 복제보다 프로필 연결 |
| 기획·기술 문서 원본과 승인 상태 | 이 문서 | 역할별 가이드는 담당 작업 순서 안내 |
| GitHub 작업·파일 관리 | [개발 흐름](DEVELOPMENT_WORKFLOW.md) | 초보 가이드는 사용 방법, 원격 정책 확정 아님 |
| 테스트 수준·범위 | [검증 계획](../verification/VERIFICATION_PLAN.md), [TDD 범위](../ai/TDD.md) | 스킬은 변경 위험에 맞는 검사 적용 |
| 스킬 설치 목록·동기화 | [스킬 목록](../tools/SKILLS.md), [도구 관리](../common/INTEGRATION.md) | 역할 가이드는 필요한 스킬만 선택 |

이 프로젝트에 적용하는 규칙이 바뀌면 상세 원본을 먼저 고치고 관련 링크·어댑터를 함께 점검한다. 템플릿과 외부 스킬의 예시는 프로젝트 결정을 새로 부여하지 않는다. 예외에는 적용 범위·이유·결정 근거를 남긴다. [문서 유지](../common/DOCUMENTATION_POLICY.md)의 단일 원본 원칙을 따른다.
