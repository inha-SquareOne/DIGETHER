# DIGETHER 마일스톤

## 단계 전환 검토 제안

- M1→M2: 핵심 기술의 실행 근거와 선택 이유를 남기고, 남은 위험이 전체 콘텐츠 제작에 주는 영향을 확인한다. 문서 작성만으로 기술 검증 완료 처리하지 않는다.
- M2→M3: 최초 범위의 통합 흐름을 재현하고 미구현·미확정 기능을 명시한다. 통과 성능 기준·지원 플랫폼·테스트 환경은 지원 플랫폼·성능 예산 결정 후 적용한다.
- M3 이후: 베타 종료와 출시 승인을 동일시하지 않는다. 출시 기준·배포 방식·운영 범위는 실제 결정이 필요하다.

각 단계의 요구 배치는 담당자·기술 조사 후 조정한다. 달력 날짜와 작업자 배정은 Notion 마일스톤 DB에서 실제 합의 뒤 입력한다.

## 기획 전달 예정과 범위 제한

사용자 전달 [2026-11-06 기획 답변](planning/PLANNING_RESPONSE_2026-11-06.md)이 11월 10일까지 전달하겠다고 한 몬스터 기획서는 2026-11-08에 시스템·우선 제작(미스터리 박스·땅거미) 2종으로 받았다(승인 전 초안, [반영 기준](planning/MONSTER_DESIGN_2026-11-08.md)). 같은 답변은 11월 18일 콘텐츠 1차 확정 때 몬스터 종류·수·외형·핵심 행동과 아이템·장비·소모품 목록·이름·표시·가격 전달 예정(세부 수치 제외)을 적었다. 답변의 팀장 결정은 팀 승인 전이며 이 날짜를 개발 완료일이나 제작 마일스톤 수용일로 바꾸지 않는다. 경제 담당 수치와 목록은 답변 대기다.

MVP 입력은 키보드·마우스이며 배터리·연료·충전과 제단 헌납은 범위에서 제외한다. 던전 지정 벽 파괴는 플레이어·몬스터 모두 레벨 디자이너 결정 전 보류하며 갱도↔던전 이동은 무로딩 기준이다. 치장 착용 부위·수, 정식 갱도 목록, 지원 언어는 담당 기획·출시 범위 결정을 기다린다. 최초 몬스터 2종의 행동은 2026-11-08 기획서(승인 전 초안)로 받았고, 스폰 곡선·파워 한도 값 등 기획 미정 수치와 나머지 종의 명세는 계속 기다린다. 기존 DG 연결이나 문서상 목표만으로 이 항목들을 완료 처리하지 않는다.

## 최초 범위 이후

추가 던전·몬스터·아이템은 최초 범위 완성 후 확장 방향이다. 추가 콘텐츠를 현재 마일스톤의 필수 완료 조건으로 자동 포함하지 않는다. 변경 시 기획 결정과 영향을 연결해 범위를 다시 합의한다.

## 검증 기록 최소 형식

테스트 ID / 요구 ID / 빌드·커밋 / 실행 환경 / 참여 인원 / 선행 상태 / 절차 / 기대 결과 / 실제 결과 / 증거 / 결함 링크. 이 문서에는 실행 결과를 기록하지 않는다. 게임 기능의 자동 테스트·다인 검증 기록은 [구현 현황](design/IMPLEMENTATION_STATUS.md)과 [검증 계획](verification/VERIFICATION_PLAN.md)에서 확인하며, 그 기록을 제작 마일스톤의 수용 판정으로 간주하지 않는다.
