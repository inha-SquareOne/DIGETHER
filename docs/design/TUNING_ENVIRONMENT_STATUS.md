# 튜닝 환경 R01~R14 대조표 (DEV-069)

기준일: 2026-11-06. 기준 자료는 시스템 작업리스트 1.1.0의 '개발 요청(튜닝 환경)' R01~R14와 '튜닝 파라미터' 시트(129행), 사용자 전달 [11/6 기획 답변](../planning/PLANNING_RESPONSE_2026-11-06.md)이다. 정의 데이터와 런 스냅샷이 R01~R14를 얼마나 채우는지 정리한다. P0·P1을 다시 구현하는 작업이 아니다.

## 근거와 한계

- **요구 원문을 확보했다.** 시스템 작업리스트 1.1.0의 '개발 요청(튜닝 환경)' R01~R14 문구와 '튜닝 파라미터' 시트 129행(파라미터 ID·단위·기본값·최소·최대·런타임 조정 열)을 직접 대조했다. 이전 판(2026-11-04)은 원문을 찾지 못해 [전체 시스템 설계](../SYSTEM_DESIGN.md)의 요약을 썼으나, 이 판부터 R 행의 요약은 원문 기준이다. 작업리스트는 Notion 승인본이 아니며 시트의 기본값 공란은 미승인 값이다.
- 2026-11-04 기획 답변(초안)이 R03·R05~R10의 범위·완료 기준(제안)과 수치 7개의 ID(확정)를 보냈다. 아래 [요청 상세](#2026-11-04-기획-답변초안의-요청-상세)에 정리했다.
- 구현 상태는 작업 트리의 코드를 읽은 결과다. 코드는 작업리스트에 맞춰 순차 구현 중이므로 이 문서의 "현재 구현"은 구현 완료나 실행 검증을 뜻하지 않는다. 2026-11-05 이전부터 있던 항목은 "구현(실행 검증 일부)", 2026-11-05 구현분은 "구현(자동 테스트 통과, M2·연출 미검증)"(격리 사본 Editor 빌드, `DIGETHER.Game` 자동 테스트 165개 실패 0), 아직 코드가 없는 규칙은 "기획 기준(구현 진행 중)"으로 적는다. 아래 임시값은 모두 시트 승인값이 아니다.
- 구현 근거: [P0·P1 적용 기록](../../.claude/docs/2026-11-03/P0P1-GameplayTag-정의데이터-적용.md), `Game/Data/DigetherTuningProfile.h`, `Game/Elevator/DigetherElevatorTuning.h`, `Game/Economy/DigetherEconomyTuning.h`, `Game/Run/DigetherGameOverTypes.h`, `Game/Save/DigetherSaveTuning.h`, `Game/Data/DigetherItemDefinition.h`, `Game/Tests/DigetherDataDefinitionTest.cpp`.

## 현재 구현 요약

- `UDigetherTuningProfile`(DA) 하나가 `FDigetherRunTuning` 12개 값(프로필 버전 포함)의 원본이다. C++ 기본값은 비워 뒀다.
- `MakeSnapshot()`이 런 시작 때 복사본을 만들고 출처 프로필 ID를 채운다. 프로토타입 GameMode가 시작마다 다시 읽고 검사하며, 실패하면 출발을 거절한다. 런 시작 로그에 프로필 ID·버전을 남긴다. 스냅샷은 서버 GameMode가 가진다.
- 엘리베이터(`FDigetherElevatorTuning`)와 경제(`FDigetherEconomyTuning`) 값은 별도 구조체의 중앙 기본값이다. 납부 효율 30/50/70/100%는 경제 기본값에 들어 있다(구현(실행 검증 일부)). 문 닫힘 시간(`LOBBY_DOOR_CLOSE_TIME`·`ELV_DOOR_CLOSE_TIME`)은 엘리베이터 기본값에 개발 임시값 3초로 들어 있다.
- 2026-11-05에 추가한 튜닝 필드(모두 임시값, 2026-11-05):

- `UDigetherItemDefinition`(DA)이 물품 종류·특성 태그·가치·무게를 가진다.

### 몬스터 임시값

2026-11-05 사용자 결정(임시): 땅거미 `MON_HP` 100, 미스터리 박스(처치 가능) `MON_HP` 200. 근거는 플레이어 기본 공격 피해 12.5 가정(땅거미 약 8번)이다. 시트 기본값은 공란이므로 승인값이 아니다. 정의 자산 `DA_Monster_GroundSpider`(100)·`DA_Monster_MysteryBox`(200)를 만들었으므로 시트 '변경 메모'에 임시로 기록해야 한다. `MON_SPAWN_COUNT`는 서식지·배출구 방식과 정의가 맞지 않아 PQ-33에서 확인한다.

### 단위 정책

시트 규칙은 계산 단위를 kg·m·초·도·정수 돈으로 통일하고 단위를 섞지 않는 것이다. 엔진 내부는 거리 cm, 비율은 정수 백분율(%)을 쓴다(예: `InteractionDistanceCm`, `DeathLossPercent`). 따라서 튜닝 값은 시트 단위(m·비율)로 입력받고 엔진 단위로 바꾸는 **변환 위치를 한 곳으로 정해 명시해야 한다**. 현재는 필드마다 엔진 단위로 직접 입력하고 주석에 시트 단위를 적는 방식이며, R09 완료 기준("에디터에서 시트와 같은 단위가 보임")과 맞추려면 변환 위치 결정이 필요하다(미결정).

## 2026-11-04 기획 답변(초안)의 요청 상세

기획은 '개발 요청(튜닝 환경)' 시트의 한 줄 요약이 가진 원문 전부라고 답하고, R03·R05~R10의 만들 범위와 완료 기준을 풀어 썼다(A1, **제안**). 기준 작업리스트는 1.1.0이다. Notion 승인본이 아니며 아래 대조표의 R05~R08 판정은 이 기준으로 다시 하지 않았다. 전체 목표는 기획자가 프로그래머 없이 게임 수치와 몬스터 행동을 바꿔 볼 수 있는 작업 환경이다.

공통 전제: 계산 단위는 kg·m·초·도·정수 돈이다. 시트의 기본값 공란은 미승인 값이며, 확인용 임시값을 넣으면 시트 '변경 메모' 열에 "임시"라고 적는다. 판정 값은 호스트 기준(R13)이다.

### 곡선과 런타임 조정 (E1·E2, 제안)

- R11 곡선: 1.1.0 원문은 "중량-속도처럼 곡선형 항목은 엔진 커브 편집기로 조정"이다. 시트에 곡선 단위로 지정된 `PLY_WEIGHT_SPEED_CURVE`(소지 무게 → 이동 속도), `QUAKE_INTERVAL_CURVE`(남은 제한 시간 → 여진 간격)부터 붙인다. 추가 제안은 붕괴 진행도 → 지진 스캐너(가칭) 그래프 세기, 거리 → 음성 크기, 경제 설계 후 목표 달성 횟수 → 다음 할당량이다.
- R04·R13 런타임 조정: 1.1.0 원문은 "런타임 조정 Y는 호스트 기준으로 플레이 중 반영, 운행 횟수·사망 비율처럼 진행 결과를 바꾸는 프로필은 거점에서 바꿔 다음 탐사 시작 때 고정, 탐사 중간 소급 변경 금지"(R04)와 "판정 값은 호스트 기준, 버전이 다른 클라이언트 참가 시 경고, 런타임 변경도 호스트 권한·동일 버전으로 동기화, 화면 전용 설정은 판정값과 분리"(R13)다. 기획 답변은 모든 값을 탐사 시작 때 고정하는 현재 방식이 R04와 맞지 않는다고 했다. 먼저 붙일 값: 여진 간격, 붕괴 예고 시간(3~10초), 몬스터 등장 판정 주기·확률, 이동 속도·무게 감속, 엘리베이터 운행 시간·상승당 시간 감소, 음성 거리. 탐사 중 바꾸지 않는 값: 시트 N 값(`RUN_TIME_LIMIT`, `PAY_TARGET_GROWTH`, 상승 횟수, 사망 비율 등)과 맵 생성 때 정해지는 값. 땅거미 둥지 확률은 맵 생성 때 정해지지만 시트는 런타임 Y로 적었다(PQ-37).
- R01 D16: 11/4 B3는 비교용 탈출 시점형 선택을 요청했다([게임 기획](../GAME_DESIGN.md#비교용-탈출-시점형-분배), 미구현). 11/6 답변 03은 현재 합산형을 유지하고 분배·비율의 최종 결정은 시험 뒤로 둔다. 비교용 기능을 현행 기본값이나 새 구현 승인으로 해석하지 않는다.
