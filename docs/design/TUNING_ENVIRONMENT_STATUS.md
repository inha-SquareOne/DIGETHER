# 튜닝 환경 R01~R14 대조표 (DEV-069)

기준일: 2026-11-04. 정의 데이터와 런 스냅샷이 R01~R14를 얼마나 채우는지 정리한다. P0·P1을 다시 구현하는 작업이 아니다.

## 근거와 한계

- **요구 원문을 확인하지 못했다.** 보드 DEV-069는 기능 명세 '개발 요청(튜닝 환경)' R01~R14와 '튜닝 파라미터' 시트를 가리킨다. 2026-11-04에 Notion 읽기 전용 검색·조회를 했으나 DEV-069 보드 페이지(본문 비어 있음, 개정·승인 표시 `unverified`)만 나오고 기능 명세 페이지와 시트는 찾지 못했다. 저장소에는 `docs/project/notion/` 스냅샷이 없다.
- 그래서 요구 내용은 저장소가 R번호를 인용한 [전체 시스템 설계](../SYSTEM_DESIGN.md)의 "튜닝 데이터와 테스트 환경 R01~R14" 절과 [UE 기능 활용 범위](UNREAL_FEATURE_COVERAGE.md)에서 가져왔다. 이는 **원문이 아니라 저장소의 요약**이며, R05~R08은 같은 문서의 몬스터 BT 문단(116행) 요약에서 가져왔으며 이것도 원문이 아니다. 요약에서 경계가 드러나지 않는 R03 매핑과 R09·R10 구분은 원문 확인 전까지 "원문 미확인"으로 두고 추정으로 채우지 않았다.
- 구현 근거: [P0·P1 적용 기록](../../.claude/docs/2026-11-03/P0P1-GameplayTag-정의데이터-적용.md), `Game/Data/DigetherTuningProfile.h`, `Game/Data/DigetherItemDefinition.h`, `Game/Tests/DigetherDataDefinitionTest.cpp`.

## 현재 구현 요약

- `UDigetherTuningProfile`(DA) 하나가 `FDigetherRunTuning` 12개 값(프로필 버전 포함)의 원본이다. C++ 기본값은 비워 뒀다.
- `MakeSnapshot()`이 런 시작 때 복사본을 만들고 출처 프로필 ID를 채운다. 프로토타입 GameMode가 시작마다 다시 읽고 검사하며, 실패하면 출발을 거절한다. 런 시작 로그에 프로필 ID·버전을 남긴다. 스냅샷은 서버 GameMode가 가진다.
- 값 범위는 `ClampMin`/`ClampMax`/`Units` 메타와 `CollectProblems`·`IsDataValid`가 검사한다.
- `UDigetherItemDefinition`(DA)이 물품 종류·특성 태그·가치·무게를 가진다.

## 기록상 남은 검증 (확인만, 이번에 실행하지 않음)

- 패키지(cook)에서 정의 DA 로드: P0·P1 기록에 "남은 작업"으로 적혀 있고 이번 세션에서도 실행하지 않았다.
- 1인 렌더 완주: 스크린샷이 마감 뒤 생성돼 실패한 기록이 있고 5.8.4에서 재실행하지 않았다. 이번에도 실행하지 않았다.
- 4인 교실 대열 이동 실패와 낡은 DigCell 검사는 기록상 별도 결함으로 남아 있다.
