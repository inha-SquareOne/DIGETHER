# Dain 굴착 — 현재 구현과 팀 통합 설계

기준: 2026-11-10. 개인 굴착의 현재 상태와 남은 팀 통합 작업을 정리한다. 팀 공용 API·담당·최종 도구 수치 승인 문서가 아니다. 실행 방법과 검증 기록은 [테스트 안내](DAIN_EXCAVATION_MAP_TEST.md)를 따른다.

## 1. 목표와 근거

출시할 DIGETHER의 S07 굴착 기능을 개발한다. 개인 맵은 실제 기능의 검증 장소이며, 1인 시험 성공을 제품 기능 완료로 보지 않는다. 사용자의 담당 MUST는 굴착, 갱도 생성(S05), 여진·통로 붕괴, 매몰, 구조다. S05는 탐사마다 사전 제작 갱도 맵 여러 개 중 하나를 선택·로드하는 뜻으로 정정한다(런 플로우 v1.0.1 6.1, 2026-11-11 반영). 갱도 형태를 매번 새로 만들지 않으며 던전·물품 배치는 기존 규칙을 따른다. 담당 배정은 유지한다. 이번 구현 범위는 굴착이며 후속 기능에 필요한 지형 변경 정보까지만 설계한다.

지정된 갱도 흙만 반복해서 파고, 표면·충돌을 갱신하여 캐릭터가 통과하게 한다. 던전 지정 벽 파괴는 별도다. [게임 기획](../GAME_DESIGN.md), [굴착 설계](EXCAVATION_IMPLEMENTATION.md), [전체 구조](../ARCHITECTURE.md), [결정 목록](../planning/DECISIONS.md), [네트워크 권위](../unreal/NETWORK_AUTHORITY.md)가 관련 근거다. Notion 최신 개정·팀 담당 승인까지 확인됐다는 뜻은 아니다.

## 2. 현재 구조

밀도장 기반 복셀 + Marching Tetrahedra + 엔진 ProceduralMeshComponent를 사용한다. DynamicMesh/Geometry Script나 외부 복셀 플러그인 구현이 아니다.

| 경로( Source/DIGETHER/Game/Excavation 기준 ) | 책임 |

| Dain/DigetherDiggableSoil.h/.cpp | 밀도 보관, 좌표 변환, 후보 지형/충돌 준비와 교체 |
| Dain/DigetherSoilFieldTests.cpp | 계산·경계·와인딩·보호·입력·노멀 검증 |
| Dain/DigetherSoilActorTests.cpp | 실제 엔진 충돌·상태 보존·캐릭터 이동 검증 |
| DainLab/DigetherDainCharacter.h/.cpp | 개인 시험 카메라 Trace·입력 연결 |
| DainLab/DigetherDainGameMode.h/.cpp | 개인 시험 Pawn/HUD와 검증기 선택 |

총 C++16개다(청크 구현·계측 헤더 포함). 헤더/소스 한 쌍이 보통 한 클래스이며 파일 개수와 시스템 개수는 다르다. 구형 DigetherDainField/SoilWall 네 파일과 호환 분기는 제거했다. 계산 출처는 기존 prototype/DainField의 표면 추출 방식이며 관련 코드 주석은 보존한다. Prototype 자체는 변경하지 않는다.

## 3. 굴착 처리

1. 시험 캐릭터가 카메라 앞 첫 차단 대상을 확인한다. 보호벽 너머를 파지 않는다.
2. Actor가 서버 권한·입력·단위 스케일을 검사하고 월드 위치를 로컬로 변환한다.
3. 밀도 사본에 구형 제거 함수를 적용한다. 128이 경계이며 큰 값은 흙이다. HP 차감이 아니라 기존 값과 제거 함수 중 작은 값을 취한다. 같은 위치·반경은 변화가 없을 수 있다.
4. 보호 영역을 한 셀 확장한 범위와 외곽 공기층은 유지한다.
5. 사면체별 흙/공기 경계에서 선형 보간한 삼각형을 만들고 밀도 기울기를 보간해 노멀을 부드럽게 한다.
6. 비활성 PMC에 새 표면·동기식 충돌을 준비한다. 성공 시 밀도·표시·충돌을 교체하고 revision을 증가시킨다. 실패 시 이전 상태를 보존한다. 빈 지형은 두 버퍼 모두 표시/충돌을 끈다.

TryExcavate 결과는 Applied/NoChange/Rejected/ApplyFailed다. 변경 영역은 지형 변경 범위이며 보강 가능한 천장·붕괴 구역을 확정하는 값은 아니다. 노멀 개선은 음영만 바꾸며 충돌 형태를 바꾸지 않는다.

## 4. 현재 범위와 한계

- 개인 맵은 25cm 격자, (9,35,19)셀/7200표본, 반경75cm/간격0.35초를 사용한다. 최종 도구 수치가 아니다.
- 격자 축4~64, 총 표본32768 이하, 간격2~200cm는 CPU 입력 제한이다. 네트워크 허용 크기/최종 성능 보증이 아니다.
- Carve는 전체 표본 순회를 유지한다. 메시/충돌은 전체·8셀·16셀 모드를 지원하며, 2026-11-10 사용자 결정으로8셀을 잠정 개발 기준으로 삼는다. 비교용 기본 CVar0은 보존하며 시험/향후 배치 연결부에서8을 명시한다. 비동기 작업·청크 전송은 없다.
- 서버 권한 검사만 존재하며 RPC/Replication/OnRep 지형 적용은 미구현이다. 클라이언트에서 직접 호출해 동기화된다고 생각하면 안 된다.
- 개인 raw 입력은 학습·검증 어댑터다. 공용 Character/Enhanced Input/장비/공격 시스템이 연결됐다는 뜻이 아니다.
- 초기화는 지원하지만 런 관리·탐사 지형 영구 저장을 구현한 것은 아니다.

## 5. 최소 팀 연결 계약(제안)

| 담당 경계 | 협의할 내용 |
|---|---|
| 플레이어·공격 | 서버가 확정한 첫 타격 대상/위치, 공격과 굴착 분기, 가림·거리·생존/매몰 상태 제한 |
| 장비·인벤토리 | 현재 도구·운반 상태 조회, 서버가 소유한 반경/간격 설정 위치 |
| 런·네트워크 | 소유 PlayerController/Pawn의 요청 경로, 런 식별, 최신 밀도/revision 복제, 클라이언트 충돌 준비와 재접속 완료 계약 |
| 레벨·AI | 허용 흙/보호 영역/지정 붕괴 구역, 충돌 적용 후 내비게이션 갱신 담당 |
| 개발 책임자 | 최종 통합 경로와 리뷰 담당 |

클라이언트가 보통 소유하지 않는 흙 Actor에 직접 Server RPC를 호출하지 않는다. 클라이언트 반경/결과를 신뢰하지 않고 서버 장비 설정으로 검증한다. 동시 요청은 최신 서버 상태에 순서대로 적용하고 NoChange를 별도 성공 보상으로 처리하지 않는다. 요청 ID·범용 이벤트 버스·새 캐릭터/세션 시스템을 미리 강제하지 않는다.

Prototype의 서버 타격/OnRep/후속 기능은 참고할 수 있으나 Game에서 Prototype 전용 타입에 직접 의존하지 않는다. 실제 사용할 공용 함수·소유권은 담당자와 합의한다.

최신 밀도만 수신했다고 이동 준비 완료로 판정하지 않는다. 클라이언트 충돌 적용 실패/재시도와 준비 전 진입 제한 계약이 필요하다. 새 탐사 참가 금지와 동일 ID 재접속은 별도 정책이며 새 세션 구현으로 대체하지 않는다. 네트워크 배열 한도는 엔진/NetDriver에서 실제 확인하고 무조건 한도를 늘려 해결하지 않는다.

보강·붕괴에는 초기/현재 밀도와 변경 범위 외에 표면 방향·지정 구역·필요한 행위 주체 정보가 필요하다. 몬스터가 판 천장 보강(PQ-28), 진행량 추가 의미(PQ-29), 던전 벽(D41)은 미결을 임의 확정하지 않는다. 체력·매몰·구조는 흙 Actor에 모두 넣지 않는다.

E1/E2/표면 개선의 별도 문서3개를 이 문서와 테스트 안내로 통합했다. 과거 상세 기록은 Git 이력과 정리 전 외부 백업에 남는다. 초기 5.8.2 기록이나 다른 prototype의 검증을 현재 5.8.4 구현의 성공으로 이월하지 않는다. 에셋 관리 기준은 [Git/SVN 결정](../decisions/ADR-004-git-code-svn-assets.md)을 따른다.

## 코드 읽는 순서 — 정돈 후

파일/클래스/에셋 경로와 공개 호출 이름은 유지했다. C++14개 안에서 서식·지역 변수 이름과 내부 함수 책임만 정리했다.

1. DigetherDiggableSoil::TryExcavate — 권한/입력 확인, 밀도 사본 준비
2. DigetherSoil::Carve — 보호 영역을 제외한 밀도 변경
3. DigetherDiggableSoil::Apply → DigetherSoil::BuildSurface — 후보 지형의 표면 생성
4. AppendTetrahedron → AppendTriangle — 사면체의 경계점/삼각형 생성
5. UpdateSmoothNormals — 밀도 기울기를 보간한 음영 노멀
6. Apply — 새 충돌 확인 후 현재 상태 교체

G/NS/NA 등 계산 변수는 Grid/SolidCount/AirCount처럼 역할이 보이도록 변경했다. 표면 기준128은 SurfaceThreshold 상수로 명명했다. if/for의 중괄호와 탭 들여쓰기를 통일하고 압축된 여러 문장을 펼쳤다. 한국어 주석은 보호 경계·표면 분할·충돌 교체 제약 중심으로 정리했다. 계산식/순회 순서/브러시 수치/테스트 판정은 유지했다.

## 개인 코드 컨벤션 적용 범위 (2026-11-06)

- 내부 타입은 FDigetherSoilGrid / FDigetherSoilSurface / EDigetherSoilCarveResult, 격자 조회는 GetSampleCount / GetSampleIndex / GetSamplePosition 사용
- 계산 코어와 시험 코드의 식별자·탭·중괄호 정리, 주석은 선택 이유·제약 중심의 짧은 한국어로 작성
- LabVerify 검증기의 자동 조작·결과 파일 기록·프로세스 종료는 !UE_BUILD_SHIPPING에서만 실행, UCLASS는 기존 참조 호환성을 위해 유지
- 검증기는 월드가 소유한 Character·흙을 TWeakObjectPtr로 참조, 개인 HUD 안내는 FText 지역화 키 사용
- 호환성 예외: 맵에 저장된 CellSpacing(cm), SoilBrushRadius(cm), HitInterval(s) 및 Blueprint 함수 이름·핀은 유지. 단위는 메타데이터·주석에 명시. 이름 변경은 CoreRedirects와 에셋 참조 검증이 필요한 별도 작업
- 파일 추가·알고리즘 교체·공용 Character 연결 없음. 시험 수치는 정식 밸런스 값이 아니며 네트워크·장비 데이터 연결은 기존 미완료 범위 유지


## 개인 청크 비교 구현 (2026-11-07)

사용자 승인 범위의 비교 구현이다. 기존 전체 방식(기본값0)을 보존하고, 개인 흙 Actor의 메시·충돌만 8셀 또는16셀 단위로 나눈다. 공용 시스템·맵·설정·기존 에셋은 변경하지 않는다. 최종 채택 판단은 [실측 보고](DAIN_EXCAVATION_MAP_TEST.md)의 청크 비교 절을 따른다.

- ADigetherDiggableSoil: 전체 밀도 배열·revision은 그대로 보유. SetComparisonChunkCells(0/8/16)는 지형을 초기화하며 모드를 변경한다. 런 중 상태를 보존하는 설정 전환 API가 아니다.
- DigetherSoilChunks.cpp: ApplyChunks/ClearChunks 구현. 청크별 앞·뒤 PMC 두 개를 만들고 변경되지 않은 청크의 활성 메시를 유지한다. UObject는 Actor의 InstanceComponents 및 Transient 배열에서 소유한다.
- BuildSurfaceRange: 전역 밀도를 읽고 해당 셀 범위만 기존 Marching Tetrahedra로 추출. 전체 방식 BuildSurface는 비교 원본으로 유지한다. 두 경로의 사면체 분할·보간·음영 노멀 계산을 일치 검사한다.
- 변경된 모든 표본을 비교하고 청크 꼭짓점 범위보다 각 축으로 한 표본 더 넓은 범위를 갱신 대상으로 잡는다. 밀도 기울기 의존성을 포함하며, 반경 밖의 기존 밀도 변경도 생략하지 않는다.
- 모든 후보의 표면·동기 충돌 준비가 성공한 후 한 게임 스레드 호출 안에서 활성 버퍼와 밀도를 교체한다. 실패하면 기존 활성 밀도·메시·충돌을 유지한다. 멀티스레드 원자성이나 네트워크 트랜잭션을 구현한 것은 아니다.
- 빈 결과는 Air/Solid/Failed로 분리한다. 전부 흙인 내부 청크의 표면0은 정상이며 내부 가상 벽을 만들지 않는다. 혼합 밀도인데 삼각형0이면 보수적으로 실패 처리한다. 임계값 퇴화 사례의 추가 판정 및 흙 내부 스폰 정책은 별도다.
- 음영 노멀은 공유 밀도에서 동일하게 계산한다. 현재는 각 갱신 청크마다 전체 격자의 기울기를 다시 계산하므로 이 부분은 최적화 여지가 남아 있다.
- 충돌 Trace가 삼각형 모서리를 정확히 맞히면 전체/청크 BVH가 다른 인접 면을 선택할 수 있다. 위치가 같아도 ImpactNormal까지 비트 동일하다고 가정하지 않는다.

| 여진·붕괴 S09 | 초기/현재 밀도 비교, 변경 영역, 레벨 지정 붕괴 구역과의 교차, 천장 표면 분류 가능성 | 변경 박스 전체를 붕괴 가능 천장으로 처리, 임의 손상 공식 |
| 보강 S08 | 실제 굴착 천장과 표면 유효성 조회 | 몬스터가 판 천장 보강 여부 확정(PQ-28) |
| 매몰·구조 S10 | 붕괴 충돌 확정 시점·영역 전달 경계 | 흙 Actor가 체력·이동·구조 점유까지 소유 |
| AI | 충돌 확정 이후 변경 범위 통지 | NavMesh 존재만으로 몬스터 통과 완료 판정 |

### 에디터에서 비교

1. 개인 맵 L_DainExcavation을 연다. 공용 기본 맵이나 프로젝트 설정은 변경하지 않는다.
2. 플레이를 시작하기 전에 콘솔에서 `digether.SoilChunkCells 8`을 입력하고 PIE를 시작한다. 16셀은16, 기존 전체 방식은0이다.
3. 같은 흙벽을 반복 굴착하고 통과한다. 비교 모드 변경은 PIE를 종료한 뒤 다시 시작해야 반영된다.
4. 시험 후 `digether.SoilChunkCells 0`으로 돌려 둔다. 이 CVar를 Config나 맵 에셋에 저장하지 않는다.

독립 실행 자동 시험은 `-game -LabVerify -DainChunkCells=8`을 사용한다. 계측은 `digether.SoilProfile 1`(마지막 결과 저장) 또는2(로그)이며, 기본0이다. 기존 틀을 유지하기 위해 Enhanced Input·공용 Character·서버 RPC·새 플러그인은 이번 작업에 추가하지 않았다.


## 절차 생성 연결에 필요한 최소 계약 (2026-11-10)

8×8×8셀은 개인 굴착의 잠정 채택 기준이다. 아래는 현재 API를 바탕으로 한 **연결 제안**이며, 새 구조체·배치 함수·절차 생성기는 이번에 구현하지 않았다. 네트워크·저장 스키마의 확정안도 아니다.

### 책임 구분

| 주체 | 책임 |
|---|---|
| 갱도 생성기 | 시드로 방·통로·던전 입구 배치 결정, 기본 경로 연결/엘리베이터→입구 도달 검사, 흙을 둘 위치와 보호 영역 지정 |
| 흙 Actor | 전체 밀도 보유, 지정 위치 굴착,8셀 메시/충돌 준비·상태 교체 |
| 도구·캐릭터 연결부 | 첫 유효 타격·거리·도구 범위·사용 조건 검증 후 TryExcavate 호출 |
| 생성 완료 판정 | 모든 필요한 흙/모듈의 생성과 충돌 준비 성공 후 탐사 진입 허용. 실패 시 생성 주체가 이번 배치를 회수/재시도 |

**시드는 생성기의 입력이다.** 현재 흙 초기화는 격자와 간격으로 결정되므로 흙마다 별도 Seed가 필요하지 않다. 같은 시드가 네트워크 지형 일치/충돌 준비를 보장하지는 않는다. 굴착 청크와 방/통로 모듈은 다른 단위다.

### 배치 데이터 제안 — FDigetherSoilPlacement

| 값 | 의미·현재 제약 |
|---|---|
| FTransform Transform | 흙 Actor 원점·회전. 현재 WorldToLocal은 단위 스케일만 허용. 크기는 Scale 대신 GridCells/CellSpacing으로 지정 |
| FIntVector GridCells | 셀 수. 현재 각 축4~64 및 전체 표본32768 이하 |
| double CellSpacingCm | cm 단위 간격. 현재2~200 허용, 이번 검증25 |
| TArray<FBox> ProtectedLocalBounds | 흙 로컬 좌표 보호 영역. 기존 계산이 한 셀 여유를 확장하므로 실제 개구부와 간섭 검사 필요 |

청크 크기8은 굴착 구현의 선택값으로 배치 연결부에서 명시한다. 개별 방 데이터마다 튜닝 옵션을 늘릴 필요는 없다. 모듈과 Actor를 연결할 필요가 생기면 생성기 내부의 모듈 인덱스와 약한 Actor 참조로 시작하고, 범용 ID·요청 ID·snapshot 형식부터 강제하지 않는다.

### 현재 사용할 수 있는 함수와 없는 함수

- 기존: GridCells/CellSpacing/ProtectedRegions 설정 후 SetComparisonChunkCells(8)의 bool로 초기화 성공 확인. 이 함수는 지형을 **초기화**하므로 굴착 후 매 요청마다 호출하면 안 된다.
- 기존: TryExcavate(WorldPoint, Radius) → Applied / NoChange / Rejected / ApplyFailed. 실패 시 이전 흙 상태 유지. GetRevision/GetLastChangedWorldBounds로 성공 결과를 조회할 수 있다.
- 기존: 런 종료 때 생성기가 소유한 Actor 제거. ResetSoil은 초기 흙으로 재설정하며 저장된 굴착 상태 복원 기능은 아니다.
- 제안: 나중에 실제 생성 연결을 구현할 때 작은 TryCreateSoil(Placement, OutActor) 어댑터 하나로 배치·초기화·실패 회수를 묶는다. 현재 존재하는 API로 표기하지 않는다.
- 주의: 현재 OnConstruction/BeginPlay와 명시적 비교 초기화가 겹칠 수 있다. 최초 배치 어댑터를 만들 때 한 번 준비하도록 호출 순서를 검토한다. 이번에는 런타임 초기화 순서나 최적화를 변경하지 않았다.

### 모듈 연결에서 꼭 확인할 것

1. 기존 통로/필수 경로는 정적 모듈의 연결·캡슐 통과로 검증한다. 흙 샛길은 별도 선택 연결로 다루며, 닫힌 흙이 필수 경로를 막는지 검사한다. 필수 굴착을 요구하는 배치는 기획과 별도 합의한다.
2. 흙 뒤에 정적 벽의 충돌이 남으면 파도 통과하지 못한다. 연결할 개구부에서 정적 모듈과 흙의 충돌이 겹치지 않도록 제작한다.
3. 격자 영역은 원점부터 GridCells×CellSpacing이다. 초기 외곽 한 층은 공기이므로 실제 표면은 경계 안쪽(이번25cm 격자의 평면부12.5cm)에 생긴다. Actor 상자를 맞댔다고 흙 표면이 이어지지 않는다.
4. **Actor 내부 청크 경계와 Actor끼리의 경계는 다르다.** 이번 여러 Actor 시험은 떨어진 흙벽이다. 서로 맞댄 독립 밀도장의 틈·법선·양쪽 동시 굴착까지 검증하지 않았다. 우선 독립적인 개구부마다 흙 Actor 하나를 배치하는 연결을 권장한다.
5. 생성 완료 전에 캡슐 겹침·시작 위치 점유·필수 경로 도달을 검사한다. 표면 없는 내부 Solid 청크는 공기가 아니므로 삼각형 유무만으로 스폰 가능 판정하지 않는다.
6. 내비게이션 갱신·굴착 후 추가 경로 인식·멀티플레이 지형 준비는 후속 계약이다. 현재 GetLastChangedWorldBounds를 읽을 수 있다는 것과 자동 NavMesh 갱신이 연결됐다는 것은 다르다.

추가 최적화는 보류하고, 실제 연결 착수 시에는 작은 고정 모듈 두 개와 흙 개구부 하나의 계약부터 검증한다. 이번 작업에서 방 생성 알고리즘·공통 Character·세션·인벤토리는 추가하지 않는다.

## develop 현황 정정 반영 — 2026-11-10

원격 a1e0884의 정정을 로컬 통합 문서에 반영했다. [구현 현황](IMPLEMENTATION_STATUS.md)과 [굴착 구현 설계](EXCAVATION_IMPLEMENTATION.md)를 함께 읽되, 원격에 아직 없는 로컬 청크·도구 시험과 구분한다.

- E1 계산 코어와 E2 흙 Actor 연결은 이미 완료한 단계다. L_DainExcavation의 Dain_DiggableSoil 라벨은 현재 ADigetherDiggableSoil을 가리키며 구형 DainLab 흙벽을 뜻하지 않는다.
- 구형 E1/E2 문서의 현황 정정은 이 문서에 통합했다. 로컬에서 통합·삭제한 별도 문서를 다시 되살리지 않았다. 당시의 코드 줄 수·테스트 수를 최신 구현 수치로 취급하지 않는다.
- 축별 셀 상한은 64이며 개인 맵은 7,200표본이다. 이는 복제 없는 시험 규모다. 원격 문서가 경고한 단일 배열 복제 기본 한도 2,048과의 차이를 E4 설계에서 검토해야 하며, 현 격자를 통째로 복제할 수 있다고 가정하지 않는다. 엔진/NetDriver의 실제 직렬화 경로와 한도도 검증해야 한다.
- 초기화는 서버 권한에서만 수행한다. 클라이언트 초기 지형 생성·조각 전송·최신 revision 확인·충돌 준비 완료 경로는 미구현이다.
- 각 흙 Actor는 외곽 공기층을 가진 닫힌 볼륨이다. Actor 여러 개를 붙이는 것은 현재 한 Actor 내부 메시 청크와 다르며, 연속 지형으로 확장하려면 표본/경계 계약이 필요하다. 갱도 흙을 구획형 또는 연속형으로 운영할지는 미확정이다.
- 다음 정식 연결은 E3 도구 타격 계약 확인이다. 개인 곡괭이·삽 시험은 정식 장착·공격 연결 완료와 구분한다. E1/E2 완료를 S07 전체 완료로 표시하지 않는다.
