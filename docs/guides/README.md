# 역할별 시작 안내

자기 역할의 안내부터 읽으면 된다. 기술 규칙은 기존 문서를 원본으로 유지하고 이 폴더는 읽는 순서와 실제 협업 방법을 안내한다.

| 역할 | 먼저 읽을 안내 | 주로 남기는 결과 |
|---|---|---|
| 기획반 | [기획자 안내](planning/README.md) | Notion 요구사항·개정·승인 및 구현 수용 결과 |
| 아트반 | [아트 제작자 안내](art/README.md) | 제작 원본·내보내기 파일·검수 이미지와 전달 정보 |
| 개발자 | [개발자 안내](development/README.md) | 구현·설정·검사 증거·PR |
| GitHub가 처음인 팀원 | [GitHub 처음 사용하기](GITHUB_BEGINNER.md) | 요청 등록·리뷰 의견, 필요할 때 파일 전달 |

**확정된 기준:** 기획은 Notion, 프로젝트 파일은 GitHub, 엔진은 UE 5.8.2다. 기획자는 브라우저에서 기획과 요청을 작성할 수 있으며 저장소 복제가 필수는 아니다.

**준비 중인 항목:** Unreal 프로젝트와 LFS 패턴은 추가됐으며, Notion 페이지 주소·LFS 원격 사용 검증·원격 브랜치 규칙·리뷰/통합 담당은 아직 준비 중이다. 아래 안내의 브랜치·Issue·PR 전달 절차는 초기 운영안이다. 팀 담당이 [프로필](../project/PROJECT_PROFILE.md)과 [작업 경계](../project/PROJECT_BOUNDARIES.md)에 확정값을 등록한 후 적용한다. 문서만으로 계정 권한·잠금·자동 동기화가 생기지는 않는다.

기획과 파일 사이의 연결 기준은 [문서 운영](../project/DOCUMENTATION.md), 현재 할 수 있는 작업은 [현황](../project/STATUS.md)을 따른다. 역할이 겹치면 관련 안내를 함께 읽되 같은 게임 규칙을 여러 문서에서 별도로 고치지 않는다.
