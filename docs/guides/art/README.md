# 아트반 안내

제작 파일과 게임에 들어가는 에셋을 구분해서 전달한다. GitHub가 처음이면 첫 전달은 기술 담당과 함께 [Desktop 흐름](../GITHUB_BEGINNER.md)을 진행한다. 제작 도구와 원본 보관 위치는 작업 시작 전에 합의한다.

## 처음 읽을 순서

1. [프로필](../../project/PROJECT_PROFILE.md): 스타일·엔진·미정인 예산 확인.
2. [담당과 경계](../../project/PROJECT_BOUNDARIES.md): 파일·공유 맵 편집 예약.
3. [모델·재질 제작과 검수](../../unreal/ART_PRODUCTION.md), Unreal을 직접 편집할 때 [에셋 안전](../../unreal/ASSET_SAFETY.md).
4. [GitHub 초보 안내](../GITHUB_BEGINNER.md): 파일 전달·오류 보존 방법.

로비 시설 모델을 전달하거나 교체할 때는 [로비 시설 아트 전달과 외형 교체](HUB_FACILITY_ASSET_HANDOFF.md)의 Blueprint 슬롯·치수·기능 연결 기준을 함께 확인한다.

## 파일 세 종류

| 종류 | 예시 | 전달할 정보 |
|---|---|---|
| 제작 원본 | `.blend`, 레이어가 있는 이미지 파일 | 도구 버전·의존 텍스처·편집 가능한 원본 위치 |
| 내보내기 결과 | `.fbx`, `.glb`, 텍스처·오디오 | 내보내기 설정·단위·축·피벗·원본과의 관계 |
| Unreal 에셋 | `.uasset`, `.umap` | 엔진 내 경로·참조·임포트 설정·실제 검사 결과 |

아직 프로젝트가 없으므로 Unreal 내 저장 경로를 이미 존재하는 것처럼 정하지 않는다. 제작 원본의 저장소 경로와 LFS 추적·용량·권한은 기술 담당 확인 후 정한다. 웹 화면에 큰 제작 파일을 끌어놓아 업로드하지 않는다. LFS가 준비되지 않았다면 원본을 보존하고 전달을 대기한다. 임의 외부 공유 서비스로 우회하지 않는다.

## 하루 작업과 전달

1. Notion 요구·승인 개정과 레퍼런스, 크기·용도·관찰 카메라를 확인한다. 폴리곤·텍스처 예산이 미정이면 임의의 숫자로 확정하지 않는다.
2. 편집할 파일·맵과 작업 시간을 담당자에게 알리고 예약한다. 같은 바이너리는 한 번에 한 사람만 저장한다. 브랜치가 달라도 같은 에셋의 동시 편집을 안전하게 합칠 수 있는 것은 아니다.
3. 원본을 저장하고 담당 범위만 제작한다. 엔진 도입은 준비된 프로젝트에서 담당자가 진행한다. Blender 스킬을 쓰면 실제 도구 버전과 스킬의 지원 기준을 먼저 확인한다.
4. 제작 검수 후 아래 양식과 같은 카메라의 비교 이미지를 준비한다. 준비가 된 저장소에서는 Desktop으로 작업 브랜치에 커밋·전송하고 PR을 만든다. 자세한 버튼 순서는 공통 초보 안내를 따른다.
5. 기술 담당이 임포트·참조·게임 내 결과를 검수하고 통합한다. 파일 전달 완료와 게임 내 검증 완료를 구분한다. 다음 편집 가능 시점을 알리고 잠금은 합의된 인계 시점에 해제한다.

```text
작업 / 요구 ID·Notion URL·개정 / 관련 Issue:
제작 원본·내보내기 파일 경로 / 사용 도구·버전:
크기·단위·축·피벗 / 내보내기 설정:
텍스처·재질·리그 등 의존 파일 / 사용 권리·제약:
변경 내용 / 비교 이미지:
검사한 항목 / 미검사·알려진 문제:
Unreal 통합 담당 / 예약·잠금 상태 / 다음 편집 가능 시점:
```

## 막혔을 때

충돌·파일 누락·LFS 오류가 나오면 원본을 삭제하거나 다른 사람 파일로 덮어쓰지 않는다. 현재 작업 경로·브랜치·변경 목록·오류 화면을 기술 담당에게 전달한다. 충돌한 바이너리에 자동 병합이나 임의의 한쪽 선택을 하지 않는다. Unreal 에셋 이동·이름 변경도 파일 탐색기에서 임의로 하지 않고 [에셋 안전](../../unreal/ASSET_SAFETY.md)을 따른다.
