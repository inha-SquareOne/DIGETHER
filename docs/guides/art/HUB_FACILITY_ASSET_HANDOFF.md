# 로비 시설 아트 전달과 외형 교체

`/Game/Game/Maps/L_Hub`의 시설은 기능 Actor와 외형 Blueprint를 분리한다. 아트 담당은 시설별 Blueprint의 메시·재질을 교체하고, 기능 ID·상호작용 위치·충돌·휴식 위치는 유지한다. 엔진은 UE **5.8.4**를 사용한다.

이 문서는 외형 교체 계약이다. 실제 적용·빌드·플레이 검증 결과는 작업 기록에서 별도로 확인한다. 상점 품목·가격·제단 효과 등의 게임 규칙이나 폴리곤·텍스처 예산을 확정하는 문서가 아니다. 공통 제작·검수는 [모델·재질 제작과 검수](../../unreal/ART_PRODUCTION.md), 패키지 편집은 [에셋 안전](../../unreal/ASSET_SAFETY.md)을 따른다.

## 교체할 Blueprint

저장 폴더는 `/Game/Game/Environment/Hub/Blueprints`다. 각 Blueprint는 `ADigetherHubVisualActor`를 부모로 사용한다.

| 시설 | 외형 Blueprint | 기능과 연결할 때 유지할 것 |
|---|---|---|
| 상점 | `BP_HubVisual_Shop` | 상점 기능 Actor·시설 ID·상호작용 원점 |
| 물품 수령함 | `BP_HubVisual_Delivery` | 수령 기능 Actor·시설 ID·상호작용 원점 |
| 침대 | `BP_HubVisual_Bed` | 침대별 기능 Actor·시설 ID·`RestLocationOffset` |
| 제단의 수조 | `BP_HubVisual_Altar` | 제단 기능 Actor·시설 ID·기존 `OfferingLight` 참조 |
| 납부대 | `BP_HubVisual_Deposit` | 납부대 기능 Actor·`StationId`·거리 판정 원점 |
| 스테이지 구매·선택 패널 | `BP_HubVisual_StagePanel` | 스테이지 기능 Actor·시설 ID·상호작용 원점 |
| 엘리베이터 바닥 외형 | `BP_HubVisual_Elevator` | 기능 엘리베이터와의 부착·탑승 영역 |
| 엘리베이터 레버 | `BP_HubVisual_Lever` | 각 기능 레버와의 부착·레버 종류·엘리베이터 참조 |

침대 두 개는 같은 `BP_HubVisual_Bed`의 인스턴스를 사용하되, 기능 Actor와 시설 ID는 각각 유지한다. 레버 두 개도 같은 외형 Blueprint를 쓰고 기능 연결은 각각 유지한다. Blueprint 기본값에 특정 레벨의 기능 Actor를 연결하지 않고, 맵에 배치된 인스턴스에서 연결한다.

외형 교체는 에디터에서 BP·맵을 저장하고 동일한 에셋을 배포하는 절차다. 비주얼 Actor를 삭제·재생성하거나 실행 중 서버에서만 메시를 바꾸는 방식은 이 계약에 포함하지 않는다.

거점의 벽·천장·기둥·등불과 시험 구역의 고정 엘리베이터 장식은 위 시설 교체 범위와 별도다. 특히 시험 구역의 고정 장식은 현재 배치를 유지하므로, 이동하는 엘리베이터 외형을 바꾼 뒤 겹침도 확인한다.

## 컴포넌트별 역할

```text
SceneRoot
├─ ArtRoot
│  └─ ReplacementMesh
├─ PlaceholderRoot
├─ CollisionRoot
└─ InteractionAnchor
```

| 컴포넌트·속성 | 편집 용도 |
|---|---|
| `SceneRoot` | 시설 배치의 기준이다. 외형 피벗 보정을 위해 이동·확대하지 않는다. |
| `ArtRoot` | 새 아트의 위치·회전·크기를 보정한다. 여러 파트의 메시도 이 아래에 둔다. |
| `ReplacementMesh` | 한 덩어리로 전달된 Static Mesh와 재질을 지정하는 슬롯이다. |
| `PlaceholderRoot` | 새 외형을 지정하기 전 사용하는 임시 외형이다. 교체할 때 지울 필요가 없다. |
| `CollisionRoot` | 통행과 판정에 필요한 충돌 형상을 둔다. 아트 메시 교체와 분리한다. |
| `InteractionAnchor` | 기존 기능 위치와의 연결 기준이다. 외형에 맞춰 임의로 옮기지 않는다. |
| `GameplayActor` | 맵에 배치된 기존 기능 Actor 참조다. 외형을 바꿀 때 다시 생성하거나 바꾸지 않는다. |
| `bUseCustomArt` | `ArtRoot` 아래 여러 파트로 만든 외형을 사용할 때 켠다. |

`ReplacementMesh`에 메시가 있거나 `bUseCustomArt`가 켜지면 임시 외형을 숨기고 새 외형을 표시한다. 메시가 없고 `bUseCustomArt`가 꺼져 있으면 임시 외형을 표시한다. 메시 없이 `bUseCustomArt`만 켜면 빈 외형이 될 수 있으므로 `ArtRoot` 아래의 실제 파트를 확인한다. 편집 후 `RefreshVisuals`로 표시 상태를 갱신할 수 있다.

새 아트와 임시 외형 계층의 메시 충돌은 사용하지 않는다. 충돌은 `CollisionRoot`에서 담당한다. 따라서 아트 파일에 자동 생성 충돌이 포함되어 있어도 그것만으로 게임의 통행 판정이 바뀌는 구조로 사용하지 않는다.

## 제작 기준과 전달 치수

- 단위는 **cm**, 위쪽은 **+Z**, 시설 정면은 **+X**로 맞춘다.
- 메시 피벗은 바닥 중앙, 내보내기와 Blueprint 인스턴스의 기준 스케일은 `(1, 1, 1)`로 맞춘다. 로비에서 바라보는 방향은 배치 Actor의 회전으로 맞춘다.
- 기존 파일의 피벗·축이 다르면 원본 설정을 기록하고 `ArtRoot` 또는 `ReplacementMesh`의 상대 변환에서 보정한다. `SceneRoot`와 기능 Actor를 옮겨 보정하지 않는다.
- 재질 슬롯의 이름·순서와 각 슬롯이 가리키는 파트를 함께 전달한다. 교체 후 슬롯 수가 달라지면 이전 `Override Materials`가 새 슬롯과 맞는지 확인한다.
- 제작 원본, 내보내기 파일, 텍스처 의존 파일, 도구 버전과 사용 권리를 함께 전달한다. 파일 보관(SVN)·잠금·전달 절차는 [아트반 안내](README.md)를 따른다.

아래는 현재 임시 외형과 배치 공간을 비교하기 위한 기준이다. 최종 아트의 예산·강제 상한이 아니며, 실제 통행 공간과 기능 기준점을 유지하는 범위에서 조정한다. 가로·세로는 현재 도면에서 차지하는 공간을 나타낸다. 새 메시의 로컬 +X 정면으로 방향을 맞출 때는 시설의 배치 회전도 함께 확인한다.

| 시설 | 현재 도면상 대략적인 가로 × 세로 × 높이(cm) | 주의할 부분 |
|---|---|---|
| 상점 | 140 × 145 × 150 | 앞쪽 화면과 손잡이가 상호작용 지점을 가리지 않게 한다. |
| 수령함 | 200 × 200 × 110 | 접근 면과 물품 수령 동선을 남긴다. |
| 침대 | 120 × 180 × 90 | 머리·발 방향, 누울 위치와 일어날 공간을 확인한다. |
| 제단 수조 | 지름 440, 테두리 높이 10 | 룬 장식은 테두리보다 높다. 수조 내부를 큰 단일 Box로 막지 않는다. |
| 납부대 | 250 × 180 × 140 | 앞쪽 납부·조작 지점을 유지한다. |
| 스테이지 패널 | 100 × 100 × 140 | 앞쪽 조작면과 시야를 유지한다. |
| 엘리베이터 | 바닥 공간 400 × 250, 판재 높이 4 | 장식 테두리는 더 높다. 벽·문틀·탑승 판정 영역과 바닥 외형을 구분한다. |
| 레버 | 임시 메시 20 × 20 × 100 | 기능 Actor 원점에서 +Z 80 지점이 조준 기준이다. |

치수의 출처는 [로비 배치 스크립트](../../../scripts/editor/build_hub_layout.py)와 [기능 기본값](../../../DIGETHER/Source/DIGETHER/Game/Framework/DigetherFrameworkDefaults.h)이다. 배치 스크립트의 도면 좌표는 엔진 배치 시 Y축 부호를 바꾸므로, 도면의 좌표를 그대로 월드 좌표로 복사하지 않는다.

## 메시·재질 교체 순서

1. 대상 Blueprint와 `L_Hub`의 편집 담당·미저장 상태를 확인하고, 변경 전 저장본과 같은 카메라의 비교 이미지를 남긴다. 같은 `.uasset`·`.umap`은 한 작업자만 편집한다.
2. 에셋을 Unreal 에디터에서 임포트한다. 파일 탐색기로 기존 `.uasset`을 덮어쓰거나, 기능 Actor를 삭제하고 새로 만들지 않는다.
3. 시설 Blueprint를 열고 `ReplacementMesh`의 **Static Mesh**와 **Materials**를 지정한다. 같은 메시를 쓰는 모든 침대·레버를 바꾸려면 Blueprint 기본값에서 변경하고, 인스턴스에 이전 메시 오버라이드가 남아 있는지도 확인한다.
4. 파트가 여러 개면 `ArtRoot` 아래에 메시 컴포넌트를 추가하고 `bUseCustomArt`를 켠다. 각각의 상대 변환만 조정한다. 단일 메시와 여러 파트를 동시에 표시할 필요가 없으면 `ReplacementMesh`의 메시를 비운다.
5. 피벗·크기는 `ArtRoot`에서 보정하고 `RefreshVisuals`를 실행한다. 새 외형이 보이고 임시 외형이 숨겨지는지 확인한다. 필요하면 메시를 비우고 `bUseCustomArt`를 꺼서 임시 외형으로 돌아갈 수 있다.
6. 아래 기능·충돌 검사를 수행한 뒤 Blueprint를 컴파일·저장하고, 수정한 인스턴스가 있는 맵도 저장한다. 새 에셋의 참조와 대상 패키지에서의 로드를 별도로 확인한다.

## 기능과 충돌 검사

외형 교체 전후에 기존 기능 Actor의 위치·회전·ID와 연결을 비교한다. `ArtRoot` 보정으로 정상 위치를 맞출 수 없을 만큼 기능 배치 자체를 바꿔야 한다면, 아트 교체 완료로 처리하지 말고 레벨·기능 담당과 변경 범위를 확인한다.

| 검사 대상 | 확인할 결과 |
|---|---|
| 모든 시설 | 새 메시와 임시 메시가 동시에 보이지 않고, 새 아트의 충돌이 켜지지 않는다. 기존 `CollisionRoot` 형상과 접근 동선을 유지한다. |
| 상호작용 | 시설 앞에서 기존 거리·시야 조건으로 UI가 열리고, 뒤쪽·벽 너머에서는 부적절하게 열리지 않는다. 큰 장식이 실제 조작 위치를 가리지 않는다. |
| 침대 | `RestLocationOffset`을 유지하고 누움·기상 위치가 침대 및 주변 벽과 겹치지 않는다. 별도의 아트 소켓을 실제 휴식 위치로 오인하지 않는다. |
| 제단 | `OfferingLight`가 가리키는 기존 조명 Actor를 유지한다. 효과 작동과 복구를 확인하고, 수조 내부가 잘못된 충돌로 막히지 않는다. |
| 납부대·패널 | 기존 납부 UI와 스테이지 구매·선택 UI가 열리고 같은 기능 Actor에 요청한다. |
| 엘리베이터 | 외형이 기능 엘리베이터에 부착된 상태를 유지하며 이동·복귀를 따라간다. `BoardingVolume`과 레버 연결을 보존하고 바닥·출입 경계를 확인한다. |
| 레버 | 외형이 각 기능 레버에 부착돼 이동을 따라간다. 두 기능 레버를 엘리베이터의 자식으로 재구성하지 않는다. 현 이동 코드가 별도로 이동시키므로 중복 이동을 피한다. |
| 저장·재접속 | 외형 교체 때문에 시설 ID·`StationId`·게임 진행 값이 바뀌지 않고, 다시 열기·재접속 후에도 참조와 외형이 유지된다. |

정면·측면·후면·상단과 실제 플레이 카메라에서 확인한다. 자동화 검사, 에디터 프리뷰, 실제 다인 플레이, cook 결과는 각각 구분해 기록한다. 실제 아트가 들어오기 전의 교체 구조 검사가 최종 아트의 품질·성능·충돌 검사를 대신하지는 않는다.

전달 기록에는 대상 시설·Blueprint, 변경한 메시·재질, 피벗·치수 보정값, 유지한 기능 연결, 실제 수행한 검사와 미검증 항목을 남긴다. 공통 전달 양식은 [아트반 안내](README.md#하루-작업과-전달)를 사용한다.
